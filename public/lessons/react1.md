### Ситуация
Ты сделал список задач на чистом JavaScript: добавление, удаление, фильтры, счётчик. Через 300 строк выясняется, что после удаления счётчик не обновляется, а после фильтра пропадает отметка «выполнено». Ты вручную синхронизируешь данные и экран — и каждый раз что-то забываешь. React берёт эту синхронизацию на себя. Именно поэтому он в большинстве вакансий фронтенда.

### На пальцах
React — конструктор LEGO для интерфейсов. Вместо одной огромной страницы собираешь её из деталей: кнопка, карточка, шапка. Vite — коробка с инструкцией и пластиной, на которой удобно собирать. TypeScript — наклейки на деталях, которые не дают вставить деталь не туда.

### Как это работает
1. `npm create vite@latest my-shop -- --template react-ts`
2. `cd my-shop`, `npm install`, `npm run dev` → `http://localhost:5173`.

```text
my-shop/
├── index.html            ← один div#root
├── src/
│   ├── main.tsx          ← «монтирует» App в div#root
│   ├── App.tsx           ← главный компонент
│   ├── App.css
│   └── assets/
├── tsconfig.json
└── vite.config.ts
```

- `main.tsx` находит `<div id="root">` и говорит React: «рисуй здесь компонент App».
- Весь интерфейс дальше — дерево компонентов, растущее из `App`.
- `.tsx` — TypeScript с JSX (HTML-подобной разметкой внутри кода).
- `<StrictMode>` в разработке специально вызывает некоторые функции дважды, чтобы находить ошибки.

?: Почему в `index.html` почти пусто, а вся страница появляется из JavaScript? || React строит интерфейс сам: ты описываешь, как он должен выглядеть при текущих данных, а React создаёт и обновляет нужные элементы внутри `div#root`. Поэтому HTML-файл — только точка крепления.

### Пример
```tsx
// src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

```tsx
// src/App.tsx
export default function App() {
  console.log("рисую App");
  return <h1>Мой магазин</h1>;
}
```

?! Сколько раз в режиме разработки появится в консоли «рисую App» при загрузке? || Обычно два раза. `StrictMode` в разработке нарочно вызывает компонент повторно, чтобы находить ошибки. В собранной версии будет один раз.

### Частые ошибки
- **Удалён `<div id="root">`** из `index.html` — приложению некуда рисоваться.
- **Испуг от двойных `console.log`** в разработке — это `StrictMode`.
- **Проект без TypeScript**, который потом мучительно переводят. Сразу выбирай `react-ts`.

?? Что такое файл с расширением `.tsx`? || TypeScript-файл, внутри которого можно писать JSX-разметку.

### Ситуация
Ты переносишь свою вёрстку в React, копируешь HTML как есть — и получаешь россыпь ошибок и предупреждений: `class` не работает, `<img>` «не закрыт», два блока рядом «нужно обернуть». Выглядит как HTML, а правила другие. Семь правил JSX — и миграция проходит без боли.

### На пальцах
JSX — HTML, который живёт внутри JavaScript. Выглядит почти как HTML, но это переодетый JS, поэтому у него свои правила: вместо `class` — `className`, всё нужно класть в одну коробку, а фигурные скобки — окошко, через которое в разметку можно подставить любое выражение.

### Как это работает
1. **Один корневой элемент.** Если обёртка не нужна — фрагмент `<>...</>`.
2. **`className` вместо `class`**, `htmlFor` вместо `for` у `label`.
3. **Все теги закрыты**: `<img />`, `<br />`, `<input />`.
4. **camelCase для атрибутов**: `onClick`, `tabIndex`, `strokeWidth`.
5. **`{выражение}`** — подставить значение: переменную, вычисление, вызов функции, тернарник. `if` или `for` вставить нельзя — только выражения.
6. **`style`** принимает объект: `style={{ color: "red", fontSize: 18 }}`.
7. Комментарий: `{/* текст */}`.

JSX безопасен по умолчанию: строки в `{}` выводятся как текст, HTML-теги внутри них не выполняются.

?: Почему в JSX пишут `className`, а не `class`? || JSX превращается в вызовы JavaScript, а `class` в JavaScript — зарезервированное слово для классов. Поэтому React использует имя DOM-свойства `className`, как и в `element.className`.

### Пример
```tsx
export default function Profile() {
  const name = "Анна";
  const skills = 3;
  const bio = "<b>люблю CSS</b>";

  return (
    <>
      <h2 className="title">{name.toUpperCase()}</h2>
      <p style={{ color: skills > 2 ? "green" : "gray" }}>
        Навыков: {skills}
      </p>
      <p>{bio}</p>
    </>
  );
}
```

?! Какого цвета будет строка с навыками и как отобразится `bio`? || Зелёного — 3 больше 2. `bio` выведется буквально, с угловыми скобками: `<b>люблю CSS</b>`. JSX экранирует строки, поэтому жирного шрифта не будет — это защита от XSS.

### Частые ошибки
- **Два соседних корневых элемента** без обёртки — «Adjacent JSX elements must be wrapped».
- **`class` вместо `className`** — React предупредит в консоли.
- **`if` внутри `{}`.** Используй тернарник или вычисли значение выше.

### Проверь себя
?? Что делать, если компонент должен вернуть два соседних элемента без лишней обёртки? || Обернуть их во фрагмент `<>...</>`.
?? Как в JSX задать inline-стиль? || Объектом в двойных фигурных скобках: `style={{ color: "red" }}`.
?? Объясни своими словами, что можно и что нельзя писать внутри `{}` в JSX. || Можно любое выражение, у которого есть значение: переменные, вычисления, вызовы функций, тернарник. Нельзя инструкции вроде `if` и `for`.

### Мини-задание
Свёрстай в JSX карточку пользователя: аватар, имя, город, статус «в сети» зелёным или «не в сети» серым (через тернарник и `className`). Значения храни в переменных над `return`.

### Ситуация
В каталоге 40 карточек товаров. Ты копируешь кусок разметки сорок раз, меняя название и цену. Заказчик просит добавить в карточку рейтинг — и ты правишь все сорок копий, пропуская пару. Компоненты придуманы ровно для этого: описал карточку один раз — используешь сколько угодно, а изменения делаешь в одном месте.

### На пальцах
Компонент — штамп: один раз вырезал форму «карточка товара», потом штампуешь сколько угодно. Props — краска, которой мажешь штамп перед каждым оттиском: название, цена, картинка. Форма одна, оттиски разные.

### Как это работает
- Компонент — функция, которая возвращает JSX. Имя всегда с большой буквы: `ProductCard`, иначе React примет его за HTML-тег.
- Используется как тег: `<ProductCard title="Кроссовки" price={5990} />`.
- Props приходят первым аргументом — объектом. Их удобно сразу деструктурировать.
- Строки передают в кавычках, всё остальное — в фигурных скобках: числа, массивы, функции.
- В TypeScript props описывают типом.
- Props только для чтения: компонент не меняет то, что ему передали.
- Обычно компонент живёт в своём файле: `components/ProductCard.tsx`.

?: Почему компонент не должен менять свои props? || Props принадлежат родителю. Если ребёнок тайком поменяет переданный объект, данные родителя испортятся, а React не узнает об изменении и не перерисует экран. Для изменяемых данных есть состояние.

### Пример
```tsx
type Props = { title: string; price: number; isNew?: boolean };

export function ProductCard({ title, price, isNew = false }: Props) {
  return (
    <article className="card">
      {isNew && <span className="badge">Новинка</span>}
      <h3>{title}</h3>
      <p>{price.toLocaleString("ru-RU")} ₽</p>
    </article>
  );
}

// в App
<ProductCard title="Кроссовки" price={5990} isNew />
<ProductCard title="Куртка" price="8990" />
```

?! Что покажут две карточки и что скажет TypeScript? || Первая — с плашкой «Новинка» и ценой «5 990 ₽»: проп `isNew` без значения означает `true`. На второй TypeScript подчеркнёт `price="8990"`: строка вместо числа.

### Частые ошибки
- **Имя с маленькой буквы** — React попытается нарисовать HTML-тег `<productCard>` и ничего не покажет.
- **Число в кавычках:** `price="5990"` — придёт строка.
- **Изменение props внутри:** `props.price = 0` — нельзя.

### Проверь себя
?? Почему имя компонента пишут с большой буквы? || Так React отличает компоненты от обычных HTML-тегов: с маленькой буквы он будет искать HTML-элемент.
?? Как передать в компонент число, а как — строку? || Строку в кавычках: `title="Кроссовки"`. Число и всё остальное — в фигурных скобках: `price={5990}`.
?? Объясни своими словами, что такое props. || Входные данные компонента: значения, которые родитель передаёт ему как атрибуты тега. Компонент только читает их и рисует по ним интерфейс.

### Мини-задание

### Ситуация
С сервера пришёл массив из 120 товаров. Писать 120 тегов `<ProductCard />` руками — не вариант, их число меняется каждый день. А когда ты всё-таки выведешь их через `map`, консоль покраснеет загадочным «Each child in a list should have a unique key prop». Разберёмся, зачем React этот ключ и почему индекс массива — плохая идея.

### На пальцах
Список в React — фабрика штампов: берёшь массив данных и для каждого элемента делаешь оттиск компонента. `key` — номер на каждом оттиске. Когда список меняется, React по номерам понимает, какая карточка новая, какую удалили, а какие просто переехали.

### Как это работает
- Списки рисуют через `map`: `{items.map(item => <Card key={item.id} {...item} />)}`.
- У каждого элемента списка должен быть `key` — уникальный и постоянный среди соседей.
- Лучший ключ — `id` из данных. Индекс массива подходит, только если список никогда не сортируется, не фильтруется и не меняется.
- `key` не передаётся внутрь компонента как prop — он только для React.

Фильтрация и сортировка — до `map`: `items.filter(...).map(...)`.

?: Что конкретно ломается, если использовать индекс как `key`, а потом удалить первый элемент? || У всех остальных индексы сдвигаются на один. React думает, что элемент с ключом 0 остался, а исчез последний, — и переиспользует не те карточки. Состояние внутри них, например введённый текст или раскрытый блок, «переезжает» к соседям.

### Пример
```tsx
type Task = { id: number; title: string; done: boolean };

const tasks: Task[] = [
  { id: 101, title: "Сверстать шапку", done: true },
  { id: 102, title: "Подключить API", done: false },
  { id: 103, title: "Задеплоить", done: false },
];

export function TaskList() {
  const active = tasks.filter(t => !t.done);
  return (
    <section>
      <h2>Осталось: {active.length}</h2>
      <ul>
        {active.map(task => <li key={task.id}>{task.title}</li>)}
      </ul>
      {active.length === 0 && <p>Все задачи выполнены</p>}
    </section>
  );
}
```

?! Что увидит пользователь? Какие ключи получат элементы списка? || Заголовок «Осталось: 2» и два пункта: «Подключить API» и «Задеплоить» с ключами 102 и 103. Надпись «Все задачи выполнены» не появится — длина не ноль.

### Частые ошибки
- **Нет `key`** — предупреждение в консоли и возможные странности при изменениях.
- **`key={Math.random()}`** — ключ меняется на каждой отрисовке, React пересоздаёт все элементы и теряет их состояние.
- **Забыт `return` в `map` с фигурными скобками:** `map(t => { <li>...</li> })`.

### Проверь себя
?? Каким должен быть `key` у элемента списка? || Уникальным среди соседей и постоянным между отрисовками — лучше всего `id` из данных.
?? Когда допустимо использовать индекс массива как `key`? || Только если список никогда не сортируется, не фильтруется, и элементы не добавляются и не удаляются.
?? Объясни своими словами, зачем React нужен `key`. || Чтобы при изменении списка понять, какой элемент какой: что добавилось, что удалилось, что переехало, — и обновить экран правильно, не перепутав состояние.

### Мини-задание
Выведи список из 6 товаров через `map` с ключом по `id`. Добавь отдельный блок «Только в наличии», который фильтрует тот же массив. Попробуй убрать `key` и посмотри предупреждение в консоли.

### Ситуация
Компонент `Card` начинался просто. Потом добавились флаги `hasIcon`, `isBig`, `showFooter`, `footerType`, `withImage`, `imagePosition`… Через месяц у него 15 props и 200 строк условий, и никто не понимает, какое сочетание что рисует. Опытные разработчики решают это не флагами, а композицией.

### На пальцах
Композиция — рамка для картины: рамка не знает, что в неё вставят, — она просто красиво обрамляет. `children` — то, что ты вложил внутрь тега компонента. Одна рамка — бесконечно разное содержимое.

### Как это работает
- Всё, что написано между открывающим и закрывающим тегом компонента, приходит в проп `children`.
- Тип в TypeScript: `children: React.ReactNode` — любой JSX, текст, число, массив элементов.
- Так делают обёртки: `Card`, `Modal`, `Section`, `Layout`.
- Несколько «слотов» передают через обычные props: `<Section title={<h2>…</h2>} actions={<button>…</button>}>`.

?: Почему композиция лучше компонента с десятком флагов? || Каждый флаг удваивает число возможных вариантов, и проверить их все невозможно. С композицией обёртка отвечает только за рамку, а содержимое собирается снаружи из простых частей — без условий внутри.

### Пример
```tsx
import type { ReactNode } from "react";

type CardProps = { title: string; footer?: ReactNode; children: ReactNode };

function Card({ title, footer }: CardProps) {
  return (
    <article className="card">
      <h3>{title}</h3>
      {footer && <footer>{footer}</footer>}
    </article>
  );
}

<Card title="Лендинг" footer={<button>Заказать</button>}>
  <p>Одностраничный сайт под рекламу.</p>
</Card>
```

?! Что отобразится в карточке «Лендинг»? || Заголовок и кнопка «Заказать». Абзац про сайт пропадёт: компонент принимает `children` в типе, но не выводит `{children}` в разметке.

### Частые ошибки
- **Компонент-монстр с двадцатью флагами** вместо нескольких маленьких.
- **Забыто `{children}`** внутри обёртки — содержимое исчезает.
- **Тип `children: JSX.Element`** вместо `ReactNode` — нельзя передать текст или несколько элементов.

### Проверь себя
?? Что попадает в проп `children`? || Всё, что написано между открывающим и закрывающим тегом компонента.
?? Какой тип в TypeScript используют для `children`? || `React.ReactNode`.
?? Объясни своими словами, что такое композиция компонентов. || Сборка интерфейса из простых компонентов, вложенных друг в друга: обёртка задаёт рамку, а содержимое передаётся внутрь, вместо одного компонента с множеством настроек.

### Мини-задание
