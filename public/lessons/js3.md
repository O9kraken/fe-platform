### Ситуация
В интернет-магазине 300 товаров, и для каждого нужно посчитать цену со скидкой. Писать 300 одинаковых строчек? Конечно, нет. Компьютеры обожают повторять одно и то же миллион раз без ошибок — нужно только объяснить, что повторять и когда остановиться. Именно здесь новички впервые вешают вкладку бесконечным циклом.

### На пальцах
Цикл — «повторить, пока не закончится». `for` — «сделай 10 отжиманий, считая вслух»: количество известно заранее. `while` — «мешай суп, пока не закипит»: количество неизвестно, есть только условие. `for...of` — «пройди по списку гостей и каждому вручи подарок»: перебираешь готовый список.

### Как это работает
>> `for` — по счётчику → `while` — пока условие → `for...of` — по элементам массива

```js
for (let i = 0; i < 5; i++) { ... }   // старт; условие; шаг
while (условие) { ... }               // пока условие истинно
for (const item of list) { ... }      // каждый элемент массива или строки
```

- В `for` три части: с чего начать (`let i = 0`), до каких пор продолжать (`i < 5`), что делать после каждого круга (`i++`).
- `while` проверяет условие перед каждым кругом. Внутри обязательно должно что-то меняться, иначе цикл бесконечный и вкладка зависнет.
- `for...of` — самый удобный для массивов: не нужен счётчик, нет ошибок с границами.
- `break` — выйти из цикла досрочно, `continue` — пропустить текущий круг.

Индексы массивов начинаются с нуля, поэтому условие обычно `i < arr.length`, а не `<=`.

?: Почему для массивов удобнее `for...of`, чем классический `for` с индексом? || Не нужно следить за счётчиком и границами — меньше мест для ошибки вроде `<=` вместо `<`. Код говорит прямо: «для каждого гостя», а не «для i от нуля до длины минус один».

### Пример
```js
let balance = 1000;
let months = 0;
while (balance < 2000) {
  balance *= 1.5;
  months++;
}
console.log(months);

const guests = ["Анна", "Борис", "Вика"];
for (const guest of guests) {
  if (guest === "Борис") continue;
  console.log(`Подарок для ${guest}`);
}
```

?! Что выведет первый `console.log` и сколько строк про подарки появится? || `2`: 1000 → 1500 → 2250, после второго месяца условие ложно. Подарков две строки — для Анны и Вики, Бориса пропускает `continue`.

### Частые ошибки
- **Бесконечный цикл:** забыл менять переменную в `while`. Вкладка зависла — закрой её и проверь, что меняется внутри.
- **`i <= arr.length`** — лишний круг и `undefined` в конце.
- **`for...in` вместо `for...of`** для массивов: `in` перебирает ключи (индексы строками), а не значения.

### Проверь себя
?? Из каких трёх частей состоит заголовок цикла `for`? || Начальное значение, условие продолжения и шаг после каждого круга.
?? Чем отличаются `break` и `continue`? || `break` полностью выходит из цикла, `continue` пропускает только текущий круг и переходит к следующему.
?? Объясни своими словами, когда выбрать `while`, а когда `for`. || `for` — когда заранее известно, сколько раз повторять. `while` — когда известно только условие остановки, а число повторов заранее не посчитать.

### Ситуация
Ты считаешь цену со скидкой в пяти местах сайта: в корзине, в карточке, в письме, в модалке, в итогах. Везде скопирована одна и та же формула. Потом бизнес меняет правила округления — и ты исправляешь пять мест, забыв одно. Функция позволяет записать формулу один раз и вызывать её по имени.

### На пальцах
Функция — рецепт. Ты один раз записываешь: «Чтобы сделать чай: вскипяти воду, положи пакетик, подожди 3 минуты». Потом говоришь «сделай чай» — и не объясняешь заново. Стрелочная функция — тот же рецепт, записанный коротко, на стикере.

### Как это работает
>> `function sum(a, b) {}` → `const sum = (a, b) => a + b` → вызов `sum(2, 3)`

Три способа создать функцию:

```js
function greet(name) { return `Привет, ${name}`; }   // объявление
const greet2 = function (name) { ... };             // функциональное выражение
const greet3 = (name) => `Привет, ${name}`;          // стрелочная
```

- **Объявление** `function` можно вызвать даже выше по коду, чем оно написано (всплытие).
- **Стрелочная** — короче. Если тело — одно выражение, можно без фигурных скобок и `return`: значение вернётся само.
- Один параметр — скобки можно опустить: `x => x * 2`. Нет параметров — пустые скобки: `() => ...`.
- Чтобы вернуть объект из короткой стрелочной, оберни его в скобки: `() => ({ ok: true })`.

Функции — такие же значения, как числа: их кладут в переменные и передают в другие функции. Так работают `addEventListener` и `map`.

Объявить функцию — записать рецепт. Вызвать — `greet("Анна")` — приготовить по нему. Без скобок функция не вызывается.

?: Зачем объект в короткой стрелочной функции оборачивать в круглые скобки? || Фигурная скобка после `=>` означает начало тела функции. Без круглых скобок JavaScript решит, что `{ ok: true }` — это блок кода, а не объект, и функция вернёт `undefined`.

### Пример
```js
const double = n => n * 2;
const triple = n => { n * 3 };
const makeUser = (name) => ({ name, admin: false });

console.log(double(21));
console.log(triple(3));
console.log(makeUser("Анна"));
console.log(double);
```

?! Что выведут четыре строки? || `42`. `undefined` — у `triple` фигурные скобки без `return`. `{ name: "Анна", admin: false }`. И сам текст функции `n => n * 2` — её не вызвали, забыли скобки.

### Частые ошибки
- **Забыты скобки при вызове:** `console.log(double)` выведет саму функцию, а не результат.
- **Фигурные скобки в стрелочной без `return`:** `x => { x * 2 }` вернёт `undefined`.
- **Результат вызова вместо функции в обработчике:** `addEventListener("click", save())` вызовет `save` сразу при загрузке. Нужно `save` без скобок или `() => save()`.

### Проверь себя
?? Назови три способа создать функцию. || Объявление `function имя() {}`, функциональное выражение `const f = function () {}` и стрелочная функция `const f = () => {}`.
?? Когда стрелочная функция возвращает значение без `return`? || Когда её тело — одно выражение без фигурных скобок, например `x => x * 2`.
?? Объясни своими словами разницу между `save` и `save()`. || `save` — сама функция, рецепт, её можно передать куда-то. `save()` — вызов, выполнение рецепта прямо сейчас и его результат.

### На пальцах
Параметры — ингредиенты, которые передаёшь в рецепт: «приготовь чай с сахаром». Значение по умолчанию — «если про сахар не сказали, клади одну ложку». `return` — готовое блюдо, которое функция отдаёт обратно. Без `return` функция что-то делает, но в руки ничего не даёт.

### Как это работает
>> Параметры на вход → значение по умолчанию → тело функции → `return` результат

- Параметры перечисляются в скобках при объявлении, аргументы — значения при вызове.
- Если аргумент не передали, параметр равен `undefined`.
- Значение по умолчанию: `function greet(name = "гость")`.
- `return` сразу завершает функцию и отдаёт значение. Код после `return` не выполняется.
- Функция без `return` возвращает `undefined`.
- Остаточные параметры `...rest` собирают «все остальные» аргументы в массив.
- Если параметров много, передавай объект: `createOrder({ id, qty, address })` — так не перепутаешь порядок.

?: Почему при пяти и более параметрах лучше передавать один объект? || При вызове `send("a", true, null, 3, false)` уже через неделю непонятно, что значит каждое значение, а перепутать порядок — легко. С объектом каждое значение подписано именем, и порядок не важен.

### Пример
```js
function price(base, discount = 0) {
  if (discount < 0 || discount > 100) return base;
  return base - base * discount / 100;
}

function show(a, b) {
  console.log(a + b);
}

console.log(price(1000));
console.log(price(1000, 15));
const r = show(2, 3);
console.log(r);
```

?! Что появится в консоли? || `1000` — скидка по умолчанию 0. `850`. Затем `5` — его печатает сама `show`. И `undefined` — функция ничего не вернула, поэтому `r` пустой.

### Частые ошибки
- **`console.log` вместо `return`** внутри функции — результат потом не использовать.
- **Код после `return`**, который никогда не выполнится.
- **Пять позиционных параметров** — через неделю непонятно, что есть что.

### Проверь себя
?? Что вернёт функция, в которой нет `return`? || `undefined`.
?? Как задать параметру значение по умолчанию? || Прямо в объявлении: `function greet(name = "гость")`.
?? Объясни своими словами разницу между «вывести» и «вернуть». || `console.log` только показывает значение человеку в консоли. `return` отдаёт значение коду, который вызвал функцию, — его можно сохранить и использовать дальше.

### Ситуация
Ты объявил `const message` внутри `if`, а через три строки ниже пытаешься его вывести — «message is not defined». Переменная же есть, вон она! Есть — но в другой «комнате». ### На пальцах
Область видимости — комнаты с односторонними окнами. Из маленькой комнаты (функции) видно всё, что в коридоре снаружи. А из коридора не видно, что внутри комнаты. Переменная, объявленная в комнате, там и остаётся.

### Как это работает
>> Глобальная → функция → блок `{}` → внутренний видит внешнее, внешний внутреннее — нет

- **Глобальная** область — переменные вне функций и блоков. Видны везде. Их стоит избегать: любой код может их случайно перезаписать.
- **Функция** — переменные, объявленные внутри, не видны снаружи.
- **Блок** `{ }` — `let` и `const` внутри `if`, `for` или просто фигурных скобок живут только там.
- Внутренняя область видит внешнюю. Если имена совпадают, внутренняя переменная «затеняет» внешнюю.

Поиск переменной идёт изнутри наружу: текущий блок, потом внешний и так далее до глобального. Не нашли — ошибка `is not defined`.

Отсюда растут замыкания: функция «помнит» переменные из места, где её создали, даже когда то место уже закончило работу.

?: Как функция `next` в примере ниже может помнить `count`, если `makeCounter` уже завершилась? || Функция, созданная внутри другой, сохраняет ссылку на переменные своего «места рождения». Пока `next` существует, её `count` не исчезает. Это и есть замыкание — приватная память функции.

### Пример
```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const a = makeCounter();
const b = makeCounter();
console.log(a(), a(), a());
console.log(b());
```

?! Что выведут две строки? || `1 2 3` и `1`. Каждый вызов `makeCounter` создаёт свой отдельный `count`, поэтому счётчики `a` и `b` не мешают друг другу.

### Частые ошибки
- **Переменная объявлена внутри `if`**, а используется после него.
- **Всё в глобальных переменных** — случайные перезаписи и путаница.
- **Одинаковые имена** во внешней и внутренней области — легко запутаться, какая используется.

### Проверь себя
?? Видна ли переменная, объявленная через `let` внутри `if`, после этого блока? || Нет, `let` и `const` живут только внутри своего блока.
?? В каком направлении JavaScript ищет переменную? || Изнутри наружу: от текущего блока к внешним и до глобальной области.
?? Объясни своими словами, что такое замыкание. || Функция помнит переменные того места, где её создали, и продолжает ими пользоваться, даже когда внешняя функция уже закончила работу.

### Ситуация
Функция «добавить в корзину» заодно меняла исходный массив товаров, увеличивала глобальную сумму и писала в `localStorage`. Однажды каталог внезапно стал показывать товары с двойной ценой — потому что функцию вызвали дважды. Найти такую ошибку очень тяжело. Чистые функции делают подобные сюрпризы невозможными.

### На пальцах
Чистая функция — калькулятор: нажал 2 + 2 — всегда 4, и калькулятор ничего не меняет вокруг. Грязная функция — кот: даёшь ему одно и то же, а результат каждый раз разный, и по пути он что-нибудь роняет со стола.

### Как это работает
>> Те же входные данные → тот же результат → ничего не меняет снаружи → легко тестировать

Функция чистая, если:

1. При одних и тех же аргументах всегда возвращает один и тот же результат.
2. Не имеет побочных эффектов: не меняет внешние переменные и переданные объекты, не пишет в DOM, не отправляет запросы, не пишет в `localStorage`.

Чем это хорошо:

- Легко тестировать: подал на вход — сравнил выход.
- Легко понять: всё, что влияет на результат, видно в аргументах.
- Безопасно переиспользовать.

Побочные эффекты нужны — без них программа ничего не покажет и не сохранит. Идея в том, чтобы держать вычисления в чистых функциях, а эффекты — в немногих понятных местах. React построен именно на этом.

Неизменяемость: вместо изменения переданного массива создавай новый — `[...arr, item]`, `arr.map(...)`.

?: Почему чистую функцию проще тестировать? || Её результат зависит только от аргументов. Тест — это «подал вход, сравнил выход», без подготовки DOM, сервера или глобального состояния и без страха, что функция что-то сломает вокруг.

### Пример
```js
function addDirty(cart, item) {
  cart.push(item);
  return cart;
}

function addPure(cart, item) {
  return [...cart, item];
}

const c1 = [];
const c2 = addPure(c1, "чай");
const c3 = addDirty(c1, "кофе");
console.log(c1.length, c2.length, c3 === c1);
```

?! Что выведет последняя строка? || `1 1 true`. `addPure` вернула новый массив и не тронула `c1`. А `addDirty` положила «кофе» прямо в `c1` и вернула его же — `c3` и `c1` теперь одна и та же коробка.

### Частые ошибки
- **Функция «посчитай сумму»**, которая заодно меняет DOM и сохраняет в `localStorage`.
- **`sort()` по переданному массиву** — он меняет исходник. Сначала скопируй: `[...arr].sort()`.
- **Зависимость от глобальной переменной**, которая может поменяться где угодно.

### Проверь себя
?? Назови два условия чистой функции. || Одинаковый результат при одинаковых аргументах и отсутствие побочных эффектов.
?? Чистая ли функция `() => Math.random()`? Почему? || Нет: при одних и тех же (пустых) аргументах она каждый раз возвращает разный результат.
?? Объясни своими словами, что такое побочный эффект. || Любое влияние функции на мир за её пределами: изменение внешних переменных и переданных объектов, запись в DOM или хранилище, сетевой запрос.
