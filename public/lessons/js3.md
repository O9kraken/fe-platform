### На пальцах
Цикл — «повторить, пока не закончится». `for` — «сделай 10 отжиманий, считая вслух»: заранее знаешь количество. `while` — «мешай суп, пока не закипит»: количество неизвестно, есть только условие. `for...of` — «пройди по списку гостей и каждому вручи подарок»: перебираешь готовый список.

### Как это работает
Три вида циклов:

```js
for (let i = 0; i < 5; i++) { ... }   // старт; условие; шаг
while (условие) { ... }               // пока условие истинно
for (const item of list) { ... }      // каждый элемент массива или строки
```

- В `for` три части: с чего начать (`let i = 0`), до каких пор продолжать (`i < 5`), что делать после каждого круга (`i++`).
- `while` проверяет условие перед каждым кругом. Внутри обязательно должно что-то меняться, иначе цикл бесконечный и вкладка зависнет.
- `for...of` — самый удобный для массивов: не нужен счётчик, нет ошибок с границами.
- `break` — выйти из цикла досрочно, `continue` — пропустить текущий круг.

Индексы в массивах начинаются с нуля, поэтому условие обычно `i < arr.length`, а не `<=`.

### Пример
```js
for (let i = 1; i <= 3; i++) {
  console.log(`Подход ${i}`);
}

let balance = 1000;
let months = 0;
while (balance < 2000) {
  balance *= 1.1;      // +10% в месяц
  months++;
}
console.log(`Удвоится через ${months} мес.`);

const guests = ["Анна", "Борис", "Вика"];
for (const guest of guests) {
  if (guest === "Борис") continue;   // Борису подарок вручим отдельно
  console.log(`Подарок для ${guest}`);
}
```

### Частые ошибки
- Бесконечный цикл: забыл менять переменную в `while`. Если вкладка зависла — закрой её.
- `i <= arr.length` — лишний круг и `undefined` в конце.
- `for...in` вместо `for...of` для массивов: `in` перебирает ключи (индексы строками), а не значения.

### На пальцах
Функция — рецепт. Ты один раз записываешь: «Чтобы сделать чай: вскипяти воду, положи пакетик, подожди 3 минуты». Потом говоришь «сделай чай» — и не объясняешь заново. Стрелочная функция — тот же рецепт, записанный коротко, на стикере.

### Как это работает
Три способа создать функцию:

```js
function greet(name) { return `Привет, ${name}`; }   // объявление
const greet2 = function (name) { ... };             // функциональное выражение
const greet3 = (name) => `Привет, ${name}`;          // стрелочная
```

- **Объявление** `function` можно вызвать даже выше по коду, чем оно написано (всплытие).
- **Стрелочная** — короче. Если тело одно выражение, можно без фигурных скобок и `return`: значение вернётся само.
- Один параметр — скобки можно опустить: `x => x * 2`. Нет параметров — пустые скобки: `() => ...`.
- Чтобы вернуть объект из короткой стрелочной, оберни его в скобки: `() => ({ ok: true })`.

Функции — такие же значения, как числа: их кладут в переменные и передают в другие функции. Так работают `addEventListener` и `map`.

Объявить функцию — записать рецепт. Вызвать — `greet("Анна")` — приготовить по нему. Без скобок функция не вызывается.

### Пример
```js
function area(width, height) {
  return width * height;
}

const double = n => n * 2;
const sum = (a, b) => a + b;
const makeUser = (name) => ({ name, createdAt: Date.now() });

console.log(area(3, 4));      // 12
console.log(double(21));      // 42
console.log(sum(2, 3));       // 5
console.log(makeUser("Анна"));

document.querySelector("button")?.addEventListener("click", () => {
  console.log("Нажали");
});
```

### Частые ошибки
- Забыть скобки при вызове: `console.log(double)` выведет саму функцию, а не результат.
- Фигурные скобки в стрелочной без `return`: `x => { x * 2 }` вернёт `undefined`.
- Передать в обработчик результат вызова: `addEventListener("click", save())` вызовет `save` сразу. Нужно `save` без скобок или `() => save()`.

### Мини-задание
Напиши функции `toCelsius(f)` и стрелочную `toFahrenheit = c => ...`. Проверь: 212°F → 100°C, 0°C → 32°F. Затем напиши стрелочную функцию, возвращающую объект `{ c, f }`.

### На пальцах
Параметры — ингредиенты, которые ты передаёшь в рецепт: «приготовь чай с сахаром». Значение по умолчанию — «если про сахар не сказали, клади одну ложку». `return` — готовое блюдо, которое функция отдаёт обратно. Без `return` функция что-то делает, но в руки ничего не даёт.

### Как это работает
- Параметры перечисляются в скобках при объявлении, аргументы — значения при вызове.
- Если аргумент не передали, параметр равен `undefined`.
- Значение по умолчанию: `function greet(name = "гость")`.
- `return` сразу завершает функцию и отдаёт значение. Код после `return` не выполняется.
- Функция без `return` возвращает `undefined`.
- Остаточные параметры `...rest` собирают «все остальные» аргументы в массив.
- Если параметров много, передавай объект: `createOrder({ id, qty, address })` — так не перепутаешь порядок.

Разница между «вывести» и «вернуть» важна: `console.log` показывает значение в консоли, но им нельзя воспользоваться дальше. `return` отдаёт значение коду, который вызвал функцию.

### Пример
```js
function price(base, discount = 0) {
  if (discount < 0 || discount > 100) return base;   // ранний return
  return base - base * discount / 100;
}
console.log(price(1000));       // 1000
console.log(price(1000, 15));   // 850

function sumAll(...nums) {
  let s = 0;
  for (const n of nums) s += n;
  return s;
}
console.log(sumAll(1, 2, 3, 4)); // 10

function createOrder({ title, qty = 1, express = false }) {
  return `${title} × ${qty}${express ? ", срочно" : ""}`;
}
console.log(createOrder({ title: "Лендинг", express: true }));

function bad(a, b) { console.log(a + b); }
const r = bad(2, 3);   // выведет 5
console.log(r);        // undefined — функция ничего не вернула
```

### Частые ошибки
- Выводить результат через `console.log` внутри функции вместо `return` и потом не мочь его использовать.
- Код после `return`, который никогда не выполнится.
- Пять позиционных параметров: `send("a", true, null, 3, false)` — через неделю непонятно, что есть что.

### На пальцах
Область видимости — комнаты с односторонними окнами. Из маленькой комнаты (функции) видно всё, что в коридоре (снаружи). А из коридора не видно, что внутри комнаты. Переменная, объявленная в комнате, там и остаётся.

### Как это работает
- **Глобальная** область — переменные вне функций и блоков. Видны везде. Их стоит избегать: любой код может их случайно перезаписать.
- **Функция** — переменные, объявленные внутри, не видны снаружи.
- **Блок** `{ }` — `let` и `const`, объявленные внутри `if`, `for` или просто фигурных скобок, живут только там.
- Внутренняя область видит внешнюю. Если имена совпадают, внутренняя переменная «затеняет» внешнюю.

Поиск переменной идёт изнутри наружу: сначала в текущем блоке, потом во внешнем и так далее до глобального. Не нашли — ошибка `is not defined`.

Отсюда растут замыкания: функция «помнит» переменные из места, где её создали, даже когда то место уже закончило работу.

### Пример
```js
const site = "Студия";           // глобальная

function showPrice() {
  const price = 30000;           // видна только внутри функции
  if (price > 10000) {
    const message = "Дорого";    // видна только в этом if
    console.log(site, price, message);
  }
  // console.log(message);       // ошибка: message is not defined
}
showPrice();
// console.log(price);           // ошибка: price is not defined

function makeCounter() {
  let count = 0;                 // «спрятанная» переменная
  return () => ++count;
}
const next = makeCounter();
console.log(next(), next(), next()); // 1 2 3 — функция помнит count
```

### Частые ошибки
- Объявить переменную внутри `if` и пытаться использовать её после.
- Всё делать глобальными переменными — случайные перезаписи и путаница.
- Одинаковые имена во внешней и внутренней области — легко запутаться, какая используется.

### Мини-задание
Напиши `makeCounter(start, step)`, возвращающую функцию, которая при каждом вызове выдаёт следующее число: `makeCounter(10, 5)` → 15, 20, 25. Убедись, что два счётчика не мешают друг другу.

### На пальцах
Чистая функция — калькулятор: нажал 2 + 2 — всегда 4, и калькулятор ничего не меняет вокруг. Грязная функция — кот: даёшь ему одно и то же, а результат каждый раз разный, и по пути он что-нибудь роняет со стола.

### Как это работает
Функция чистая, если:

1. При одних и тех же аргументах всегда возвращает один и тот же результат.
2. Не имеет побочных эффектов: не меняет внешние переменные и переданные объекты, не пишет в DOM, не отправляет запросы, не пишет в `localStorage`.

Чем это хорошо:

- Легко тестировать: подал на вход — сравнил выход.
- Легко понять: всё, что влияет на результат, видно в аргументах.
- Безопасно переиспользовать.

Побочные эффекты нужны — без них программа ничего не покажет и не сохранит. Идея в том, чтобы держать вычисления в чистых функциях, а эффекты — в немногих понятных местах. React построен именно на этом: компонент — почти чистая функция от данных к интерфейсу.

Неизменяемость: вместо изменения переданного массива создавай новый — `[...arr, item]`, `arr.map(...)`.

### Пример
```js
// Грязная: меняет внешнюю переменную и переданный массив
let total = 0;
function addToCartDirty(cart, item) {
  cart.push(item);
  total += item.price;
}

// Чистая: возвращает новый массив, ничего не трогает снаружи
function addToCart(cart, item) {
  return [...cart, item];
}
function cartTotal(cart) {
  return cart.reduce((sum, i) => sum + i.price, 0);
}

const cart1 = [];
const cart2 = addToCart(cart1, { title: "Чай", price: 300 });
console.log(cart1.length, cart2.length);   // 0 1 — исходный не изменился
console.log(cartTotal(cart2));             // 300

// Нечистая по природе: результат каждый раз разный
const randomId = () => Math.random().toString(36).slice(2);
```

### Частые ошибки
- Функция «посчитай сумму», которая заодно меняет DOM и сохраняет в `localStorage`.
- Сортировать переданный массив через `sort()` — он меняет исходный массив. Сначала скопируй: `[...arr].sort()`.
- Зависеть от глобальной переменной, которая может поменяться где угодно.
