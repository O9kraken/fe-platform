### На пальцах
VS Code — это мастерская: слева стеллаж с инструментами и материалами (Explorer со всеми файлами проекта), посередине верстак (редактор), внизу — окно в подсобку (терминал). Расширения — дополнительные насадки: одна сама выравнивает код, другая показывает сайт в браузере и обновляет его при каждом сохранении.

### Как это работает
1. Скачай VS Code с code.visualstudio.com и установи.
2. Открывай не отдельный файл, а всю папку проекта: File → Open Folder. Тогда слева в Explorer видны все файлы, а поиск и терминал работают в этой папке.
3. Встроенный терминал открывается сочетанием Ctrl + ` (обратная кавычка, клавиша с буквой Ё) или через View → Terminal. Он сразу находится в папке проекта.
4. Расширения ставятся во вкладке Extensions (Ctrl + Shift + X).

Два расширения, которые нужны с первого дня:

- **Prettier** — форматирует код по единым правилам. Включи в настройках «Format On Save», и код будет выравниваться при каждом сохранении.
- **Live Server** — правый клик по `index.html` → «Open with Live Server». Сайт откроется по адресу вроде `http://127.0.0.1:5500` и будет обновляться сам после каждого сохранения.

Полезные сочетания: Ctrl + P — быстро открыть файл по имени, Ctrl + / — закомментировать строку, Alt + ↑/↓ — передвинуть строку, Ctrl + D — выделить следующее такое же слово.

### Пример
Настройки можно открыть как файл: Ctrl + Shift + P → «Preferences: Open User Settings (JSON)» и добавить:

```json
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.tabSize": 2,
  "files.autoSave": "onFocusChange"
}
```

### Частые ошибки
- Открывать один файл вместо папки — тогда Live Server и пути к картинкам работают странно.
- Ставить десятки расширений «на всякий случай». Они тормозят редактор и спорят друг с другом. Начни с двух.
- Смотреть сайт, открыв файл двойным кликом (`file:///...`), а не через Live Server. Некоторые вещи, например модули JS и fetch, так не работают.

### Мини-задание
Установи VS Code, Prettier и Live Server. Открой папку `web-learning`, включи форматирование при сохранении. Запусти `index.html` через Live Server, поменяй текст заголовка и убедись, что браузер обновился сам.

### На пальцах
Терминал — это разговор с компьютером текстом вместо кликов мышкой. Вместо «двойной клик по папке» ты пишешь «зайди в папку», вместо «правый клик → создать папку» — «создай папку». Медленнее для новичка, но гораздо быстрее, когда привыкнешь, и многие инструменты разработчика работают только так.

### Как это работает
Терминал всегда «находится» в какой-то папке — это текущая папка. Все команды выполняются относительно неё.

| Команда | Что делает | В Windows (cmd) |
|---|---|---|
| `pwd` | показать, в какой я папке | `cd` без аргументов |
| `ls` | показать содержимое папки | `dir` |
| `cd имя` | перейти в папку | `cd имя` |
| `cd ..` | подняться на уровень выше | `cd ..` |
| `mkdir имя` | создать папку | `mkdir имя` |

В PowerShell и Git Bash на Windows работают и `ls`, и `pwd`, так что удобнее пользоваться ими.

Два приёма экономят массу времени:

- **Tab** — автодополнение: набери `cd web` и нажми Tab, терминал допишет `web-learning`.
- **Стрелка вверх** — повторить предыдущую команду.

### Пример
```bash
pwd                  # /home/anna
mkdir web-learning   # создали папку
cd web-learning      # зашли в неё
mkdir week-01 week-02
ls                   # week-01  week-02
cd week-01
pwd                  # /home/anna/web-learning/week-01
cd ..                # вернулись в web-learning
```

### Частые ошибки
- Путать, в какой папке находишься. Не уверен — выполни `pwd`.
- Пробелы в именах папок: `cd My Projects` не сработает, нужно `cd "My Projects"`. Проще не использовать пробелы вовсе.
- Пугаться пустого ответа. Если команда ничего не вывела — обычно это значит «всё прошло успешно».

### Мини-задание
Только через терминал: создай в `web-learning` папки `week-01`, `week-02`, `week-03`, зайди во вторую, проверь, где ты, через `pwd`, и вернись обратно. В конце выведи список папок через `ls`.

### На пальцах
Git — машина времени для проекта. Каждый коммит — фотография всех файлов в момент, когда ты сказал «сохрани это состояние». Сломал что-то — открываешь старую фотографию и смотришь, как было. `git add` — положить вещи в коробку, `git commit` — заклеить коробку и подписать.

### Как это работает
1. `git init` — один раз в папке проекта. Появится скрытая папка `.git` — там хранится вся история.
2. Работаешь как обычно: меняешь файлы.
3. `git status` — что изменилось с последнего коммита. Красное — изменения ещё не в коробке, зелёное — уже в коробке.
4. `git add файл` или `git add .` (все изменения) — положить в коробку. Это называется индекс или staging.
5. `git commit -m "Что сделал"` — запечатать снимок с подписью.
6. `git log --oneline` — список всех снимков, от новых к старым.

Зачем два шага, add и commit? Чтобы собирать в один коммит только связанные изменения. Поменял шапку и подвал — можно сделать два понятных коммита вместо одного «всё подряд».

Перед первым коммитом Git попросит представиться — один раз на компьютер:

```bash
git config --global user.name "Анна Смирнова"
git config --global user.email "anna@example.com"
```

### Пример
```bash
cd web-learning
git init
git status                 # index.html — untracked (красный)
git add index.html
git commit -m "Добавил страницу о себе"
# правим файл...
git status                 # modified: index.html
git add .
git commit -m "Добавил список навыков"
git log --oneline
# a1b2c3d Добавил список навыков
# 9f8e7d6 Добавил страницу о себе
```

### Частые ошибки
- Делать `git init` в домашней папке или на Рабочем столе — тогда Git начнёт следить за всем компьютером. Только в папке проекта.
- Один коммит раз в неделю «на всё». Коммить каждый законченный маленький шаг.
- Забыть `git add` и удивляться, что коммит пустой или в нём не всё.

### Мини-задание
Сделай в `web-learning` репозиторий и три коммита: создание страницы, добавление списка, добавление картинки. Посмотри историю через `git log --oneline`.

### На пальцах
Git на компьютере — личный фотоальбом. GitHub — облачный архив, куда альбом копируется: его не потеряешь, если сломается ноутбук, им можно поделиться с работодателем, и по нему можно работать вместе. `git push` — отнести свежие фото в архив.

### Как это работает
1. Зарегистрируйся на github.com.
2. Нажми «New repository», придумай имя (например, `web-learning`), не ставь галочку «Add README», если проект уже есть на компьютере.
3. GitHub покажет адрес репозитория вида `https://github.com/твой-логин/web-learning.git`.
4. Свяжи свою папку с этим адресом — один раз:

```bash
git remote add origin https://github.com/твой-логин/web-learning.git
git branch -M main
git push -u origin main
```

`origin` — короткое имя удалённого репозитория, `main` — название основной ветки. Флаг `-u` запоминает связь, поэтому дальше достаточно просто `git push`.

Обычный рабочий цикл: изменил → `git add .` → `git commit -m "..."` → `git push`.

При первом push Git попросит войти. Самый простой способ — GitHub Desktop или вход через браузер, который предлагает Git Credential Manager. Обычный пароль от аккаунта в терминале не подойдёт.

### Пример
```bash
git remote -v
# origin  https://github.com/anna/web-learning.git (fetch)
# origin  https://github.com/anna/web-learning.git (push)

git add .
git commit -m "Добавил контакты"
git push
```

Обнови страницу репозитория на GitHub — там появился новый коммит.

### Частые ошибки
- Отправить на GitHub файл с паролями или ключами. Такие файлы (`.env`) добавляй в `.gitignore` до первого коммита.
- Создать на GitHub репозиторий с README, а потом пытаться отправить свой проект — Git скажет, что истории разошлись. Для существующего проекта создавай пустой репозиторий.
- Копировать в новую папку чужую скрытую папку `.git` — история перепутается.

### Мини-задание
Создай репозиторий на GitHub, свяжи с ним папку `web-learning` и отправь свои коммиты. Сделай ещё одно изменение и отправь его, проверив результат на сайте.

### На пальцах
Сообщение коммита — подпись на коробке при переезде. «Разное» не поможет найти чайник через месяц. «Кухня: посуда и чайник» — поможет. История коммитов — оглавление проекта, и его читают коллеги, работодатель и ты сам через полгода.

### Как это работает
Хорошее сообщение отвечает на вопрос: «Что изменится, если применить этот коммит?»

Правила:

- Пиши в одном стиле: «Добавил форму заявки» или «Добавить форму заявки» — выбери и держись.
- Конкретно: что именно и где. «Исправил отступы в шапке на мобильных» вместо «fix».
- Первая строка до 50–70 символов. Если нужны подробности — пустая строка и пояснение ниже.
- Один коммит — одно логическое изменение. Если в описании хочется написать «и ещё...», это два коммита.

Многие команды используют соглашение Conventional Commits: в начале тип изменения.

| Тип | Значение |
|---|---|
| `feat:` | новая возможность |
| `fix:` | исправление ошибки |
| `style:` | оформление кода без изменения логики |
| `docs:` | документация |
| `refactor:` | переделка кода без новых функций |

### Пример
Плохая история:

```text
asdf
fix
изменения
ещё правки
```

Хорошая история:

```text
feat: добавить форму обратной связи
fix: исправить переполнение меню на iPhone SE
style: выровнять отступы карточек
docs: описать запуск проекта в README
```

### Частые ошибки
- Сообщения-пустышки: «update», «fix», «123».
- Описывать процесс вместо результата: «пытался починить, вроде работает».
- Смешивать в одном коммите исправление ошибки, новый раздел и переименование файлов.

### Мини-задание
Открой `git log --oneline` своего проекта. Перепиши в блокноте три самых невнятных сообщения так, чтобы по ним было понятно, что изменилось. Следующие пять коммитов делай по формату `feat:` / `fix:`.
