### Ситуация
В обычном React страница каталога открывается так: пустой экран → спиннер → через секунду товары. Поисковый робот за это время уже ушёл, а пользователь на медленном интернете смотрит на крутилку. В Next.js можно сделать так, чтобы товары были в HTML с первой же миллисекунды — и код получается даже проще.

### На пальцах
В обычном React браузер сначала получает пустую страницу, потом идёт за данными, и только потом показывает товары. В Next.js сервер сам сходит за данными и пришлёт уже заполненную страницу. Как ресторан, где официант приносит готовое блюдо, а не набор продуктов и рецепт.

### Как это работает
>> `async function Page()` → `await` данные прямо в компоненте → HTML уже с данными

- Серверный компонент может быть `async` и прямо в теле дождаться данных через `await`.
- Источник данных — что угодно: `fetch` к API, запрос к базе через ORM, чтение файла.
- Секретные ключи и строки подключения безопасно использовать здесь — код не попадает в браузер.
- Пока данные грузятся, Next.js показывает `loading.tsx`.
- Несколько независимых запросов запускай параллельно через `Promise.all`.
- Ошибка внутри — сработает `error.tsx`.

`useEffect` и `useState` для загрузки здесь не нужны.

?: Почему загрузка в серверном компоненте лучше для SEO, чем `useEffect` в клиентском? || Сервер присылает HTML уже с данными: робот сразу видит товары и тексты. С `useEffect` робот получает пустую разметку, а данные появляются только после выполнения JavaScript в браузере.

### Пример
```tsx
async function getOrders() {
  await new Promise(r => setTimeout(r, 1000));
  return [{ id: 1 }, { id: 2 }];
}
async function getStats() {
  await new Promise(r => setTimeout(r, 1000));
  return { visitors: 120 };
}

export default async function Dashboard() {
  const orders = await getOrders();
  const stats = await getStats();
  return <h1>Заказы: {orders.length}, посетителей: {stats.visitors}</h1>;
}
```

?! Сколько примерно времени займёт загрузка страницы? Как ускорить её вдвое? || Около двух секунд: второй запрос ждёт, пока закончится первый. Запросы независимые, поэтому их можно запустить параллельно: `const [orders, stats] = await Promise.all([getOrders(), getStats()])` — около одной секунды.

### Частые ошибки
- **Загрузка через `useEffect` в клиентском компоненте по привычке** — теряются скорость и SEO.
- **Последовательные `await` для независимых запросов.**
- **Запрос к собственному Route Handler из серверного компонента** — проще сразу вызвать функцию, которая ходит в базу.

### Проверь себя
?? Как загрузить данные в серверном компоненте Next.js? || Сделать компонент `async` и дождаться данных через `await` прямо в его теле.
?? Как запустить два независимых запроса одновременно? || Через `Promise.all([запрос1, запрос2])`.
?? Объясни своими словами, почему в серверном компоненте можно использовать секретный токен API. || Код серверного компонента выполняется только на сервере и не отправляется в браузер, поэтому пользователь не сможет увидеть токен.

### Ситуация
Ты опубликовал новую статью в блоге, а на сайте её нет. Обновляешь — нет. Через пять минут появляется. Заказчик звонит: «Сайт сломался!». А в другом проекте наоборот: каждая загрузка главной страницы дёргает базу, и при наплыве посетителей сервер ложится. За обе ситуации отвечает кеш, и им нужно уметь управлять.

### На пальцах
Кеш — заготовки на кухне. Не нужно резать салат заново для каждого гостя, если его нарезали пять минут назад. `revalidate` — правило «нарезанное хранится 60 секунд, потом режем свежее». Гостю быстро, а данные не протухают надолго.

### Как это работает
>> Запрос → кеш → `revalidate: 60` → через минуту обновить в фоне

| Настройка | Что значит |
|---|---|
| `fetch(url, { next: { revalidate: 60 } })` | хранить ответ до 60 секунд |
| `fetch(url, { cache: "no-store" })` | не кешировать, свежие данные при каждом запросе |
| `export const revalidate = 3600` в файле страницы | вся страница обновляется раз в час |
| `export const dynamic = "force-dynamic"` | страница всегда рисуется заново |
| `revalidatePath("/blog")` | сбросить кеш страницы прямо сейчас |
| `revalidateTag("posts")` | сбросить все запросы с тегом `posts` |

Как выбрать:

- Статьи, каталог, лендинг — кеш на минуты или часы.
- Личный кабинет, корзина, остатки на складе — без кеша или сброс после изменений.
- После изменения данных пользователем — `revalidatePath` в Server Action или Route Handler.

Поведение кеша в разных версиях Next.js менялось — для важных страниц задавай его явно. Проверяй на собранной версии (`npm run build && npm start`): в режиме разработки кеш работает иначе.

?: Почему личный кабинет нельзя кешировать так же, как статью? || Кеш общий для всех посетителей. Закешированная страница кабинета, собранная для одного пользователя, может показаться другому — с чужими заказами и данными.

### Пример
```tsx
// app/blog/page.tsx
export const revalidate = 300;

export default async function Blog() {
  const posts = await fetch("https://api.example.com/posts", {
    next: { tags: ["posts"] },
  }).then(r => r.json());
  return <ul>{posts.map((p: { id: number; title: string }) => <li key={p.id}>{p.title}</li>)}</ul>;
}

// app/admin/actions.ts
"use server";
import { revalidateTag } from "next/cache";
export async function publishPost(formData: FormData) {
  // ... сохранить пост в базу
  revalidateTag("posts");
}
```

?! Редактор опубликовал статью через `publishPost`. Когда она появится в блоге: сразу или через 5 минут? А если убрать строку `revalidateTag`? || Сразу: `revalidateTag("posts")` сбросил кеш запроса с этим тегом. Без этой строки — в худшем случае через 5 минут, когда истечёт `revalidate = 300`.

### Частые ошибки
- **Кеширование персональных данных** — один пользователь видит данные другого.
- **«Старые данные»** без понимания, что страница закеширована.
- **Проверка кеша только в `npm run dev`.**

### Проверь себя
?? Что делает `export const revalidate = 60` в файле страницы? || Хранит готовую страницу и обновляет её не чаще раза в 60 секунд.
?? Как сразу обновить закешированный блог после публикации новой статьи? || Вызвать `revalidatePath("/blog")` или `revalidateTag` с тегом запросов после сохранения статьи.
?? Объясни своими словами, как выбрать стратегию кеширования для страницы. || Публичный и редко меняющийся контент кешировать на минуты или часы. Персональные и быстро меняющиеся данные — не кешировать или сбрасывать кеш сразу после изменений.

### Мини-задание
Сделай страницу, которая показывает текущее время сервера, с `revalidate = 10`. Собери проект, запусти `npm start` и понаблюдай: сколько секунд время не меняется при обновлении. Затем поставь `force-dynamic` и сравни.

### Ситуация
У блога 200 статей, и в выдаче Яндекса у всех одинаковый заголовок «Блог — Студия». Ссылка на статью в Telegram показывается без картинки. А каждая статья генерируется на сервере при каждом заходе, хотя меняется раз в год. Для SEO-специалиста это три боли сразу, и Next.js закрывает все три парой функций.

### На пальцах
`generateMetadata` — табличка на двери каждого кабинета: у каждой статьи свой заголовок и описание для поисковика и мессенджеров. `generateStaticParams` — заранее напечатать все страницы-брошюры на складе, чтобы выдавать их мгновенно, а не печатать по запросу.

### Как это работает
>> `generateStaticParams` → список страниц при сборке → `generateMetadata` → title и OG для каждой

Метаданные:

- Для страницы с постоянным текстом — экспорт объекта `export const metadata = { title, description }`.
- Для динамической страницы — функция `generateMetadata({ params })`, которая загружает данные и возвращает метаданные.
- В корневом layout удобно задать шаблон: `title: { template: "%s — Студия", default: "Студия" }`.
- Next.js сам вставит `<title>`, `<meta name="description">`, Open Graph и другие теги.

Статическая генерация:

- `generateStaticParams()` возвращает список параметров, для которых страницы надо собрать заранее при `npm run build`.
- Такие страницы отдаются как готовые HTML-файлы — максимально быстро.
- Новые slug, которых не было при сборке, тоже работают: страница соберётся при первом запросе.

?: Почему метаданные можно экспортировать только из серверных файлов? || Мета-теги должны оказаться в HTML ещё до того, как браузер выполнит JavaScript, — их читают роботы поисковиков и мессенджеров. Это возможно только при отрисовке на сервере.

### Пример
```tsx
// app/layout.tsx
export const metadata = {
  title: { template: "%s — Студия GeoBit", default: "Студия GeoBit" },
  description: "Сайты и SEO под ключ",
};

// app/blog/[slug]/page.tsx
export async function generateMetadata({ params }: { params: Promise<{ slug: string }> }): Promise<Metadata> {
  const { slug } = await params;
  const post = await getPost(slug);
  if (!post) return { title: "Статья не найдена" };
  return { title: post.title, description: post.excerpt };
}

// app/contacts/page.tsx — без своих metadata
```

?! Какой `<title>` будет у статьи «Как выбрать хостинг», а какой — у страницы контактов? || У статьи — «Как выбрать хостинг — Студия GeoBit»: заголовок подставился в шаблон `%s`. У контактов своих метаданных нет, поэтому сработает `default` — «Студия GeoBit».

### Частые ошибки
- **Один и тот же `title` для всех статей.**
- **`metadata` из клиентского компонента** — не сработает.
- **Данные недоступны при сборке** — `generateStaticParams` выполняется при `npm run build`.

### Проверь себя
?? Чем `export const metadata` отличается от `generateMetadata`? || `metadata` — постоянный объект для страницы с неизменным текстом. `generateMetadata` — функция, которая загружает данные и строит метаданные для динамической страницы.
?? Когда выполняется `generateStaticParams`? || Во время сборки проекта (`npm run build`).
?? Объясни своими словами, что даёт шаблон `title: { template: "%s — Студия" }`. || Все страницы автоматически получают единый формат заголовка: свой заголовок плюс название сайта, без повторения этой строки в каждой странице.

### Мини-задание
Добавь в свой блог шаблон заголовка в корневом layout, `generateMetadata` для статей и `generateStaticParams`. Выполни `npm run build` и найди в выводе, какие страницы собраны статически (значок ●).

### Ситуация
Дизайнер прислал фото для главного экрана — 6000×4000 пикселей, 8 мегабайт. Ты вставляешь его как есть, и на телефоне страница грузится 15 секунд, а Lighthouse ставит красную оценку. Вручную делать по пять размеров каждой картинки и конвертировать в WebP — долго. В Next.js это делает один компонент.

### На пальцах
`next/image` — умный фотограф-ретушёр. Ты даёшь ему огромную фотографию, а он сам подготовит нужные размеры для телефона и компьютера, переведёт в лёгкий формат, загрузит только когда до неё долистают, и заранее займёт место на странице, чтобы ничего не прыгало.

### Как это работает
>> `<Image src width height>` → нужный размер и формат → ленивая загрузка → нет сдвигов

Что делает компонент `Image` из `next/image`:

- создаёт несколько размеров картинки и отдаёт подходящий экрану (`srcset`);
- конвертирует в WebP или AVIF;
- включает ленивую загрузку по умолчанию;
- требует размеры (или `fill`), чтобы не было сдвига вёрстки;
- для главной картинки первого экрана — `priority`, чтобы она грузилась сразу.

Обязательные props: `src`, `alt`, и либо `width` + `height`, либо `fill` (тогда родитель должен быть `position: relative` с размерами).

`sizes` подсказывает, какую ширину картинка займёт на экране: `"(max-width: 768px) 100vw, 33vw"`.

Картинки с чужих доменов нужно разрешить в `next.config` через `images.remotePatterns`.

?: Зачем главной картинке первого экрана `priority`, если ленивая загрузка экономит трафик? || Главная картинка видна сразу, и её загрузка определяет, когда страница «появилась» для пользователя (метрика LCP). Ленивая загрузка её только задержит. `priority` говорит: «эту — грузи первой».

### Пример
```tsx
import Image from "next/image";

export default function Page() {
  return (
    <div className="card">
      <Image
        src="https://images.unsplash.com/photo-1498050108023-c5249f4df085"
        alt="Ноутбук с кодом на столе"
        fill
        sizes="(max-width: 768px) 100vw, 33vw"
        style={{ objectFit: "cover" }}
      />
    </div>
  );
}
```

?! Что пойдёт не так, если у `.card` нет `position: relative` и размеров, а домен Unsplash не добавлен в настройки? || Сначала — ошибка «hostname is not configured», потому что чужой домен не разрешён в `remotePatterns`. После исправления картинка с `fill` растянется на весь ближайший позиционированный блок, часто на весь экран, потому что у родителя нет `position: relative`.

### Частые ошибки
- **Чужой домен не в `remotePatterns`** — «hostname is not configured».
- **`fill` без `position: relative` у родителя** — картинка растягивается на весь экран.
- **`priority` у всех картинок** — пропадает смысл ленивой загрузки.

### Проверь себя
?? Какие props обязательны у `Image`? || `src`, `alt` и либо `width` с `height`, либо `fill`.
?? Для чего нужен атрибут `sizes`? || Подсказывает браузеру, какую ширину картинка займёт на экране, чтобы он скачал подходящий по размеру вариант.
?? Объясни своими словами, чем `next/image` лучше обычного `img`. || Он сам делает уменьшенные копии под разные экраны, переводит в лёгкие форматы, лениво загружает и резервирует место, чтобы страница не прыгала.

### Мини-задание
Замени обычные `img` в своём Next.js-проекте на `Image`. Для главной картинки поставь `priority`, для карточек — `sizes`. Сравни размер загруженных картинок в Network до и после.

### Ситуация
Сайт запустили три месяца назад, а в Яндексе он до сих пор показывает пять страниц из пятидесяти. Выясняется, что в `robots.txt` с этапа разработки осталось `Disallow: /`, а карты сайта нет вообще. Для студии, которая продаёт SEO, — позор. В Next.js эти файлы генерируются кодом и сами обновляются, когда появляются новые статьи.

### На пальцах
Поисковый робот — гость, который впервые пришёл в большой дом. `sitemap.xml` — карта всех комнат: «вот список страниц, обойди их». `robots.txt` — таблички «сюда не заходить» у служебных помещений. Open Graph — визитка, которую дом показывает, когда о нём рассказывают в мессенджерах.

### Как это работает
>> `sitemap.ts` → карта для поисковиков → `robots.ts` → правила → Open Graph → карточки ссылок

| Файл | Адрес | Что делает |
|---|---|---|
| `app/sitemap.ts` | `/sitemap.xml` | список адресов для поисковиков с датами изменений |
| `app/robots.ts` | `/robots.txt` | что можно и нельзя индексировать, где карта сайта |
| `app/opengraph-image.tsx` или `.png` | картинка превью | автоматически подставляется в `og:image` |
| `app/icon.png` | фавикон | подключается сам |

Sitemap может быть динамическим: загрузить все статьи из базы и добавить их адреса.

После публикации добавь сайт в Яндекс Вебмастер и Google Search Console и укажи адрес sitemap.

?: Чем динамический `sitemap.ts` лучше статического файла `sitemap.xml`? || Статический файл нужно обновлять руками после каждой новой статьи, и об этом легко забыть. Динамический берёт список прямо из базы — новая статья попадает в карту сайта автоматически.

### Пример
```ts
// app/sitemap.ts
import type { MetadataRoute } from "next";

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts = await getAllPosts();
  return [
    { url: "https://geobit.ru", lastModified: new Date() },
    ...posts.map(p => ({ url: `/blog/${p.slug}`, lastModified: p.updatedAt })),
  ];
}

// app/robots.ts
export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: "*", allow: "/", disallow: ["/admin", "/api"] },
    sitemap: "https://geobit.ru/sitemap.xml",
  };
}
```

?! Найди ошибку в `sitemap.ts`, из-за которой поисковики не смогут использовать адреса статей. || Адреса статей относительные: `/blog/${p.slug}`. В sitemap нужны полные адреса с доменом: `https://geobit.ru/blog/${p.slug}`.

### Частые ошибки
- **`disallow: "/"` с этапа разработки** — сайт не попадает в поиск.
- **Относительные адреса в sitemap** — нужны полные, с доменом.
- **Страница закрыта в robots.txt, но есть в sitemap** — противоречивые сигналы поисковикам.

### Проверь себя
?? По какому адресу будет доступен файл, сгенерированный из `app/sitemap.ts`? || `/sitemap.xml`.
?? Что указывают в `robots.txt` кроме правил индексации? || Адрес карты сайта — строку `sitemap`.
?? Объясни своими словами, зачем сайту `sitemap.xml` и `robots.txt`. || Sitemap даёт поисковикам полный список страниц, чтобы они быстрее их нашли. Robots закрывает служебные разделы от индексации и указывает, где лежит карта сайта.

### Мини-задание
Добавь в Next.js-проект `sitemap.ts` с главной, услугами и всеми статьями блога и `robots.ts`, закрывающий `/admin`. Открой `/sitemap.xml` и `/robots.txt` и проверь содержимое.
