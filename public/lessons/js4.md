### Ситуация
Список дел, корзина товаров, лента постов, результаты поиска — всё это списки. Хранить каждое дело в отдельной переменной (`task1`, `task2`, `task3`…) невозможно: заранее неизвестно, сколько их будет. Массив — первая структура данных, без которой не обходится ни одна программа. И первая, где ты будешь путать `slice` со `splice`.

### На пальцах
Массив — поезд с пронумерованными вагонами. Нумерация начинается с нуля: первый вагон — № 0. `length` — сколько вагонов в составе. `push` — прицепить вагон в конец. `slice` — сфотографировать часть поезда, не отцепляя вагоны.

### Как это работает
>> `[10, 20, 30]` → индекс с `0` → `length` → `push` — в конец → `slice` — копия части

- Создание: `const fruits = ["яблоко", "груша", "слива"]`.
- Доступ по индексу: `fruits[0]` — первый, `fruits.at(-1)` — последний.
- `length` — количество элементов.
- **Меняют** массив: `push` (в конец), `pop` (убрать последний), `unshift` (в начало), `shift` (убрать первый), `splice` (вырезать или вставить в середине), `sort`, `reverse`.
- **Не меняют**, возвращают новое: `slice(начало, конец)` (конец не включается), `concat`, `map`, `filter`, `[...arr]`.
- Поиск: `includes(x)` — есть ли, `indexOf(x)` — под каким номером (или -1).
- `join(", ")` — склеить в строку, `"a,b".split(",")` — разрезать строку в массив.

?: Почему важно знать, какие методы меняют исходный массив, а какие нет? || Если массив используется в нескольких местах — в корзине, в итогах, в истории, — метод, который его меняет, тихо испортит данные везде. А в React изменённый на месте массив вообще не вызовет перерисовку.

### Пример
```js
const tasks = ["вёрстка", "стили", "скрипты"];
const n = tasks.push("деплой");
const first2 = tasks.slice(0, 2);

console.log(n, tasks.length);
console.log(first2, tasks[4]);
console.log(tasks.indexOf("тесты"));
```

?! Что выведут три строки? || `4 4` — `push` возвращает новую длину, а не массив. `["вёрстка", "стили"] undefined` — `slice` берёт индексы 0 и 1, а элемента с индексом 4 нет, ошибки при этом не будет. `-1` — такой задачи нет.

### Частые ошибки
- **Ждать ошибку при выходе за границы.** `tasks[10]` даст `undefined`, а не ошибку — и баг тихо поедет дальше.
- **Путать `slice` и `splice`.** `slice` копирует кусок, `splice` вырезает его из исходного массива.
- **Сохранять результат `push`:** он возвращает длину, а не массив.

### Проверь себя
?? Как получить последний элемент массива? || `arr.at(-1)` или `arr[arr.length - 1]`.
?? Чем `slice` отличается от `splice`? || `slice` возвращает копию части массива и не меняет его. `splice` вырезает или вставляет элементы прямо в исходном массиве.
?? Объясни своими словами, почему первый элемент массива имеет индекс 0. || Индекс — это смещение от начала массива. У первого элемента смещение ноль, у второго — один, и так далее.

### Ситуация
Карточка товара — это название, цена, фото, рейтинг, наличие, характеристики. Хранить всё это в шести отдельных переменных для каждого из сотни товаров — безумие. Объект собирает все данные одной сущности в одну «анкету». А ещё именно с объектами связана первая неожиданность: «копия», которая на самом деле не копия.

### На пальцах
Объект — анкета с полями: «Имя: Анна», «Город: Москва», «Возраст: 27». Точка — когда название поля знаешь заранее: «покажи графу Город». Квадратные скобки — когда название поля написано на бумажке и может меняться: «покажи графу, которая указана вот здесь».

### Как это работает
>> `user.name` — известное имя → `user[key]` — имя в переменной → добавить, изменить, удалить

- Создание: `const user = { name: "Анна", age: 27 }`. Слева ключ, справа значение.
- Чтение: `user.name` или `user["name"]`.
- Запись: `user.city = "Москва"` — добавит новое поле или изменит существующее.
- Удаление: `delete user.age`.
- Нет такого поля — получишь `undefined`, не ошибку.
- Квадратные скобки нужны, если ключ в переменной (`user[field]`) или в ключе есть пробел или дефис (`obj["full-name"]`).
- Короткая запись: `{ name, age }` вместо `{ name: name, age: age }`.
- Перебор: `Object.keys(obj)`, `Object.values(obj)`, `Object.entries(obj)` (пары ключ-значение).
- Проверка наличия поля: `"city" in user`.

Значением может быть что угодно: массив, другой объект, функция (тогда это метод).

?: Почему `const copy = user` не создаёт копию объекта? || В переменной лежит не сам объект, а ссылка на него — «адрес коробки». Присваивание копирует адрес, и обе переменные указывают на одну коробку. Настоящая копия делается через `{ ...user }`.

### Пример
```js
const project = {
  title: "Лендинг кофейни",
  budget: 40000,
  client: { name: "Kofeby", city: "Минск" },
};

const field = "budget";
const same = project;
same.status = "в работе";

console.log(project.field, project[field]);
console.log(project.status);
console.log(project.manager?.name);
```

?! Что выведут три строки? || `undefined 40000` — точка ищет поле буквально с именем «field», а скобки берут имя из переменной. `в работе` — `same` и `project` одна и та же коробка. `undefined` — благодаря `?.` без ошибки, хотя менеджера нет.

### Частые ошибки
- **`user.field` вместо `user[field]`**, когда ключ в переменной — ищется поле с именем «field».
- **Поле у `undefined`:** `project.manager.name` при отсутствии `manager` — ошибка. Используй `project.manager?.name`.
- **Копия присваиванием:** `const copy = user` — та же коробка. Копия: `{ ...user }`.

### Проверь себя
?? Когда нужны квадратные скобки вместо точки? || Когда имя поля лежит в переменной или содержит пробелы, дефисы и другие недопустимые для точки символы.
?? Что вернёт обращение к несуществующему полю? || `undefined`, без ошибки.
?? Объясни своими словами, что делает `Object.entries(obj)`. || Превращает объект в массив пар `[ключ, значение]`, чтобы его удобно было перебрать циклом.

Опиши объектом свою карточку товара: название, цена, характеристики (вложенный объект), теги (массив). Выведи все характеристики циклом по `Object.entries`. Затем получи значение поля, имя которого лежит в переменной.

### Ситуация
У тебя массив из 200 заказов. Нужно: показать только оплаченные, посчитать выручку, найти заказ Бориса и проверить, есть ли долги. Через `for` это четыре цикла, четыре временные переменные и куча места для ошибок. Через методы массивов — четыре строчки, которые читаются как предложения на английском.

### На пальцах
Методы массивов — конвейер на фабрике. `map` — станок, который каждую деталь превращает во что-то другое. `filter` — контролёр, который пропускает только годные. `find` — ищет первую подходящую деталь. `some` — проверка «есть хоть одна бракованная?». `reduce` — упаковщик, собирающий всё в одну коробку. `sort` — расставить по порядку.

### Как это работает
>> `filter` — отобрать → `map` — преобразовать → `reduce` — свести к одному → `sort` — упорядочить

Все методы принимают функцию, которая вызывается для каждого элемента.

| Метод | Возвращает | Пример |
|---|---|---|
| `map(fn)` | новый массив той же длины | цены → цены со скидкой |
| `filter(fn)` | новый массив тех, где fn вернула true | только активные |
| `find(fn)` | первый подходящий элемент или undefined | пользователь с id 5 |
| `some(fn)` | true, если хоть один подходит | есть ли просроченные |
| `every(fn)` | true, если подходят все | все ли оплачены |
| `reduce(fn, start)` | одно значение | сумма, объект-группировка |
| `sort(fn)` | тот же массив, отсортированный | по цене |

`reduce((acc, item) => ..., начальное)` — `acc` («аккумулятор») — то, что накопили к текущему шагу. Функция возвращает новое значение аккумулятора.

`sort` по умолчанию сравнивает как строки, поэтому числа сортируют так: `sort((a, b) => a - b)`. Он меняет исходный массив — сначала скопируй.

Методы можно соединять в цепочку: `filter` → `map` → `reduce`.

?: Почему `[10, 9, 1].sort()` даёт `[1, 10, 9]`? || Без функции сравнения `sort` превращает элементы в строки и сравнивает их по алфавиту: «1» < «10» < «9», как в словаре. Для чисел нужна функция `(a, b) => a - b`.

### Пример
```js
const orders = [
  { id: 1, client: "Анна", sum: 1500, paid: true },
  { id: 2, client: "Борис", sum: 3200, paid: false },
  { id: 3, client: "Вика", sum: 800, paid: true },
];

const revenue = orders
  .filter(o => o.paid)
  .reduce((acc, o) => acc + o.sum, 0);
const hasDebt = orders.some(o => !o.paid);
const top = [...orders].sort((a, b) => b.sum - a.sum)[0].client;

console.log(revenue, hasDebt, top);
```

?! Что выведет `console.log`? Пройди цепочку в уме. || `2300 true Борис`. Оплачены Анна и Вика: 1500 + 800. Борис не оплатил — долг есть. При сортировке по убыванию первым идёт самый большой заказ — Бориса.

### Частые ошибки
- **Фигурные скобки без `return`:** `map(o => { o.sum })` даст массив из `undefined`.
- **`reduce` без начального значения** на пустом массиве — ошибка.
- **`sort()` для чисел без функции:** `[10, 9, 1].sort()` → `[1, 10, 9]`.

### Проверь себя
?? Чем `filter` отличается от `find`? || `filter` возвращает массив всех подходящих элементов, `find` — первый подходящий элемент или `undefined`.
?? Что такое `acc` в `reduce`? || Аккумулятор — значение, накопленное к текущему шагу. Функция возвращает его новую версию.
?? Объясни своими словами, что делает `map`. || Проходит по массиву и превращает каждый элемент во что-то новое, возвращая новый массив той же длины.

### Мини-задание
Возьми массив товаров с названием, ценой и наличием. Получи: список названий, только товары в наличии, самый дорогой товар, общую стоимость товаров в наличии. Используй цепочку методов. Посмотри схему «map, filter, reduce — конвейер» в этом уроке.

### Ситуация
Из ответа сервера нужно достать имя пользователя, email из вложенного объекта контактов и первый заказ. Получается три строчки вида `const email = response.user.contacts.email`. В React-коде такое на каждом шагу, и опытные разработчики пишут это одной строкой. Деструктуризация и spread выглядят как шифр, пока не разберёшь их один раз.

### На пальцах
Деструктуризация — распаковка посылки: вместо «открой коробку, достань чашку, достань блюдце» говоришь одной фразой «чашку сюда, блюдце туда». Spread `...` — высыпать содержимое одной коробки в другую: удобно, чтобы сделать копию или объединить две коробки.

### Как это работает
>> `const { name } = user` → `const [a, b] = arr` → `{ ...user, age: 30 }` — копия с изменением

Деструктуризация объекта — по именам полей:

```js
const { name, city = "Не указан", contacts: { email } } = user;
```

Можно задать значение по умолчанию и переименовать: `const { name: userName } = user`.

Деструктуризация массива — по позиции:

```js
const [first, second, ...rest] = list;
```

Spread `...` раскладывает:

- `[...arr, 4]` — копия массива с новым элементом;
- `{ ...obj, city: "Казань" }` — копия объекта с изменённым полем (поле справа перезапишет);
- `Math.max(...nums)` — передать элементы массива как отдельные аргументы.

Деструктуризация в параметрах функции — частый приём в React: `function Card({ title, price }) { ... }`.

Spread делает поверхностную копию: вложенные объекты остаются общими.

?: Что значит «поверхностная копия»? || Копируется только верхний уровень: новые коробки для полей первого уровня. Вложенный объект, например `contacts`, не копируется — в копии лежит ссылка на тот же самый объект, и его изменение видно в обоих.

### Пример
```js
const user = { name: "Анна", age: 27, contacts: { email: "a@mail.ru" } };

const [winner, , ...others] = ["Анна", "Борис", "Вика", "Глеб"];
const older = { age: 99, ...user };
const copy = { ...user };
copy.contacts.email = "new@mail.ru";

console.log(winner, others);
console.log(older.age, user.contacts.email);
```

?! Что выведут две строки? || `Анна ["Вика", "Глеб"]` — пропущенная позиция пропускает Бориса. `27 new@mail.ru`: в `older` возраст из `user` записан позже и перезаписал 99, а `contacts` в копии — тот же объект, что в оригинале.

### Частые ошибки
- **Деструктуризация `undefined`:** `const { name } = undefined` — ошибка. Дай значение по умолчанию: `= {}`.
- **Вера в глубокую копию:** `copy.contacts.email = "..."` изменит и исходный объект.
- **Порядок в spread объектов:** `{ age: 28, ...user }` — возраст перезапишется старым.

### Проверь себя
?? Как достать поле `name` из объекта и сразу переименовать его в `userName`? || `const { name: userName } = user`.
?? Как сделать копию массива с новым элементом в конце, не меняя исходный? || `const longer = [...arr, newItem]`.
?? Объясни своими словами, чем деструктуризация массива отличается от деструктуризации объекта. || Массив распаковывается по позициям: первый, второй, остальные. Объект — по именам полей, порядок неважен.

### Мини-задание
Из объекта заказа `{ id, client: { name, phone }, items: [...] }` одной строкой достань имя клиента и первый товар. Сделай копию заказа с новым статусом через spread, не меняя исходный.

### Ситуация
Открой любой сайт: товары, посты, задачи, сообщения, отзывы, уведомления. Почти всё — список одинаковых карточек. А за каждым таким списком в коде стоит одно и то же — массив объектов. Здесь соберутся вместе массивы, объекты, методы и spread. Освоишь эти восемь операций — поймёшь 80% повседневного фронтенда.

### На пальцах
Массив объектов — картотека: каждая карточка — объект с одинаковыми графами, а у каждой карточки есть уникальный номер (`id`), по которому её находят, правят или выбрасывают.

### Как это работает
>> Сервер → массив объектов `[{id, title}]` → `filter`, `map` → карточки на странице

С сервера данные почти всегда приходят как массив объектов в формате JSON:

```js
[
  { "id": 1, "title": "Кроссовки", "price": 5990, "category": "обувь" },
  { "id": 2, "title": "Куртка",    "price": 8990, "category": "одежда" }
]
```

Типичные операции, которые ты будешь делать всю карьеру:

| Задача | Метод |
|---|---|
| Показать список | `map` → HTML или компоненты |
| Поиск и фильтр | `filter` |
| Найти по id | `find` |
| Сортировка | `[...arr].sort(...)` |
| Итоги, суммы | `reduce` |
| Добавить | `[...arr, newItem]` |
| Изменить один | `arr.map(x => x.id === id ? { ...x, done: true } : x)` |
| Удалить | `arr.filter(x => x.id !== id)` |

?: Почему элементы ищут и удаляют по `id`, а не по индексу? || Индекс — это позиция, и она меняется после сортировки, фильтра или удаления соседнего элемента. `id` навсегда привязан к конкретной записи, поэтому всегда указывает на нужную карточку.

### Пример
```js
let todos = [
  { id: 1, text: "Сверстать шапку", done: true },
  { id: 2, text: "Подключить шрифты", done: false },
  { id: 3, text: "Задеплоить", done: false },
];

todos = [...todos, { id: 4, text: "Написать README", done: false }];
todos = todos.map(t => t.id === 2 ? { ...t, done: true } : t);
todos = todos.filter(t => t.id !== 3);

console.log(todos.length, todos.filter(t => !t.done).length);
```

?! Что выведет последняя строка? || `3 1`. Добавили четвёртую задачу (4 штуки), отметили вторую выполненной, удалили третью — осталось три. Невыполненной осталась только «Написать README».

### Частые ошибки
- **Поиск и удаление по индексу** вместо `id` — после сортировки или фильтра индексы меняются.
- **Изменение объекта прямо в массиве** (`todos[1].done = true`) там, где нужна неизменяемость, например в React.
- **Пользовательский текст в HTML через шаблонную строку** без экранирования — так появляется XSS. Позже научимся делать это безопасно.

### Проверь себя
?? Как удалить элемент с нужным `id`, не меняя исходный массив? || `arr.filter(x => x.id !== id)`.
?? Как изменить одно поле у одного элемента, получив новый массив? || `arr.map(x => x.id === id ? { ...x, done: true } : x)`.
?? Объясни своими словами, почему у каждого объекта в списке должен быть уникальный `id`. || По нему элемент однозначно находят, изменяют и удаляют, независимо от того, как отсортирован или отфильтрован список.

Сделай массив из пяти контактов (`id`, имя, телефон, избранный). Напиши функции: добавить контакт, переключить «избранный» по `id`, удалить по `id`, получить только избранных, отсортированных по имени. Каждая функция возвращает новый массив.
