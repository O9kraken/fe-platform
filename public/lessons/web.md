### На пальцах
Файл — это лист бумаги с текстом, папка — ящик, в котором лежат листы. Расширение — надпись на обложке: «рецепт», «письмо», «чертёж». Сам текст внутри может быть одинаковым, но надпись подсказывает компьютеру, какой программой открыть лист.

### Как это работает
1. Любой файл — это просто набор байтов на диске. Компьютер не «понимает» содержимое сам.
2. Расширение — часть имени после точки: `index.html`, `notes.txt`, `photo.jpg`. По нему система выбирает программу.
3. Файл `.txt` откроется в Блокноте и покажет текст как есть.
4. Файл `.html` откроется в браузере. Браузер прочитает теги вроде `<h1>` и нарисует из них страницу: заголовок, абзацы, ссылки.
5. Если переименовать `page.txt` в `page.html`, содержимое не изменится, но браузер начнёт понимать его как страницу.

В Windows расширения по умолчанию скрыты. Включи их: Проводник → «Вид» → «Расширения имён файлов». Иначе легко получить `index.html.txt` и долго не понимать, почему браузер показывает теги текстом.

### Пример
Создай файл `hello.html` в любом редакторе и вставь:

```html
<!doctype html>
<h1>Привет, веб!</h1>
<p>Это моя первая страница.</p>
```

Открой его двойным кликом — браузер покажет крупный заголовок и абзац. Теперь сохрани тот же текст как `hello.txt` и открой — увидишь теги как обычные буквы.

### Частые ошибки
- Скрытые расширения: файл называется `index.html.txt`, а ты видишь только `index.html`.
- Пробелы и русские буквы в именах: `Моя страница.html`. Для сайтов используй латиницу, цифры и дефис: `my-page.html`.
- Файлы проекта разбросаны по Рабочему столу. Заведи одну папку, например `web-learning`, и держи всё в ней.

### Мини-задание
Включи отображение расширений. Создай папку `web-learning`, в ней `index.html` с заголовком и двумя абзацами о себе. Открой в браузере, затем переименуй в `.txt` и сравни, как файл открывается теперь.

### На пальцах
URL — это полный почтовый адрес: страна, город, улица, квартира. Домен — название дома, которое легко запомнить: «Дом книги». IP-адрес — точные координаты дома цифрами. DNS — справочная, куда ты звонишь и спрашиваешь: «Где находится Дом книги?», а тебе называют координаты.

### Как это работает
Разберём адрес `https://shop.example.com:443/catalog/shoes?color=red#reviews`:

| Часть | Что это |
|---|---|
| `https:` | протокол — как разговаривать с сервером |
| `shop.example.com` | домен — имя сервера |
| `:443` | порт — «номер двери» на сервере, обычно не пишут |
| `/catalog/shoes` | путь — какая страница нужна |
| `?color=red` | параметры — дополнительные условия |
| `#reviews` | якорь — к какому месту страницы прокрутить |

Что происходит, когда ты нажимаешь Enter:

1. Браузер берёт домен `shop.example.com` и спрашивает у DNS его IP-адрес.
2. DNS отвечает, например, `93.184.216.34`.
3. Браузер подключается к компьютеру с этим адресом и просит страницу по пути `/catalog/shoes`.

Домен нужен людям, IP — компьютерам. Один сервер с одним IP может обслуживать много доменов.

### Пример
Объект `URL` в браузере разбирает адрес так же, как сам браузер. Открой консоль (F12 → Console) и выполни:

```js
const url = new URL("https://shop.example.com/catalog/shoes?color=red#reviews");
console.log(url.hostname);              // shop.example.com
console.log(url.pathname);              // /catalog/shoes
console.log(url.searchParams.get("color")); // red
console.log(url.hash);                  // #reviews
```

### Частые ошибки
- Путать домен и адрес страницы: `example.com` — домен, `example.com/about` — конкретная страница на нём.
- Думать, что якорь `#reviews` уходит на сервер. Нет, его обрабатывает только браузер.
- Считать, что сайт «лежит в домене». Домен лишь указывает на сервер; сменишь запись DNS — тот же домен откроет другой сервер.

### Мини-задание
Возьми адрес любой страницы интернет-магазина с фильтрами. Выпиши отдельно протокол, домен, путь и все параметры. Проверь себя через `new URL(...)` в консоли.

### На пальцах
HTTP — это вежливый разговор в окошке выдачи. Ты подаёшь записку: «Дайте, пожалуйста, страницу /catalog». Сотрудник отвечает кодом и коробкой: «200 — вот, держите», «404 — такого нет», «301 — это теперь в соседнем окошке», «500 — у нас сломался склад».

### Как это работает
Запрос и ответ — обычный текст из трёх частей: стартовая строка, заголовки и (не всегда) тело.

Запрос браузера:

```http
GET /catalog HTTP/1.1
Host: shop.example.com
Accept: text/html
```

- `GET` — метод: что хотим сделать (получить)
- `/catalog` — путь
- `Host`, `Accept` — заголовки: дополнительная информация

Ответ сервера:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!doctype html><h1>Каталог</h1>...
```

Код ответа — три цифры. Первая цифра говорит, чем всё закончилось:

| Код | Значение | Когда бывает |
|---|---|---|
| 200 | всё хорошо | страница найдена |
| 301 | переехало навсегда | сайт перешёл на новый адрес, браузер сам идёт туда |
| 404 | не найдено | опечатка в адресе или страницу удалили |
| 500 | ошибка сервера | в коде сайта что-то упало |

Запомни правило: 4xx — проблема на стороне того, кто спрашивает; 5xx — на стороне сервера.

### Пример
Открой DevTools (F12) → вкладка Network → обнови страницу. Кликни по первому запросу и посмотри раздел Headers: там видно метод, адрес, код ответа и все заголовки. Потом открой несуществующую страницу, например `https://github.com/abracadabra-404`, и найди в Network код 404.

### Частые ошибки
- Думать, что 404 — «сломался интернет». Интернет работает, сервер честно ответил: «такого нет».
- Путать 401 и 403: 401 — «ты не вошёл», 403 — «вошёл, но тебе нельзя».
- Считать, что одна страница — один запрос. Страница — это десятки запросов: HTML, стили, скрипты, картинки, шрифты.

### Мини-задание
Открой любой новостной сайт с вкладкой Network. Посчитай, сколько запросов ушло при загрузке и какие из них самые тяжёлые (колонка Size). Найди хотя бы один код, отличный от 200.

### На пальцах
HTTP — открытка: почтальон и все по дороге могут прочитать текст. HTTPS — письмо в запечатанном конверте, который может открыть только получатель. Замок в адресной строке говорит: «конверт запечатан, и это действительно тот адресат, за кого он себя выдаёт».

### Как это работает
1. У сайта есть сертификат — электронный паспорт, выданный удостоверяющим центром.
2. При подключении браузер проверяет: паспорт настоящий, выдан именно этому домену и не просрочен.
3. Браузер и сервер договариваются о секретном ключе, который знают только они двое. Это называется TLS-рукопожатие.
4. Дальше весь обмен шифруется: пароли, формы, cookie. Кто-то в той же Wi-Fi-сети в кафе увидит только шум.

Что HTTPS не гарантирует: что сайт честный. Мошеннический сайт тоже может получить сертификат. Замок означает «соединение защищено», а не «здесь безопасно оставлять деньги».

Сейчас сертификаты бесплатны (Let's Encrypt), а хостинги вроде Render, Vercel и Netlify подключают их автоматически. Сайт без HTTPS браузеры помечают как «Не защищено», а поисковики ставят ниже.

### Пример
Кликни на замок слева от адреса любого сайта → «Подключение защищено» → «Сертификат». Посмотри, кому он выдан, кем и до какой даты действует.

```http
http://example.com   → 301 → https://example.com
```

Так сайты обычно перенаправляют со старого адреса на защищённый.

### Частые ошибки
- Вводить пароль на странице, где в адресе `http://` без замка.
- Считать замок знаком надёжности магазина. Проверяй домен по буквам: `sberbank-online.ru.secure-pay.top` — не Сбербанк.
- Смешанное содержимое: страница по HTTPS грузит картинку по `http://`. Браузер заблокирует её или покажет предупреждение.

### Мини-задание
Открой три сайта и посмотри их сертификаты: кто выдал, на какой срок. Найди, у какого из них сертификат выпущен Let's Encrypt.

### На пальцах
DevTools — это рентген и стетоскоп для сайта. Elements показывает скелет страницы, Console — что сайт «говорит» и на что жалуется, Network — все посылки, которые браузер отправил и получил.

### Как это работает
Открываются клавишей F12 или Ctrl + Shift + I (на Mac — Cmd + Option + I). Три главные вкладки:

| Вкладка | Что там | Когда нужна |
|---|---|---|
| Elements | HTML-дерево и стили выбранного элемента | «почему кнопка не того цвета», «откуда отступ» |
| Console | сообщения и ошибки JavaScript, можно выполнять код | «почему кнопка не работает» |
| Network | все запросы: адрес, код, размер, время | «почему не загрузились данные», «что так долго грузится» |

Полезные приёмы:

- Стрелка в левом верхнем углу DevTools (или Ctrl + Shift + C) — кликни по любому элементу страницы, и он подсветится в Elements.
- В Elements можно менять текст и стили прямо на лету — удобно примерять, но после перезагрузки всё вернётся.
- В Network включи «Disable cache», чтобы видеть страницу как новый посетитель.
- Значок телефона (Ctrl + Shift + M) показывает, как сайт выглядит на мобильном.

### Пример
Открой любой сайт, нажми F12 → Console и выполни:

```js
document.title = "Я поменял заголовок вкладки";
document.body.style.background = "#fffae6";
console.log("Ссылок на странице:", document.querySelectorAll("a").length);
```

Заголовок вкладки и фон изменятся, а в консоли появится число ссылок.

### Частые ошибки
- Не открывать Console, когда «ничего не работает». Красная строка ошибки почти всегда говорит, в чём дело и в какой строке.
- Править стили в Elements и забыть перенести их в свой CSS-файл.
- Смотреть Network без перезагрузки: запросы записываются только пока вкладка открыта, поэтому сначала открой её, потом обнови страницу.

### Мини-задание
На любом сайте найди через Elements главный заголовок, поменяй ему текст и цвет. Затем в Network найди самую большую картинку страницы и её размер в килобайтах.
