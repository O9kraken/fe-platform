### На пальцах
Семантические теги — подписанные комнаты в доме: прихожая, кухня, спальня. Можно жить и в доме, где все двери подписаны «комната», но гостю (поисковику, скринридеру, новому разработчику) будет трудно понять, где что.

### Как это работает
| Тег | Что внутри |
|---|---|
| `header` | шапка: логотип, меню, иногда поиск |
| `nav` | навигация: главное меню, хлебные крошки |
| `main` | основное уникальное содержимое страницы, один на странице |
| `section` | смысловой раздел с заголовком: «Услуги», «Отзывы» |
| `article` | самостоятельный блок, который можно вынести отдельно: статья, карточка товара, пост |
| `aside` | второстепенное: боковая колонка, «читайте также» |
| `footer` | подвал: контакты, копирайт, ссылки |

`div` — коробка без смысла. Он нужен для оформления: сгруппировать элементы ради сетки или фона. Правило: если у блока есть смысл из таблицы выше — бери семантический тег; если нужна просто обёртка для CSS — `div`.

Зачем это всё:

- Скринридеры позволяют прыгать сразу к `main` или к `nav`.
- Поисковики лучше понимают, где главное содержимое.
- Код читается легче: `<footer>` понятнее, чем `<div class="bottom-part">`.

### Пример
```html
<header>
  <a href="/" class="logo">Студия</a>
  <nav>
    <ul>
      <li><a href="#services">Услуги</a></li>
      <li><a href="#contacts">Контакты</a></li>
    </ul>
  </nav>
</header>

<main>
  <section id="services">
    <h2>Услуги</h2>
    <article>
      <h3>Лендинг под ключ</h3>
      <p>От 30 000 ₽, срок — 2 недели.</p>
    </article>
  </section>
  <aside>
    <p>Скидка 10% до конца месяца</p>
  </aside>
</main>

<footer id="contacts">
  <p>© 2026 Студия · hello@studio.ru</p>
</footer>
```

### Частые ошибки
- Несколько `main` на странице.
- `section` без заголовка — тогда это скорее `div`.
- Заменить все `div` на `section` «для семантики». Семантика — про смысл, а не про количество модных тегов.

### Мини-задание
Перепиши свою страницу «Обо мне» так, чтобы в ней были `header` с меню, `main` с двумя `section` и `footer` с контактами. В DevTools посмотри дерево и убедись, что по тегам понятна структура.

### На пальцах
Форма — бланк в банке. `form` — сам лист, `input` — пустые клеточки, `label` — подписи у клеточек: «Фамилия», «Телефон». Связь подписи и поля через `for` и `id` — как стрелочка от подписи к клеточке: ткнул в подпись — попал в поле.

### Как это работает
- `form` собирает поля и отправляет их. Атрибут `action` — куда отправить, `method` — как (`get` или `post`).
- `input` — поле ввода. Атрибут `type` меняет поведение и клавиатуру на телефоне.
- `name` — имя поля. Под этим именем значение уйдёт на сервер. Без `name` поле не отправится.
- `label` с `for="email"` привязывается к полю с `id="email"`. Клик по подписи ставит курсор в поле, а скринридер зачитывает подпись.

Полезные типы `input`:

| type | Что делает |
|---|---|
| `text` | обычный текст |
| `email` | проверяет наличие @, на телефоне клавиатура с @ |
| `tel` | цифровая клавиатура на телефоне |
| `password` | скрывает символы |
| `number` | число, стрелочки вверх-вниз |
| `checkbox` | галочка «да/нет» |
| `radio` | один вариант из нескольких (одинаковый `name`) |
| `date` | выбор даты |

Второй способ связать — вложить поле прямо в `label`: `<label>Имя <input name="name"></label>`.

### Пример
```html
<form action="/api/lead" method="post">
  <label for="name">Как вас зовут</label>
  <input id="name" name="name" type="text" autocomplete="name">

  <label for="phone">Телефон</label>
  <input id="phone" name="phone" type="tel" autocomplete="tel">

  <p>Удобный способ связи:</p>
  <label><input type="radio" name="contact" value="call" checked> Звонок</label>
  <label><input type="radio" name="contact" value="tg"> Telegram</label>

  <label><input type="checkbox" name="agree" required> Согласен на обработку данных</label>

  <button type="submit">Отправить заявку</button>
</form>
```

### Частые ошибки
- Нет `name` — данные поля не дойдут до сервера.
- `for` и `id` не совпадают (опечатка) — связь не работает.
- Для всего используется `type="text"`, и на телефоне неудобно вводить номер.

### Мини-задание
Сделай форму записи на консультацию: имя, email, телефон, дата, выбор тарифа радиокнопками и галочка согласия. Проверь, что клик по каждой подписи ставит курсор в нужное поле.

### На пальцах
`input` — строчка в анкете, `textarea` — большое поле «Расскажите о себе», `select` — выпадающий список «Выберите город», `button` — кнопка «Отправить» у окошка.

### Как это работает
- `textarea` — многострочный текст. Значение по умолчанию пишется между тегами, а не в атрибуте. Высоту задаёт `rows`.
- `select` — список вариантов. Каждый вариант — `option` со своим `value`. Первый пустой вариант с `disabled selected` работает как подсказка.
- `button` — кнопка. У неё важный атрибут `type`:
  - `submit` (по умолчанию внутри формы) — отправляет форму;
  - `button` — просто кнопка, ничего не отправляет, для JavaScript;
  - `reset` — очищает форму (нужна редко).

Главное правило: кнопка — это `button`, ссылка — это `a`. Кнопка что-то делает на странице, ссылка куда-то ведёт. Не делай кнопки из `div` — их нельзя нажать с клавиатуры.

### Пример
```html
<form>
  <label for="service">Услуга</label>
  <select id="service" name="service">
    <option value="" disabled selected>Выберите услугу</option>
    <option value="landing">Лендинг</option>
    <option value="shop">Интернет-магазин</option>
    <option value="seo">SEO-продвижение</option>
  </select>

  <label for="msg">Опишите задачу</label>
  <textarea id="msg" name="message" rows="5" maxlength="1000"></textarea>

  <button type="button" id="preview">Предпросмотр</button>
  <button type="submit">Отправить</button>
</form>
```

### Частые ошибки
- Кнопка «Показать пароль» внутри формы без `type="button"` — при нажатии форма отправляется.
- Писать значение `textarea` в атрибут `value` — там его нет.
- `<div onclick="...">Купить</div>` вместо `button`.

### Мини-задание
Добавь в форму заявки `select` с тремя бюджетами, `textarea` для описания и две кнопки: «Очистить» (`type="reset"`) и «Отправить». Проверь, что Enter в поле отправляет форму.

### На пальцах
`required` — отметка «обязательно» на бланке: сотрудник не примет его пустым. `placeholder` — бледная карандашная подсказка в клеточке: как только начинаешь писать, она стирается. А `label` — подпись, напечатанная навсегда.

### Как это работает
- `required` — браузер не отправит форму, пока поле пустое, и покажет подсказку. Для `type="email"` ещё и проверит формат.
- Другие встроенные проверки: `minlength`, `maxlength`, `min`, `max`, `pattern` (регулярное выражение).
- `placeholder` — пример формата: «+7 999 123-45-67», «anna@mail.ru».

Почему `placeholder` не заменяет `label`:

1. Он исчезает, как только человек начал печатать. Отвлёкся — и не помнишь, что это за поле.
2. У него бледный цвет и плохой контраст, его трудно прочитать.
3. Скринридеры часто его не зачитывают.
4. Браузерное автозаполнение может его перекрыть.

Важно: проверки в браузере — для удобства пользователя. Сервер всё равно должен проверять данные сам: атрибут `required` можно удалить через DevTools за секунду.

### Пример
```html
<label for="email">Email</label>
<input id="email" name="email" type="email" required placeholder="anna@mail.ru">

<label for="pass">Пароль</label>
<input id="pass" name="password" type="password" required minlength="8">

<label for="zip">Индекс</label>
<input id="zip" name="zip" inputmode="numeric" pattern="[0-9]{6}" placeholder="101000">
```

### Частые ошибки
- Форма без единого `label`, только с `placeholder`.
- Важная подсказка («пароль не короче 8 символов») спрятана в `placeholder`. Пиши её текстом рядом с полем.
- Надеяться на `required` как на защиту данных.

### Мини-задание
Возьми свою форму и сделай обязательными имя и email, добавь `minlength="2"` для имени и `pattern` для индекса. Попробуй отправить пустую и неправильную форму. Потом удали `required` через DevTools и убедись, что браузерная проверка обходится за секунду.

### На пальцах
Многие люди не пользуются мышкой: кто-то не может, кто-то просто быстрее работает с клавиатуры. Проверка клавиатурой — пройти по сайту с завязанной правой рукой: только Tab, Shift + Tab, Enter и пробел. Если где-то застрял — застрянет и реальный посетитель.

### Как это работает
- **Tab** переносит фокус на следующий интерактивный элемент: ссылку, кнопку, поле. **Shift + Tab** — назад.
- **Enter** открывает ссылку или нажимает кнопку, пробел ставит галочку и тоже нажимает кнопку.
- Фокус должен быть виден — рамка вокруг элемента. Её показывает стиль `:focus-visible`.
- Порядок фокуса идёт по порядку в HTML. Если визуально блоки переставлены через CSS, порядок Tab может стать хаотичным.

Почему элементы «не ловят» Tab:

- `div` и `span` с обработчиком клика не получают фокус, а `button` и `a` с `href` получают сами.
- Стиль `outline: none` без замены убирает рамку фокуса, и человек не видит, где находится.

Что проверить за 2 минуты:

1. Дойти Tab'ом до каждой ссылки в меню и открыть Enter.
2. Заполнить форму, не трогая мышь, и отправить.
3. Открыть и закрыть модальное окно (Esc).
4. Убедиться, что фокус всегда виден.

### Пример
```html
<!-- Плохо: на div нельзя попасть с клавиатуры -->
<div class="btn" onclick="buy()">Купить</div>

<!-- Хорошо: кнопка получает фокус и нажимается Enter и пробелом -->
<button class="btn" type="button" onclick="buy()">Купить</button>
```

```css
/* Убрал стандартную рамку — дай свою, заметную */
.btn:focus-visible {
  outline: 3px solid #1f4fd8;
  outline-offset: 2px;
}
```

### Частые ошибки
- `outline: none` для красоты — и сайт становится непроходимым с клавиатуры.
- «Кнопки» из `div`, «ссылки» из `span`.
- `tabindex="5"` и другие положительные значения — ломают естественный порядок. Используй только `0` (сделать фокусируемым) и `-1` (фокус только из кода).
