### Ситуация
Ты открываешь код сайта, который делал другой человек: сорок вложенных `div` с классами `block1`, `wrap-inner`, `bottom-part`. Где шапка? Где основное содержимое? Где меню? Приходится выяснять методом тыка. А могло бы быть написано прямо в тегах — `header`, `main`, `nav` — и всё стало бы понятно с первого взгляда.

### На пальцах
Семантические теги — подписанные комнаты в доме: прихожая, кухня, спальня. Жить можно и в доме, где на всех дверях написано «комната», но гостю — поисковику, скринридеру, новому разработчику — будет трудно понять, где что.

### Как это работает
>> `header` → `nav` → `main` (`section`, `article`) → `aside` → `footer`

| Тег | Что внутри |
|---|---|
| `header` | шапка: логотип, меню, иногда поиск |
| `nav` | навигация: главное меню, хлебные крошки |
| `main` | основное уникальное содержимое страницы, один на странице |
| `section` | смысловой раздел с заголовком: «Услуги», «Отзывы» |
| `article` | самостоятельный блок, который можно вынести отдельно: статья, карточка товара, пост |
| `aside` | второстепенное: боковая колонка, «читайте также» |
| `footer` | подвал: контакты, копирайт, ссылки |

`div` — коробка без смысла. Он нужен для оформления: сгруппировать элементы ради сетки или фона. Правило: если у блока есть смысл из таблицы — бери семантический тег; если нужна просто обёртка для CSS — `div`.

?: Если `header` и `div` выглядят на экране одинаково, кому вообще важна разница? || Скринридерам — они позволяют прыгнуть сразу к `main` или `nav`. Поисковикам — они лучше понимают, где главное содержимое. И людям — `<footer>` читается мгновенно, а `<div class="bottom-part">` надо расшифровывать.

### Пример
```html
<header>
  <a href="/" class="logo">Студия</a>
  <nav>
    <ul>
      <li><a href="#services">Услуги</a></li>
      <li><a href="#contacts">Контакты</a></li>
    </ul>
  </nav>
</header>

<main>
  <section id="services">
    <h2>Услуги</h2>
    <article>
      <h3>Лендинг под ключ</h3>
      <p>От 30 000 ₽, срок — 2 недели.</p>
    </article>
  </section>
  <aside>
    <p>Скидка 10% до конца месяца</p>
  </aside>
</main>

<footer id="contacts">
  <p>© 2026 Студия · hello@studio.ru</p>
</footer>
```

?! Карточку «Лендинг под ключ» скопировали в рассылку и в соцсети. Почему для неё выбран `article`, а не `section`? || `article` — самостоятельный блок, который имеет смысл сам по себе, вне страницы. Карточка услуги понятна и без остального сайта, поэтому это `article`. `section` — часть целого, раздел страницы.

### Частые ошибки
- **Несколько `main` на странице.** Главное содержимое одно — и `main` один.
- **`section` без заголовка.** Раздел без названия — скорее просто `div`.
- **Все `div` заменены на `section` «для семантики».** Семантика — про смысл, а не про количество модных тегов.

### Проверь себя
?? Сколько `main` может быть на странице? || Один видимый `main` — основное уникальное содержимое.
?? Когда всё-таки правильно использовать `div`? || Когда нужна обёртка только ради оформления — для сетки, фона, группировки — и у блока нет собственного смысла.
?? Объясни своими словами разницу между `section` и `article`. || `section` — тематический раздел страницы с заголовком. `article` — законченный самостоятельный кусок, который можно вынести отдельно: статья, пост, карточка.

### Мини-задание
Перепиши свою страницу «Обо мне»: `header` с меню, `main` с двумя `section` и `footer` с контактами. Открой DevTools → Elements и проверь, что по одним названиям тегов понятна структура, даже если не читать текст.

### Ситуация
Ты на телефоне заполняешь форму заказа. Поле «Телефон» открывает буквенную клавиатуру, на подпись «Email» нажимаешь — ничего не происходит, приходится целиться в маленькое поле. А после отправки выясняется, что телефон до менеджера не дошёл вовсе. Три разные ошибки, и все — в разметке формы.

### На пальцах
Форма — бланк в банке. `form` — сам лист, `input` — пустые клеточки, `label` — подписи у клеточек: «Фамилия», «Телефон». Связь подписи и поля через `for` и `id` — стрелочка от подписи к клеточке: ткнул в подпись — попал в поле.

### Как это работает
>> `label for="email"` → `input id="email"` → клик по подписи ставит фокус → `type` выбирает клавиатуру

- `form` собирает поля и отправляет их. `action` — куда отправить, `method` — как (`get` или `post`).
- `input` — поле ввода. Атрибут `type` меняет поведение и клавиатуру на телефоне.
- `name` — имя поля. Под этим именем значение уйдёт на сервер. Без `name` поле не отправится.
- `label` с `for="email"` привязывается к полю с `id="email"`. Клик по подписи ставит курсор в поле, а скринридер зачитывает подпись.

Полезные типы `input`:

| type | Что делает |
|---|---|
| `text` | обычный текст |
| `email` | проверяет наличие @, на телефоне клавиатура с @ |
| `tel` | цифровая клавиатура на телефоне |
| `password` | скрывает символы |
| `number` | число со стрелочками |
| `checkbox` | галочка «да/нет» |
| `radio` | один вариант из нескольких (одинаковый `name`) |
| `date` | выбор даты |

Второй способ связать — вложить поле в `label`: `<label>Имя <input name="name"></label>`.

?: Почему у радиокнопок одной группы обязательно одинаковый `name`? || По общему имени браузер понимает, что кнопки — одна группа, где можно выбрать только один вариант. С разными именами можно будет отметить все сразу, и на сервер уйдёт неразбериха.

### Пример
```html
<form action="/api/lead" method="post">
  <label for="name">Как вас зовут</label>
  <input id="name" name="name" type="text" autocomplete="name">

  <label for="phone">Телефон</label>
  <input id="phone" type="tel" autocomplete="tel">

  <p>Удобный способ связи:</p>
  <label><input type="radio" name="contact" value="call" checked> Звонок</label>
  <label><input type="radio" name="contact" value="tg"> Telegram</label>

  <button type="submit">Отправить заявку</button>
</form>
```

?! Пользователь ввёл имя «Анна», телефон и выбрал Telegram. Какие данные получит сервер? || `name=Анна` и `contact=tg`. Телефон не дойдёт: у его поля нет атрибута `name`. Именно такая ошибка теряет заявки на реальных сайтах.

### Частые ошибки
- **Нет `name`** — данные поля молча не доходят до сервера. Проверяй каждое поле.
- **`for` и `id` не совпадают** из-за опечатки — подпись перестаёт ставить курсор в поле.
- **Везде `type="text"`** — на телефоне неудобно вводить номер и почту, люди бросают форму.

### Проверь себя
?? Без какого атрибута значение поля не уйдёт на сервер? || Без `name`.
?? Как связать `label` с полем? Назови два способа. || Через `for` у подписи и такой же `id` у поля — или вложить поле прямо внутрь `label`.
?? Объясни своими словами, зачем указывать правильный `type` у `input`. || Он включает подходящую клавиатуру на телефоне, встроенную проверку (например, у email) и нужное поведение (скрытый пароль, выбор даты).

### Мини-задание
Сделай форму записи на консультацию: имя, email, телефон, дата, выбор тарифа радиокнопками и галочка согласия. Проверь, что клик по каждой подписи ставит курсор в нужное поле. Открой форму в режиме телефона в DevTools и посмотри, какая клавиатура предлагается для разных полей.

### Ситуация
Ты сделал в форме регистрации кнопку «Показать пароль». Пользователь нажимает её — и форма внезапно отправляется полупустой. Никакого JavaScript-бага нет: так браузер ведёт себя по умолчанию. Кнопки в формах хитрее, чем кажутся, и сейчас станет понятно почему.

### На пальцах
`input` — строчка в анкете, `textarea` — большое поле «Расскажите о себе», `select` — выпадающий список «Выберите город», `button` — кнопка «Отправить» у окошка.

### Как это работает
>> `textarea` — много текста → `select` — выбор из списка → `button` — отправить

- `textarea` — многострочный текст. Значение по умолчанию пишется между тегами, а не в атрибуте. Высоту задаёт `rows`.
- `select` — список вариантов. Каждый вариант — `option` со своим `value`. Первый пустой вариант с `disabled selected` работает как подсказка.
- `button` — кнопка. У неё важный атрибут `type`:
  - `submit` (по умолчанию внутри формы) — отправляет форму;
  - `button` — ничего не отправляет, для JavaScript;
  - `reset` — очищает форму (нужна редко).

Главное правило: кнопка — это `button`, ссылка — это `a`. Кнопка что-то делает на странице, ссылка куда-то ведёт. Не делай кнопки из `div` — их не нажать с клавиатуры.

?: Почему у кнопки внутри формы по умолчанию `type="submit"`? || Так HTML был устроен с самого начала: формы появились раньше JavaScript, и единственное, что кнопка могла делать, — отправлять. Поэтому любую «служебную» кнопку внутри формы нужно явно пометить `type="button"`.

### Пример
```html
<form>
  <label for="service">Услуга</label>
  <select id="service" name="service">
    <option value="" disabled selected>Выберите услугу</option>
    <option value="landing">Лендинг</option>
    <option value="shop">Интернет-магазин</option>
    <option value="seo">SEO-продвижение</option>
  </select>

  <label for="msg">Опишите задачу</label>
  <textarea id="msg" name="message" rows="5" maxlength="1000"></textarea>

  <button id="preview">Предпросмотр</button>
  <button type="submit">Отправить</button>
</form>
```

?! Что произойдёт при нажатии на «Предпросмотр»? || Форма отправится и страница перезагрузится: у кнопки не указан `type`, а внутри формы это значит `submit`. Чтобы кнопка только показывала предпросмотр, нужен `type="button"`.

### Частые ошибки
- **«Показать пароль» без `type="button"`** — форма отправляется при каждом нажатии.
- **Значение `textarea` в атрибуте `value`** — его там нет, текст пишется между тегами.
- **`<div onclick="…">Купить</div>`** вместо `button` — не нажимается с клавиатуры и не объявляется скринридером как кнопка.

### Проверь себя
?? Какой `type` у кнопки внутри формы по умолчанию? || `submit` — она отправляет форму.
?? Как сделать в `select` вариант-подсказку, который нельзя выбрать? || Первый `option` с пустым `value` и атрибутами `disabled selected`.
?? Объясни своими словами разницу между кнопкой и ссылкой. || Ссылка ведёт на другую страницу или адрес, кнопка выполняет действие на текущей странице: отправляет форму, открывает окно, переключает что-то.

### Мини-задание
Добавь в форму заявки `select` с тремя бюджетами, `textarea` для описания и две кнопки: «Очистить» (`type="reset"`) и «Отправить». Добавь третью кнопку без `type` и убедись, что она тоже отправляет форму. Затем почини её.

### Ситуация
Форма красивая и минималистичная: никаких подписей, только серые подсказки внутри полей. Пользователь начинает вводить телефон, отвлекается на звонок, возвращается — подсказка исчезла, и он не помнит, какое это было поле. А хакер вообще отправляет форму пустой, просто удалив одно слово в DevTools. Разберёмся, что делают `required` и `placeholder` и чего они не делают.

### На пальцах
`required` — отметка «обязательно» на бланке: сотрудник не примет его пустым. `placeholder` — бледная карандашная подсказка в клеточке: начал писать — она стёрлась. А `label` — подпись, напечатанная навсегда.

### Как это работает
>> `required` — браузер не отправит пустое → `placeholder` исчезает при вводе → подпись всегда в `label`

- `required` — браузер не отправит форму, пока поле пустое, и покажет подсказку. Для `type="email"` ещё и проверит формат.
- Другие встроенные проверки: `minlength`, `maxlength`, `min`, `max`, `pattern` (регулярное выражение).
- `placeholder` — пример формата: «+7 999 123-45-67», «anna@mail.ru».

Почему `placeholder` не заменяет `label`:

1. Он исчезает, как только человек начал печатать.
2. У него бледный цвет и плохой контраст.
3. Скринридеры часто его не зачитывают.
4. Браузерное автозаполнение может его перекрыть.

?: Если браузер уже проверяет поля, зачем ещё проверять данные на сервере? || Браузерная проверка — для удобства честного пользователя. Её отключают за секунду через DevTools или вовсе отправляют запрос без браузера. Сервер — последняя линия обороны, и он обязан проверять всё сам.

### Пример
```html
<label for="email">Email</label>
<input id="email" name="email" type="email" required placeholder="anna@mail.ru">

<label for="pass">Пароль</label>
<input id="pass" name="password" type="password" required minlength="8">

<label for="zip">Индекс</label>
<input id="zip" name="zip" inputmode="numeric" pattern="[0-9]{6}" placeholder="101000">
```

?! Пользователь ввёл email `anna`, пароль `12345` и индекс `1010`. Что сделает браузер при отправке? || Не отправит форму и подсветит первое ошибочное поле: email без @. После исправления пожалуется на пароль короче 8 символов, затем на индекс, который не совпадает с шаблоном из 6 цифр.

### Частые ошибки
- **Форма без `label`, только с `placeholder`.** Красиво на макете, мучительно в жизни.
- **Важное правило в `placeholder`** («пароль не короче 8 символов») — исчезает в момент, когда оно нужнее всего. Пиши подсказку текстом рядом с полем.
- **`required` как защита данных.** Это удобство, не безопасность.

### Проверь себя
?? Что делает атрибут `required`? || Не даёт отправить форму, пока поле пустое, и показывает подсказку.
?? Почему нельзя заменить `label` на `placeholder`? || Placeholder исчезает при вводе, плохо читается и часто не зачитывается скринридерами.
?? Объясни своими словами, почему браузерная проверка формы — не защита. || Её легко отключить или обойти, отправив запрос напрямую. Защищает только проверка на сервере.

### Мини-задание
Сделай в своей форме обязательными имя и email, добавь `minlength="2"` для имени и `pattern` для индекса. Попробуй отправить пустую и неправильную форму. Потом удали `required` через DevTools и убедись, что браузерная проверка обходится за секунду.

### Ситуация
Попробуй эксперимент: убери мышку и закажи что-нибудь на своём сайте только с клавиатуры. На многих сайтах уже на втором шаге фокус пропадает: непонятно, где ты, а «кнопка» оформления заказа не нажимается вообще. Для людей с нарушениями моторики, для слепых и для тех, кто просто любит клавиатуру, такой сайт сломан.

### На пальцах
Проверка клавиатурой — пройти по сайту с завязанной правой рукой: только Tab, Shift + Tab, Enter и пробел. Застрял ты — застрянет и реальный посетитель.

### Как это работает
>> `Tab` — следующий элемент → видна рамка фокуса → `Enter` — нажать → всё доступно без мыши

- **Tab** переносит фокус на следующий интерактивный элемент: ссылку, кнопку, поле. **Shift + Tab** — назад.
- **Enter** открывает ссылку или нажимает кнопку, пробел ставит галочку и тоже нажимает кнопку.
- Фокус должен быть виден — рамка вокруг элемента. Её показывает стиль `:focus-visible`.
- Порядок фокуса идёт по порядку в HTML. Если блоки переставлены через CSS, порядок Tab может стать хаотичным.

Почему элементы «не ловят» Tab:

- `div` и `span` с обработчиком клика не получают фокус, а `button` и `a` с `href` получают сами.
- `outline: none` без замены убирает рамку фокуса, и человек не видит, где находится.

Что проверить за 2 минуты:

1. Дойти Tab'ом до каждой ссылки меню и открыть Enter.
2. Заполнить форму, не трогая мышь, и отправить.
3. Открыть и закрыть модальное окно (Esc).
4. Убедиться, что фокус всегда виден.

?: Почему `button` работает с клавиатуры «из коробки», а `div` с `onclick` — нет? || У `button` браузер сам встроил фокус, реакцию на Enter и пробел и роль «кнопка» для скринридера. `div` — просто коробка: всё это пришлось бы дописывать вручную, и почти всегда что-то забывают.

### Пример
```html
<div class="btn" onclick="buy()">Купить</div>
<button class="btn" type="button" onclick="buy()">Купить</button>
```

```css
.btn:focus-visible {
  outline: 3px solid #1f4fd8;
  outline-offset: 2px;
}
```

?! Пользователь нажимает Tab, начиная с адресной строки. На какой из двух «кнопок» остановится фокус и что произойдёт при Enter? || Фокус пропустит `div` и остановится только на `button`. Enter вызовет `buy()` и подсветит кнопку синей рамкой благодаря `:focus-visible`. До `div` с клавиатуры не добраться.

### Частые ошибки
- **`outline: none` для красоты** — сайт становится непроходимым с клавиатуры. Убрал стандартную рамку — дай свою, заметную.
- **«Кнопки» из `div`, «ссылки» из `span`.** Используй настоящие `button` и `a`.
- **`tabindex="5"`** и другие положительные значения ломают естественный порядок. Используй только `0` (сделать фокусируемым) и `-1` (фокус только из кода).

### Проверь себя
?? Какие клавиши нужны, чтобы пройти сайт без мыши? || Tab и Shift + Tab для перемещения, Enter и пробел для нажатия, Esc для закрытия окон.
?? Чем опасен стиль `outline: none`? || Пропадает видимая рамка фокуса, и человек с клавиатурой не понимает, где находится.
?? Объясни своими словами, почему кнопку нужно делать из `button`, а не из `div`. || `button` сама получает фокус, нажимается с клавиатуры и объявляется скринридером как кнопка. `div` ничего этого не умеет.
