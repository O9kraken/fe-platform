### На пальцах
Grid — разлинованный лист в клетку. Ты заранее говоришь: «на листе три колонки, между ними промежуток 20 мм», и элементы сами раскладываются по клеткам. Flex — это одна полка, grid — целый стеллаж с рядами и колонками.

### Как это работает
- `display: grid` — на родителя.
- `grid-template-columns` — сколько колонок и какой ширины.
- `fr` — доля свободного места. `1fr 1fr 1fr` — три равные колонки, `2fr 1fr` — левая в два раза шире правой.
- `gap` — промежуток между рядами и колонками. `gap: 24px 16px` — между рядами 24, между колонками 16.
- Можно смешивать единицы: `250px 1fr` — фиксированная боковая колонка и резиновая основная.
- `repeat(4, 1fr)` — короткая запись для `1fr 1fr 1fr 1fr`.

Ряды создаются автоматически: если колонок три, а элементов семь — получится три ряда.

Элемент можно растянуть на несколько колонок: `grid-column: span 2`.

Когда что выбирать: flex — для ряда элементов в одну линию (меню, кнопки, шапка), grid — для двумерной сетки (каталог, галерея, раскладка страницы).

### Пример
```css
.catalog {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}

.catalog .card--wide {
  grid-column: span 2;
}

.layout {
  display: grid;
  grid-template-columns: 260px 1fr;
  gap: 32px;
}
```

### Частые ошибки
- Писать `display: grid` на каждом элементе вместо родителя.
- Задавать колонкам ширину в `%` вместе с `gap` — сумма вылезает за 100%. С `fr` такого не бывает.
- Делать сетку карточек через flex с шириной `33.33%` и мучиться с отступами.

### На пальцах
Это заклинание говорит сетке: «Сама посчитай, сколько колонок влезает. Каждая не уже 240 пикселей, а остаток места подели поровну». На широком экране получится четыре колонки, на планшете — две, на телефоне — одна. И ни одного медиазапроса.

### Как это работает
Разберём по кусочкам `repeat(auto-fit, minmax(240px, 1fr))`:

- `minmax(240px, 1fr)` — ширина колонки: минимум 240px, максимум — равная доля свободного места.
- `repeat(auto-fit, ...)` — повторить столько раз, сколько влезет в ширину контейнера.

Пример: контейнер 1000px, gap 20px. Влезает 3 колонки по 240+ (3 × 240 + 2 × 20 = 760), а четыре — уже нет (4 × 240 + 3 × 20 = 1020). Значит три колонки, и каждая растягивается до ~320px.

`auto-fit` и `auto-fill` отличаются, когда элементов мало. `auto-fit` растягивает имеющиеся элементы на всю ширину, `auto-fill` оставляет пустые «призрачные» колонки. Для карточек обычно нужен `auto-fit`.

Чтобы на очень узком экране (уже 240px) колонка не вылезала, используют `minmax(min(240px, 100%), 1fr)`.

### Пример
```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(240px, 100%), 1fr));
  gap: 20px;
}
```

```html
<div class="cards">
  <article class="card">Лендинг</article>
  <article class="card">Магазин</article>
  <article class="card">SEO</article>
  <article class="card">Поддержка</article>
</div>
```

Потяни край окна браузера — колонки будут перестраиваться сами.

### Частые ошибки
- Слишком большой минимум (например, 400px) — на телефоне карточка не влезет.
- Ждать, что при одном элементе будет одна колонка 240px. С `auto-fit` она растянется на всю ширину. Если нужно иначе — используй `auto-fill`.
- Добавлять медиазапросы поверх этой конструкции «на всякий случай».

### На пальцах
`grid-template-areas` — план квартиры, нарисованный словами. Ты буквально рисуешь: «вверху прихожая во всю ширину, ниже слева кухня, справа гостиная, внизу балкон». И раскладываешь мебель по названиям комнат.

### Как это работает
1. У контейнера в `grid-template-areas` пишешь строки-«картинку». Каждая строка в кавычках — ряд, каждое слово — ячейка.
2. Одинаковое имя в соседних ячейках объединяет их в одну область.
3. Точка `.` — пустая ячейка.
4. Каждому элементу назначаешь область через `grid-area: имя`.

Огромный плюс: для мобильной версии достаточно перерисовать «картинку» в медиазапросе — HTML менять не нужно.

### Пример
```css
.page {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
  gap: 16px;
  min-height: 100vh;
}

.page > header { grid-area: header; }
.page > aside  { grid-area: aside; }
.page > main   { grid-area: main; }
.page > footer { grid-area: footer; }

@media (max-width: 700px) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "main"
      "aside"
      "footer";
  }
}
```

### Частые ошибки
- Область не прямоугольная (буквой Г) — браузер проигнорирует всю раскладку.
- Разное количество слов в строках.
- Опечатка в имени: `grid-area: hedaer` — элемент встанет в первую свободную ячейку.

### На пальцах
Mobile-first — собирать чемодан, начиная с самого необходимого. Сначала делаешь сайт для маленького экрана телефона: одна колонка, крупные кнопки. Потом для больших экранов добавляешь: «а здесь можно две колонки», «а здесь меню в строку». Так проще, чем впихивать огромный сайт в маленький экран.

### Как это работает
Медиазапрос — условие «применить эти стили, только если...»:

```css
@media (min-width: 768px) {
  /* стили для экранов от 768px и шире */
}
```

- `min-width` — «от и больше» — основа подхода mobile-first.
- `max-width` — «до и меньше» — подход desktop-first.

Типичные точки перелома: 640px (большой телефон), 768px (планшет), 1024px (ноутбук), 1280px (десктоп). Но лучше ставить точку там, где ломается твой дизайн, а не по таблице.

Обязательная строка в HTML, без неё медиазапросы на телефоне не сработают:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

### Пример
```css
/* База — телефон */
.services {
  display: grid;
  gap: 16px;
}
.menu { display: none; }
.burger { display: block; }

/* Планшет */
@media (min-width: 768px) {
  .services { grid-template-columns: 1fr 1fr; }
}

/* Ноутбук и больше */
@media (min-width: 1024px) {
  .services { grid-template-columns: repeat(3, 1fr); }
  .menu { display: flex; gap: 24px; }
  .burger { display: none; }
}
```

### Частые ошибки
- Забыть `meta viewport` — телефон покажет уменьшенную десктопную версию.
- Смешивать `min-width` и `max-width` хаотично — стили начинают спорить.
- Проверять адаптив только сужением окна. Открывай режим устройства в DevTools (Ctrl + Shift + M) и реальный телефон.

### Мини-задание
Перепиши блок услуг своей страницы по mobile-first: одна колонка на телефоне, две на планшете, три на ноутбуке. Проверь в DevTools на ширинах 375, 768 и 1280px.

### На пальцах
Адаптивная картинка — фотография в рамке с паспарту: сколько бы ни менялась рамка, фото подстраивается и не вылезает за край. `:focus-visible` — подсветка, которая загорается только у тех, кто ходит по сайту с клавиатуры, и не мешает тем, кто кликает мышкой.

### Как это работает
Картинки:

- `max-width: 100%; height: auto` — картинка никогда не шире контейнера и сохраняет пропорции.
- `width` и `height` в HTML — браузер заранее резервирует место, и страница не «прыгает» при загрузке.
- `object-fit: cover` — заполнить блок фиксированного размера без искажений (лишнее обрежется).
- `srcset` и `sizes` — несколько размеров одной картинки, браузер сам выберет подходящий для экрана.
- `loading="lazy"` — грузить картинку, только когда до неё долистали.

Фокус:

- `:focus` срабатывает и при клике мышью, поэтому раньше рамку часто убирали.
- `:focus-visible` срабатывает, когда браузер понимает, что человек работает с клавиатуры. Стилизуй его — и красиво, и доступно.

### Пример
```css
img {
  max-width: 100%;
  height: auto;
  display: block;
}

.card__photo {
  width: 100%;
  aspect-ratio: 4 / 3;
  object-fit: cover;
  border-radius: 12px;
}

a:focus-visible,
button:focus-visible {
  outline: 3px solid #1f4fd8;
  outline-offset: 3px;
}
```

```html
<img
  src="img/office-800.jpg"
  srcset="img/office-400.jpg 400w, img/office-800.jpg 800w, img/office-1600.jpg 1600w"
  sizes="(min-width: 1024px) 50vw, 100vw"
  width="800" height="600"
  alt="Офис студии: открытое пространство с большими окнами"
  loading="lazy">
```

### Частые ошибки
- Фото 4000×3000 на 5 МБ для карточки шириной 300px.
- Картинки без `width` и `height` — текст скачет при загрузке.
- `outline: none` без замены на `:focus-visible`.
