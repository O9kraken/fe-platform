### Ситуация
Твой лендинг на React почти не находят в поиске: робот приходит, видит пустой `div#root` и уходит. Для каждой страницы приходится вручную расписывать маршруты в роутере, а SEO-мета-теги прикручивать сторонними библиотеками. Next.js решает это из коробки — и именно поэтому его так часто требуют в вакансиях фронтенда.

### На пальцах
В React Router ты вручную пишешь таблицу «адрес → страница». В Next.js таблица — сама структура папок. Создал папку `app/about` с файлом `page.tsx` — появился адрес `/about`. Как в шкафу с подписанными ящиками: где лежит, там и находится.

### Как это работает
1. `npx create-next-app@latest my-site` — мастер спросит про TypeScript, ESLint, Tailwind, App Router (выбирай Yes).
2. `npm run dev` → `http://localhost:3000`.

Правила App Router:

- Папка внутри `app` — сегмент адреса.
- Страница появляется, только если в папке есть файл `page.tsx`.
- Вложенные папки — вложенные адреса.
- Папка в круглых скобках `(marketing)` группирует файлы, но не попадает в адрес.
- Папка с подчёркиванием `_components` — приватная, не становится маршрутом.

| Файл | Адрес |
|---|---|
| `app/page.tsx` | `/` |
| `app/about/page.tsx` | `/about` |
| `app/blog/[slug]/page.tsx` | `/blog/что-угодно` |
| `app/(shop)/cart/page.tsx` | `/cart` |

Переходы — компонентом `Link` из `next/link`. Next.js заранее подгружает страницы по ссылкам, которые видны на экране, поэтому переходы мгновенные.

?: Почему адрес появляется только при наличии файла `page.tsx`, а не просто от папки? || Рядом со страницей в папке могут лежать компоненты, стили, утилиты. Если бы любой файл становился маршрутом, наружу торчали бы служебные куски. Явный `page.tsx` говорит: «вот это — страница».

### Пример
```text
app/
├── page.tsx
├── services/
│   ├── page.tsx
│   └── ServiceCard.tsx
├── (legal)/
│   └── privacy/page.tsx
└── _components/
    └── Header.tsx
```

?! Какие адреса будут доступны на сайте? || Три: `/`, `/services` и `/privacy`. `ServiceCard.tsx` — не страница, папка `(legal)` в адрес не попадает, а `_components` приватная.

### Частые ошибки
- **`app/about/about.tsx`** вместо `page.tsx` — адреса не будет.
- **`<a href>` для внутренних ссылок** — пропадает мгновенный переход.
- **Путаница App Router (`app/`) и старого Pages Router (`pages/`)** из старых статей.

### Проверь себя
?? Как в App Router создать страницу по адресу `/contacts`? || Создать файл `app/contacts/page.tsx` с компонентом по умолчанию.
?? Что делают папки в круглых скобках, например `(shop)`? || Группируют файлы для удобства, но не добавляют сегмент в адрес.
?? Объясни своими словами, чем роутинг в Next.js отличается от React Router. || В React Router маршруты описывают вручную в коде. В Next.js их задаёт структура папок: папка с `page.tsx` автоматически становится адресом.

### Ситуация
Блог грузит статьи пару секунд, и всё это время пользователь смотрит на пустое место. Если база упала — вся страница превращается в белый экран с технической ошибкой. Неизвестный адрес показывает некрасивую стандартную страницу. В Next.js для каждой такой ситуации есть специальный файл — достаточно положить его в папку.

### На пальцах
У каждой папки-маршрута может быть набор служебных файлов, как у квартиры: сама комната (`page`), общая прихожая для всех комнат этажа (`layout`), табличка «идёт уборка, подождите» (`loading`), табличка «прорвало трубу» (`error`) и «такой квартиры нет» (`not-found`). Next.js сам вешает нужную табличку в нужный момент.

### Как это работает
| Файл | Назначение |
|---|---|
| `page.tsx` | содержимое страницы |
| `layout.tsx` | общая обёртка для страницы и всех вложенных; не перерисовывается при переходах |
| `loading.tsx` | показывается, пока страница загружает данные |
| `error.tsx` | показывается, если при отрисовке произошла ошибка; клиентский компонент |
| `not-found.tsx` | показывается при вызове `notFound()` или для несуществующего адреса |

- Корневой `app/layout.tsx` обязателен: в нём `<html>` и `<body>`.
- Layout'ы вкладываются: корневой → `app/blog/layout.tsx` → страница.
- `error.tsx` получает `error` и функцию `reset` для повторной попытки.

?: Почему `error.tsx` обязательно клиентский компонент? || Ему нужна интерактивность: кнопка «Попробовать снова» вызывает `reset` прямо в браузере. Кроме того, ошибка может случиться и при работе в браузере, и перехватывать её нужно там же.

### Пример
```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>
        <header>Студия</header>
        {children}
        <footer>© 2026</footer>
      </body>
    </html>
  );
}

// app/blog/error.tsx
export default function Error({ reset }: { error: Error; reset: () => void }) {
  return <button onClick={reset}>Попробовать снова</button>;
}
```

?! Что не так с файлом `error.tsx`? || Не хватает строки `"use client"` в самом начале. Без неё Next.js выдаст ошибку: обработчик `onClick` и сама граница ошибки работают только в клиентском компоненте.

### Частые ошибки
- **Нет `"use client"` в `error.tsx`** — Next.js выдаст ошибку.
- **Шапка в каждой странице** вместо layout.
- **Удалены `<html>` и `<body>`** из корневого layout.

### Проверь себя
?? Какой файл показывается, пока страница загружает данные? || `loading.tsx`.
?? Что обязательно должно быть в корневом `app/layout.tsx`? || Теги `<html>` и `<body>`, внутри которых выводится `children`.
?? Объясни своими словами, зачем нужны файлы `loading`, `error` и `not-found`. || Чтобы для каждой «нестандартной» ситуации — ожидания, сбоя и отсутствия страницы — пользователь видел понятный интерфейс, а не пустоту или технический текст.

### Ситуация
У блога сто статей. Создавать сто папок — абсурд. Нужна одна страница-шаблон, которая по адресу `/blog/kak-vybrat-hosting` понимает, какую статью показать. А если кто-то откроет `/blog/nesushchestvuyushchaya`, вместо падения сервера должна появиться аккуратная 404 с правильным кодом для поисковиков.

### На пальцах
Папка с названием в квадратных скобках — пустая рамка для фотографии. `app/blog/[slug]` — «здесь будет любая статья». Адрес `/blog/kak-vybrat-hosting` вставляет в рамку слово `kak-vybrat-hosting`, и страница по нему находит нужную статью.

### Как это работает
- `[slug]` — один сегмент адреса, приходит в `params.slug`.
- `[...slug]` — любое количество сегментов (`/docs/a/b/c`), приходит массивом.
- `[[...slug]]` — то же, но адрес без сегментов тоже подходит.
- Страница получает `params` в props. В свежих версиях Next.js это промис: `const { slug } = await params`.
- Не нашли данные — вызови `notFound()`, и Next.js покажет `not-found.tsx` с кодом 404.

Slug — человекочитаемый идентификатор в адресе: латиница, цифры, дефисы.

?: Почему для статей slug лучше, чем числовой id? || Адрес `/blog/kak-vybrat-hosting` понятен человеку ещё до клика и содержит ключевые слова, которые учитывают поисковики. `/blog/42` ничего не говорит ни людям, ни поиску.

### Пример
```tsx
// app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";

const POSTS = [
  { slug: "kak-vybrat-hosting", title: "Как выбрать хостинг" },
  { slug: "chto-takoe-seo", title: "Что такое SEO" },
];

export default async function PostPage({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const post = POSTS.find(p => p.slug === slug);
  if (!post) notFound();
  return <h1>{post.title}</h1>;
}
```

?! Что увидит пользователь по адресу `/blog/chto-takoe-seo`, а что — по `/blog/react`? || По первому — заголовок «Что такое SEO». По второму — страницу `not-found.tsx` с кодом ответа 404: статьи с таким slug нет, и `notFound()` прерывает отрисовку.

### Частые ошибки
- **Папка `blog/slug` без скобок** — получится буквальный адрес `/blog/slug`.
- **Нет обработки несуществующего slug** — страница падает с ошибкой вместо 404.
- **Русские буквы и пробелы в slug** — адрес превращается в `%D0%BA%D0%B0...`.

### Проверь себя
?? Как назвать папку для динамического сегмента адреса? || В квадратных скобках, например `[slug]` или `[id]`.
?? Что делает функция `notFound()`? || Прерывает отрисовку страницы и показывает `not-found.tsx` с кодом ответа 404.
?? Объясни своими словами разницу между `[slug]` и `[...slug]`. || `[slug]` ловит ровно один сегмент адреса. `[...slug]` — любое количество сегментов, которые приходят массивом.

### Мини-задание
Сделай блог из трёх статей: список на `/blog` и страницу статьи на `/blog/[slug]` с вызовом `notFound()` для неизвестного адреса. Добавь страницу документации на `[...slug]`, которая выводит все сегменты адреса.

### Ситуация
Ты переносишь компонент из обычного React в Next.js — и получаешь ошибку «useState only works in Client Components». В другом месте ключ API случайно уехал в браузер, и любой может найти его в исходниках. Next.js разделяет компоненты на два мира, и это главная новая идея, которую нужно понять.

### На пальцах
Ресторан с открытой кухней. Серверные компоненты — повара на кухне: готовят блюдо (HTML) заранее, у них есть доступ к холодильнику (базе данных) и секретным рецептам (ключам API). Клиентские компоненты — официант у столика: реагирует на просьбы гостя прямо сейчас — нажатия, ввод, анимации.

### Как это работает
В App Router все компоненты по умолчанию **серверные**:

- выполняются на сервере, в браузер приходит готовый HTML;
- их код не попадает в JS-бандл браузера — страница легче;
- могут быть `async` и прямо внутри загружать данные, обращаться к базе, читать секретные переменные окружения;
- **не могут** использовать `useState`, `useEffect`, обработчики событий и браузерные API (`window`, `localStorage`).

**Клиентские** компоненты помечаются строкой `"use client"` в начале файла:

- работают как обычный React: состояние, эффекты, события;
- сначала рисуются на сервере (для быстрого первого показа), потом «оживают» в браузере.

Правило: держи как можно больше на сервере, а клиентскими делай только интерактивные «островки». Серверный компонент может импортировать клиентский и передавать ему данные через props.

?: Почему в серверном компоненте можно безопасно использовать секретный ключ API? || Его код выполняется только на сервере и не попадает в браузер. Пользователь получает лишь готовый HTML-результат, а сам ключ и логика запроса остаются на кухне.

### Пример
```tsx
// app/products/page.tsx
import { AddToCart } from "./AddToCart";

export default async function ProductsPage() {
  const r = await fetch("https://dummyjson.com/products?limit=5");
  const { products } = await r.json();
  return (
    <ul>
      {products.map((p: { id: number; title: string }) => (
        <li key={p.id}>{p.title} <AddToCart id={p.id} /></li>
      ))}
    </ul>
  );
}

// app/products/AddToCart.tsx
"use client";
import { useState } from "react";
export function AddToCart({ id }: { id: number }) {
  const [added, setAdded] = useState(false);
  return <button onClick={() => setAdded(true)}>{added ? "В корзине" : "Купить"}</button>;
}
```

?! Какой код из этих двух файлов попадёт в JavaScript браузера и где выполнится `fetch` к dummyjson? || В браузер попадёт только `AddToCart` с `useState`. `fetch` выполнится на сервере, а браузер получит уже готовый HTML со списком товаров.

### Частые ошибки
- **`useState` в серверном компоненте** — ошибка «useState only works in Client Components».
- **`"use client"` на весь layout** — вся страница уходит в браузерный бандл.
- **Функция или объект с методами из серверного компонента в клиентский** — props должны быть сериализуемыми (числа, строки, обычные объекты).

### Проверь себя
?? Какие компоненты в App Router по умолчанию: серверные или клиентские? || Серверные.
?? Что нельзя делать в серверном компоненте? || Использовать состояние, эффекты, обработчики событий и браузерные API вроде `window` и `localStorage`.
?? Объясни своими словами, почему выгодно держать большую часть компонентов серверными. || Их код не попадает в браузер, страница грузится быстрее, данные загружаются прямо на сервере, а секреты не утекают. Интерактивность добавляется точечно маленькими клиентскими компонентами.

### Ситуация
Чтобы кнопка темы заработала, ты пишешь `"use client"` в начале `Header`. Работает! Потом в `Layout`, потом во всех страницах — «чтобы ошибки не было». Через месяц сайт весит как обычное React-приложение, и все преимущества Next.js потеряны. Где ставить эту директиву — один из самых частых вопросов на собеседованиях по Next.js.

### На пальцах
`"use client"` — табличка на двери: «отсюда начинается зал, где работают с гостями». Всё, что за этой дверью, должно уметь общаться с посетителем в браузере. Вешай табличку только там, где реально нужен разговор с гостем, а не на входе во весь ресторан.

### Как это работает
`"use client"` нужна, если компонент использует хоть что-то из списка:

- состояние и эффекты: `useState`, `useReducer`, `useEffect`, `useRef`;
- обработчики событий: `onClick`, `onChange`, `onSubmit`;
- браузерные API: `window`, `document`, `localStorage`, геолокация;
- контексты и хуки браузерных библиотек (TanStack Query, Zustand, слайдеры, карты).

Не нужна, если компонент просто показывает данные, даже очень сложную разметку.

Как работает граница:

- Директива пишется в первой строке файла.
- Всё, что этот файл импортирует, тоже становится клиентским.
- Поэтому директиву ставят как можно ниже по дереву — на маленьком интерактивном компоненте.
- Серверный компонент можно передать в клиентский через `children` — тогда он останется серверным.

?: Почему серверный компонент, переданный в клиентский через `children`, остаётся серверным? || Клиентский компонент не импортирует его, а получает уже готовый результат отрисовки. Сервер заранее превращает `children` в разметку, и в браузер его код не попадает.

### Пример
```tsx
// app/_components/Header.tsx
import { ThemeToggle } from "./ThemeToggle";
import { Logo } from "./Logo";

export function Header() {
  return (
    <header>
      <Logo />
      <nav>...</nav>
      <ThemeToggle />
    </header>
  );
}

// app/_components/ThemeToggle.tsx
"use client";
import { useState } from "react";
export function ThemeToggle() {
  const [dark, setDark] = useState(false);
  return <button onClick={() => setDark(!dark)}>{dark ? "Светлая" : "Тёмная"}</button>;
}
```

?! Какие из трёх компонентов — `Header`, `Logo`, `ThemeToggle` — окажутся в браузерном бандле? А если перенести `"use client"` в `Header`? || Сейчас — только `ThemeToggle`. Если директиву поставить в `Header`, клиентскими станут все три: файл с директивой и всё, что он импортирует.

### Частые ошибки
- **`"use client"` во всех файлах «чтобы работало».**
- **Директива не в первой строке** (после импортов) — она не сработает.
- **Секретная переменная окружения в клиентском компоненте** — её там нет, и это правильно.

### Проверь себя
?? Где в файле пишется директива `"use client"`? || Самой первой строкой, до импортов.
?? Что происходит с компонентами, которые импортирует файл с `"use client"`? || Они тоже становятся клиентскими и попадают в браузерный бандл.
?? Объясни своими словами, куда правильно ставить `"use client"`. || Как можно ниже по дереву — на маленький компонент, которому действительно нужны состояние, события или браузерные API, а остальное оставить серверным.
