### Ситуация
Твоё React-приложение — одна страница. Пользователь открыл корзину, нажал «Назад» в браузере — и вылетел с сайта совсем. Хочет отправить другу ссылку на каталог — а ссылка всегда ведёт на главную. Приложению нужны адреса, история и кнопка «Назад», но без перезагрузки страницы. Это работа роутера.

### На пальцах
Одностраничное приложение — дом, в котором комнаты меняются без выхода на улицу. Роутер — указатель на стене: адрес `/catalog` — показываем каталог, `/cart` — корзину. `Link` — дверь между комнатами, которая не заставляет заново строить весь дом. `NavLink` — дверь с подсветкой «вы здесь».

### Как это работает
>> `<Route path="/about">` → `<Link to="/about">` → адрес меняется без перезагрузки

1. `npm install react-router-dom`
2. Описываешь маршруты: какой компонент показывать по какому адресу.
3. Оборачиваешь приложение в роутер.
4. Для переходов используешь `Link` вместо `a`.

`NavLink` автоматически получает класс `active` (или функцию в `className`), когда его адрес совпадает с текущим. Удобно для меню.

Перейти из кода (например, после отправки формы): `const navigate = useNavigate(); navigate("/thanks")`.

?: Чем `Link` лучше обычной ссылки `<a href>` внутри приложения? || `<a>` заставляет браузер заново загрузить всю страницу: всё мигает, а состояние — корзина, введённый текст — теряется. `Link` меняет адрес и подменяет нужный кусок интерфейса мгновенно, а кнопка «Назад» продолжает работать.

### Пример
```tsx
import { createBrowserRouter, RouterProvider, NavLink } from "react-router-dom";

const router = createBrowserRouter([
  { path: "/", element: <Home /> },
  { path: "/catalog", element: <Catalog /> },
  { path: "/cart", element: <Cart /> },
]);

export function Menu() {
  const cls = ({ isActive }: { isActive: boolean }) => (isActive ? "is-active" : "");
  return (
    <nav>
      <NavLink to="/" className={cls}>Главная</NavLink>
      <NavLink to="/catalog" className={cls}>Каталог</NavLink>
    </nav>
  );
}
```

?! Пользователь на странице `/catalog`. Какие пункты меню будут подсвечены? || Оба: и «Каталог», и «Главная». Адрес `/catalog` начинается с `/`, и без атрибута `end` ссылка на главную тоже считается активной. Нужно `<NavLink to="/" end>`.

### Частые ошибки
- **`<a href="/catalog">` внутри приложения** — полная перезагрузка и потеря состояния.
- **`NavLink to="/"` без `end`** подсвечивается на всех страницах.
- **404 при прямом переходе на `/catalog` после деплоя.** Хостингу нужно сказать отдавать `index.html` на все адреса (на Netlify — файл `_redirects`, на Vercel для Vite работает само).

### Проверь себя
?? Как перейти на другую страницу из кода, например после отправки формы? || Через `useNavigate`: `const navigate = useNavigate(); navigate("/thanks")`.
?? Зачем у ссылки на главную атрибут `end`? || Чтобы она считалась активной только на точном адресе `/`, а не на всех адресах, начинающихся с `/`.
?? Объясни своими словами, что делает роутер в одностраничном приложении. || Связывает адреса с компонентами: меняет адрес в строке браузера и показывает нужную «страницу» без перезагрузки, сохраняя историю и работу кнопки «Назад».

### Ситуация
В каталоге 500 товаров, и у каждого должна быть своя страница с адресом, которым можно поделиться. Делать 500 маршрутов? Конечно, нет. А ещё пользователь включил фильтр «до 5000 ₽, сортировка по цене», обновил страницу — и фильтры сбросились. Адрес умеет хранить гораздо больше, чем кажется.

### На пальцах
Нельзя сделать отдельную страницу для каждого из тысячи товаров. Делают одну страницу-шаблон с «окошком» в адресе: `/product/:id`. Адрес `/product/42` — окошко заполнено числом 42. `useParams` — посмотреть, что написано в окошке, и показать нужный товар.

### Как это работает
>> `/products/:id` → `useParams()` → `id` → загрузить товар

- В маршруте параметр обозначается двоеточием: `path: "/product/:id"`.
- `useParams()` возвращает объект параметров: `{ id: "42" }`.
- Параметры всегда строки. Для поиска по числовому id преобразуй: `Number(id)`.
- Параметров может быть несколько: `/blog/:category/:slug`.
- Ссылки на такие страницы строят шаблонной строкой: `` <Link to={`/product/${p.id}`}> ``.

Query-параметры (после `?`) читают хуком `useSearchParams()`. Их используют для фильтров и поиска: `/catalog?sort=price&page=2`.

?: Почему фильтры каталога лучше хранить в адресе, а не в `useState`? || Состояние пропадает при обновлении страницы, и ссылкой на отфильтрованный каталог нельзя поделиться. Параметры в адресе переживают перезагрузку, работают с кнопкой «Назад» и отправляются другу вместе со ссылкой.

### Пример
```tsx
const PRODUCTS = [
  { id: 1, title: "Кроссовки", price: 5990 },
  { id: 2, title: "Куртка", price: 8990 },
];

export function ProductPage() {
  const { id } = useParams();
  const product = PRODUCTS.find(p => p.id === id);

  if (!product) return <p>Товар не найден.</p>;
  return <h1>{product.title}</h1>;
}
```

?! Пользователь открыл `/product/1`. Что он увидит? || «Товар не найден». `id` из адреса — строка `"1"`, а в данных — число `1`, и строгое сравнение никогда не совпадёт. Нужно `p.id === Number(id)`.

### Частые ошибки
- **`p.id === id`** — число со строкой никогда не равны.
- **Нет обработки «не найдено»** — компонент падает на `product.title`.
- **Фильтры только в состоянии** — пропадают при обновлении, ссылкой не поделиться.

### Проверь себя
?? Какого типа значения возвращает `useParams`? || Всегда строки.
?? Как прочитать параметр `sort` из адреса `/catalog?sort=price`? || Через `useSearchParams`: `const [params] = useSearchParams(); params.get("sort")`.
?? Объясни своими словами, чем параметр пути `/product/:id` отличается от query-параметра `?sort=price`. || Параметр пути указывает, какой именно ресурс показать, и обязателен для маршрута. Query-параметры — необязательные уточнения вроде фильтров, сортировки и страницы.

### Мини-задание
Сделай каталог из 5 товаров со ссылками на страницу товара `/product/:id`. На странице товара — кнопка «Назад в каталог» и сообщение для несуществующего id. Добавь в каталог фильтр по категории через query-параметр.

### Ситуация
У тебя десять страниц, и в каждую скопированы одна и та же шапка, меню и подвал. Поменять пункт меню — значит поправить десять файлов. А пользователь начинает вводить запрос в поиске в шапке, переходит на другую страницу — и поле очищается, потому что шапка нарисовалась заново. Общие части интерфейса выносят в layout.

### На пальцах
В торговом центре на каждом этаже одинаковые эскалаторы, указатели и туалеты, а меняются только магазины. Layout — общая «оболочка этажа»: шапка, меню, подвал. `<Outlet />` — место для «магазина», который меняется в зависимости от адреса.

### Как это работает
>> `<Layout>` с шапкой → `<Outlet />` → дочерние страницы меняются внутри

- Родительский маршрут рисует layout, дочерние — содержимое внутри него.
- В layout-компоненте ставишь `<Outlet />` — туда подставится текущая дочерняя страница.
- Пути дочерних маршрутов пишут относительно родителя: `"catalog"`, а не `"/catalog"`.
- `index: true` — страница по умолчанию для адреса родителя.
- Вложенность можно продолжать: «Личный кабинет» со своим боковым меню внутри общего layout.

?: Почему состояние в шапке сохраняется при переходах между страницами внутри layout? || Layout рисуется один раз и не перемонтируется: при переходе React меняет только то, что внутри `<Outlet />`. Шапка остаётся тем же самым компонентом со своим состоянием.

### Пример
```tsx
function RootLayout() {
  return (
    <>
      <header>Шапка магазина</header>
      <main><Outlet /></main>
      <footer>© 2026 Магазин</footer>
    </>
  );
}

export const router = createBrowserRouter([
  {
    path: "/",
    element: <RootLayout />,
    children: [
      { index: true, element: <Home /> },
      { path: "catalog", element: <Catalog /> },
    ],
  },
]);
```

?! Что окажется внутри `<main>` по адресу `/` и по адресу `/catalog`? А что будет по `/cart`? || По `/` — `Home` (это `index`). По `/catalog` — `Catalog`. Шапка и подвал общие на обоих адресах. Для `/cart` маршрута нет — без маршрута `*` или `errorElement` пользователь увидит стандартную ошибку роутера.

### Частые ошибки
- **Забыт `<Outlet />`** в layout — дочерние страницы не появятся.
- **Дочерние пути с ведущей косой чертой** — они становятся абсолютными.
- **Копии шапки и подвала в каждой странице** вместо общего layout.

### Проверь себя
?? Что делает компонент `<Outlet />`? || Показывает внутри layout текущую дочернюю страницу, выбранную по адресу.
?? Что означает `index: true` у дочернего маршрута? || Это страница по умолчанию, которая показывается по адресу самого родителя.
?? Объясни своими словами, зачем нужен layout в роутере. || Чтобы описать общие части интерфейса — шапку, меню, подвал — один раз, а менять при переходах только содержимое в центре.

### Мини-задание
Сделай приложение с общим layout (шапка, подвал) и разделом «Кабинет» со своим боковым меню и двумя вложенными страницами. Убедись, что шапка не перерисовывается при переходах.

### Ситуация
Пользователь перешёл по старой ссылке из письма, ошибся буквой в адресе или открыл удалённый товар. Без специальной страницы он видит пустой белый экран — и уходит, решив, что сайт сломан. Хорошая страница 404 возвращает его обратно на сайт за один клик. На этой платформе она тоже есть — попробуй открыть любой несуществующий адрес.

### На пальцах
Страница 404 — вежливый администратор у двери, за которой ничего нет: «Такой комнаты у нас нет, но вот карта здания и выход на главную». Без него посетитель видит пустую стену и уходит.

### Как это работает
>> `path="*"` → ни один маршрут не подошёл → своя страница 404

- Маршрут `path: "*"` ловит любой адрес, который не совпал с другими. Его ставят последним среди дочерних маршрутов, чтобы он показывался внутри общего layout.
- В `createBrowserRouter` есть ещё `errorElement` — его показывают, когда при загрузке страницы произошла ошибка или маршрут не найден.
- Для «не найдено» на уровне данных (товар с несуществующим id) показывай такое же дружелюбное сообщение внутри страницы.

Что должно быть на хорошей странице 404:

- понятный заголовок «Страница не найдена»;
- короткое объяснение: возможно, ссылка устарела или в адресе опечатка;
- ссылка на главную и, если есть, поиск или популярные разделы;
- общий дизайн сайта — шапка и подвал на месте.

?: Почему маршрут `*` кладут внутрь общего layout, а не отдельно? || Тогда на странице 404 остаются шапка, меню и подвал. Пользователь не чувствует, что попал в тупик, и может сразу перейти в нужный раздел.

### Пример
```tsx
import { Link, useLocation } from "react-router-dom";

export function NotFound() {
  const { pathname } = useLocation();
  return (
    <section>
      <h1>Страница не найдена</h1>
      <p>По адресу <code>{pathname}</code> ничего нет.</p>
      <Link to="/">На главную</Link>
    </section>
  );
}

// children: [
//   { path: "*", element: <NotFound /> },
//   { index: true, element: <Home /> },
//   { path: "catalog", element: <Catalog /> },
// ]
```

?! Маршруты описаны в таком порядке. Что увидит пользователь по адресу `/catalog`? || Каталог. React Router выбирает самый конкретный подходящий маршрут, а не первый по порядку, поэтому `*` сработает только для неизвестных адресов. Тем не менее `*` принято ставить последним — так читать проще.

### Частые ошибки
- **Нет маршрута `*`** — пользователь видит пустой экран.
- **404-страница без шапки и ссылок** — тупик.
- **Только клиентский 404.** Сервер тоже должен отдавать свою страницу и код 404 для неизвестных адресов, иначе поисковики будут индексировать мусорные URL.

### Проверь себя
?? Какой маршрут ловит все неизвестные адреса? || `path: "*"`.
?? Что должно быть на хорошей странице 404? || Понятный заголовок, короткое объяснение, ссылки на главную и популярные разделы, общий дизайн сайта.
?? Объясни своими словами, зачем нужна страница 404, если «и так понятно, что страницы нет». || Пустой экран выглядит как поломка всего сайта, и человек уходит. Страница 404 объясняет ситуацию и помогает вернуться к нужному разделу, сохраняя посетителя.

### Ситуация
В проекте сорок файлов, и все лежат в одной папке `src`. Чтобы найти компонент корзины, ты листаешь список, путая `CartItem`, `cartApi`, `CartPage` и `cart.css`. Новый человек в команде вообще не понимает, с чего начать. Структура папок — первое, что видит любой, кто открывает проект, в том числе работодатель, смотрящий твоё портфолио.

### На пальцах
Пока в проекте пять файлов, их можно держать в одной папке, как пять тарелок на одной полке. Когда файлов сто — нужен кухонный гарнитур: здесь посуда, здесь продукты, здесь приборы. Структура папок — договорённость, где что лежит, чтобы любой (и ты через месяц) нашёл нужное за секунду.

### Как это работает
>> `components` — общие → `pages` — страницы → `features` — фичи со своей логикой

По типу файлов — просто и подходит небольшим проектам:

```text
src/
├── components/   ← переиспользуемые детали: Button, Card, Modal
├── pages/        ← страницы для роутера: Home, Catalog, Product
├── hooks/        ← свои хуки: useFetch, useLocalStorage
├── api/          ← функции запросов к серверу
├── utils/        ← чистые функции: formatPrice, pluralize
├── types/        ← общие типы
└── App.tsx
```

По фичам — всё про одну функцию приложения рядом, лучше масштабируется:

```text
src/
├── features/
│   ├── cart/        ← CartPage, CartItem, useCart, cartApi
│   ├── catalog/
│   └── auth/
├── shared/          ← общее: ui/Button, lib/formatPrice
└── app/             ← роутер, layout, провайдеры
```

Правила для любой схемы:

- один компонент — один файл, имя файла совпадает с именем компонента;
- общие детали интерфейса — в `components` или `shared/ui`, а не в папке конкретной страницы;
- импорты из `pages` в `components` не делают: детали не должны зависеть от страниц.

?: Почему компоненты из `components` не должны импортировать что-то из `pages`? || Переиспользуемые детали должны работать на любой странице. Если кнопка зависит от конкретной страницы, её уже не перенести в другое место, а зависимости начинают ходить по кругу и путаться.

### Пример
```tsx
// src/utils/formatPrice.ts
export const formatPrice = (n: number) => n.toLocaleString("ru-RU") + " ₽";

// src/components/ProductCard.tsx
import { formatPrice } from "../utils/formatPrice";
export function ProductCard({ title, price }: { title: string; price: number }) {
  return <article><h3>{title}</h3><p>{formatPrice(price)}</p></article>;
}

// src/pages/Catalog.tsx
import { ProductCard } from "./ProductCard";
```

?! Какой импорт в `Catalog.tsx` сломается и как его исправить? || `./ProductCard` ищет файл в папке `pages`, а компонент лежит в `components`. Нужно `../components/ProductCard`.

### Частые ошибки
- **Всё в одной папке `src`** или в одном `App.tsx` на 800 строк.
- **Вложенность в 6 уровней** ради «порядка».
- **Разные схемы** в разных частях одного проекта.

### Проверь себя
?? Чем схема «по типу файлов» отличается от схемы «по фичам»? || По типу — папки для компонентов, страниц, хуков и утилит. По фичам — всё, что относится к одной функции приложения (корзина, каталог), лежит вместе.
?? Куда положить функцию `formatPrice`? || В `utils` (или `shared/lib`) — это чистая вспомогательная функция, общая для всего проекта.
?? Объясни своими словами, зачем договариваться о структуре папок. || Чтобы любой человек быстро находил нужный файл, понимал, куда класть новый, и чтобы проект не превращался в свалку по мере роста.
