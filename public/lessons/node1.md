### На пальцах
Модуль `fs` — руки сервера для работы с бумагами: прочитать документ из шкафа, записать новый, дописать строчку в журнал, посмотреть, что лежит в папке. `fs/promises` — те же руки, но вежливые: они не заставляют весь офис ждать, пока ищут нужную папку.

### Как это работает
Три варианта API:

- синхронный: `fs.readFileSync` — блокирует программу до завершения. Допустим только при старте скрипта;
- колбэки: `fs.readFile(path, cb)` — старый стиль;
- промисы: `import { readFile } from "node:fs/promises"` — современный, с `await`.

| Функция | Что делает |
|---|---|
| `readFile(path, "utf8")` | прочитать текстовый файл |
| `writeFile(path, data)` | записать (перезаписать) файл |
| `appendFile(path, data)` | дописать в конец |
| `mkdir(path, { recursive: true })` | создать папку со всеми промежуточными |
| `readdir(path)` | список файлов в папке |
| `rm(path, { recursive: true, force: true })` | удалить |
| `stat(path)` | размер, дата изменения, папка или файл |

Пути строят через модуль `path`: `path.join(dir, "data", "users.json")` — правильные разделители на любой ОС.

Если файла нет — ошибка с кодом `ENOENT`. Её обрабатывают в `try/catch`.

?: Почему путь `readFile("data.json")` ломается, если запустить скрипт из другой папки? || Относительный путь считается от папки, из которой запустили Node.js (`process.cwd()`), а не от файла со скриптом. Надёжнее строить путь от `import.meta.dirname` — папки самого файла.

### Пример
```js

    if (e.code === "ENOENT") return [];

  }
}
```

- **Забыта кодировка `"utf8"`** — вместо текста придёт Buffer с байтами.

### На пальцах
Node.js — официант-одиночка в большом ресторане. Он очень быстрый, потому что никогда не ждёт у плиты: принял заказ, передал на кухню, пошёл к следующему столику. Но если попросить его лично почистить мешок картошки (долгое вычисление), все остальные столики останутся без внимания, пока он не закончит.

### Как это работает
- JavaScript в Node.js выполняется в одном потоке.
- Медленные операции ввода-вывода (запрос к базе, чтение файла, сетевой запрос) Node.js отдаёт системе и не ждёт: пока база думает, поток обслуживает другие запросы. Когда результат готов, колбэк или промис ставится в очередь.
- Event loop — цикл, который берёт задачи из очередей и выполняет по одной.
- Поэтому один процесс Node.js выдерживает тысячи одновременных подключений, если они в основном ждут.

Но долгое **синхронное** вычисление (тяжёлый цикл, обработка большого файла целиком, `readFileSync`, сложное регулярное выражение, `bcrypt.hashSync`) занимает поток полностью.

Что делать с тяжёлым:

- использовать асинхронные версии функций;
- разбивать работу на части;
- выносить в `worker_threads` или отдельный фоновый процесс (очередь задач).

?: Почему `async` перед функцией не делает тяжёлое вычисление неблокирующим? || `async` только позволяет внутри ждать промисы через `await`. Само вычисление по-прежнему выполняется в том же единственном потоке и занимает его целиком. Неблокирующим становится только ожидание внешних операций.

### Пример
```js
import http from "node:http";

http.createServer(async (req, res) => {
  if (req.url === "/slow-cpu") {
    const end = Date.now() + 5000;
    while (Date.now() < end) {}
    return res.end("CPU готово");
  }
  if (req.url === "/slow-wait") {
    await new Promise(r => setTimeout(r, 5000));
    return res.end("Ожидание готово");
  }
  res.end("Быстрый ответ");
}).listen(3000);
```

?! Ты открыл `/slow-cpu`, а через секунду в другой вкладке `/`. Когда придёт «Быстрый ответ»? А если сначала открыть `/slow-wait`? || После `/slow-cpu` — только через ~4 секунды: цикл занял единственный поток. После `/slow-wait` — сразу: таймер ждёт вне потока, и сервер свободен.

### Частые ошибки
- **`fs.readFileSync`, `bcrypt.hashSync`** и другие синхронные функции в обработчиках запросов.
- **Огромный массив в одном запросе** вместо пагинации.
- **Вера, что `async` делает вычисление неблокирующим.**

?? Почему Node.js выдерживает тысячи одновременных соединений? || Пока одни запросы ждут базу или сеть, поток не простаивает, а обслуживает другие — ожидание происходит вне потока.
?? Объясни своими словами, что такое event loop. || Цикл, который по очереди берёт готовые задачи — колбэки, результаты промисов, таймеры — и выполняет их одну за другой в единственном потоке JavaScript.

### Ситуация
Ты будешь писать серверы на Express, а там всё делается одной строчкой: `app.get`, `res.json`, `express.json()`. Удобно — но когда что-то ломается, непонятно, что происходит под капотом. Один раз собрать сервер голыми руками на встроенном модуле `http` — и любая магия фреймворка становится понятной.

### На пальцах
Express — удобный конструктор сервера. Модуль `http` — тот же сервер, собранный голыми руками из досок и гвоздей. Один раз собрать руками полезно: сразу понятно, что под капотом у любого фреймворка — запрос пришёл, мы посмотрели на метод и адрес, отправили ответ с кодом и заголовками.

### Как это работает
- `http.createServer((req, res) => { ... })` — функция вызывается на каждый запрос.
- `req.method` — метод, `req.url` — путь с параметрами, `req.headers` — заголовки.
- Тело запроса приходит потоком по кусочкам — его нужно собрать вручную.
- `res.statusCode = 404` — код, `res.setHeader("Content-Type", "application/json")` — заголовок.
- `res.end(текст)` — отправить ответ и закрыть. Без `end` клиент будет ждать вечно.
- `server.listen(3000)` — начать принимать запросы на порту.

Чего здесь нет и что даёт Express: разбор параметров маршрута (`/users/:id`), удобный `res.json()`, разбор JSON-тела, middleware, обработка ошибок.

?: Почему тело запроса приходит «по кусочкам», а не целиком? || По сети данные передаются пакетами, а тело может быть огромным — например, загружаемый файл. Node.js отдаёт куски по мере прихода, чтобы не держать всё в памяти и не ждать конца, если обрабатывать можно потоком.

### Пример
```js
import http from "node:http";

const projects = [{ id: 1, title: "Лендинг" }];

http.createServer(async (req, res) => {
  const url = new URL(req.url, "http://localhost");

  if (req.method === "POST" && url.pathname === "/api/projects") {
    let body = "";
    for await (const chunk of req) body += chunk;
    const data = JSON.parse(body);
    projects.push({ id: Date.now(), title: data.title });
    res.statusCode = 201;
    return res.end(JSON.stringify(projects.at(-1)));
  }

  if (req.method === "GET" && url.pathname === "/api/projects") {
    res.setHeader("Content-Type", "application/json");
    res.end(JSON.stringify(projects));
  }
}).listen(3000);
```

?! Что случится, если отправить `POST` с телом `не json`? А запрос на `/api/unknown`? || Кривое тело: `JSON.parse` бросит исключение, его никто не ловит — запрос упадёт, а в старых версиях Node.js и весь процесс. Неизвестный адрес: ни одно условие не сработает, `res.end` не вызовется, и клиент будет ждать ответа до таймаута.

### Частые ошибки
- **Забыт `res.end()`** — запрос висит до таймаута.
- **`JSON.parse` без `try/catch`** — кривое тело роняет обработчик.
- **Нет `Content-Type`** — клиент не знает, что пришёл JSON.

### Проверь себя
?? Что обязательно нужно вызвать, чтобы завершить ответ в модуле `http`? || `res.end()`.
?? Как в обработчике узнать метод и путь запроса? || Через `req.method` и `req.url` (путь удобно разобрать через `new URL(req.url, "http://localhost")`).
?? Объясни своими словами, что делает фреймворк Express поверх модуля `http`. || Берёт на себя рутину: маршруты с параметрами, разбор тела, удобные методы ответа вроде `res.json()`, цепочки middleware и обработку ошибок.
