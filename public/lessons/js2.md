### Ситуация
Интернет-магазин: доставка бесплатна от 5000 ₽, для постоянных клиентов — от 3000 ₽, в Москве — фикс 300 ₽, в регионы — 500 ₽. Без условий программа умеет делать только одно и то же для всех. Как только появляется «если… иначе…», код начинает принимать решения — и тут же появляется первый способ ошибиться.

### На пальцах
`if` — развилка на дороге с указателем: «Если идёт дождь — бери зонт». `else if` — следующий указатель: «Иначе, если солнце — надень очки». `else` — «во всех остальных случаях просто иди». Компьютер проверяет условия сверху вниз и выбирает первую подходящую дорогу.

### Как это работает
>> `if` условие → да — выполняем → `else if` — следующее → `else` — всё остальное

```js
if (условие1) {
  // если условие1 истинно
} else if (условие2) {
  // если условие1 ложно, а условие2 истинно
} else {
  // если ничего не подошло
}
```

- Условия проверяются по порядку. Как только одно подошло, остальные не проверяются.
- Поэтому порядок важен: сначала более строгие условия, потом общие.
- `else` необязателен.
- Фигурные скобки ставь всегда, даже для одной строки — так меньше ошибок при правках.

Приём «ранний выход»: в функции сначала обрабатывают плохие случаи и сразу выходят, а основной код пишут без вложенности.

?: Почему ранний выход делает код понятнее, чем вложенные `if`? || Каждый `return` в начале отсекает один случай, и дальше о нём можно забыть. Основная логика остаётся на одном уровне отступа и читается сверху вниз, а не как матрёшка из скобок.

### Пример
```js
const score = 78;
let grade;

if (score >= 50) {
  grade = "удовлетворительно";
} else if (score >= 70) {
  grade = "хорошо";
} else if (score >= 90) {
  grade = "отлично";
} else {
  grade = "нужно повторить";
}
console.log(grade);
```

?! Что выведет код для `score = 78`? А для `95`? || В обоих случаях «удовлетворительно». Первое же условие `score >= 50` истинно, и дальше проверки не идут. Условия надо переставить: сначала `>= 90`, потом `>= 70`, потом `>= 50`.

### Частые ошибки
- **Неправильный порядок:** общее условие стоит первым и «съедает» все частные — как в примере выше.
- **Точка с запятой после условия:** `if (x > 5); { ... }` — блок выполнится всегда, а `if` ничего не контролирует.
- **Глубокая вложенность** `if` в `if` в `if`. Ранний выход делает код плоским.

### Проверь себя
?? Сколько веток `if / else if / else` выполнится, если подходят сразу два условия? || Только одна — первая подходящая сверху. Остальные даже не проверяются.
?? В каком порядке писать условия вроде «больше 90», «больше 70», «больше 50»? || От самого строгого к самому общему: сначала 90, затем 70, затем 50.

### На пальцах
`==` — охранник, который пускает «похожих»: «Этот ноль и эта пустая строка — примерно одно и то же, проходите». `===` — строгий охранник: проверяет и значение, и тип. Строку «5» и число 5 он не перепутает.

### Как это работает
>> `==` приводит типы → `'5' == 5` — true → `===` без приведения → используем `===`

- `===` (строгое равенство) — `true`, только если совпадают и тип, и значение.
- `==` (нестрогое) — сначала пытается привести значения к одному типу, потом сравнивает. Правила приведения запутанные.

| Выражение | `==` | `===` |
|---|---|---|
| `5 == "5"` | true | false |
| `0 == ""` | true | false |
| `0 == false` | true | false |
| `null == undefined` | true | false |
| `"" == false` | true | false |

Правило: всегда используй `===` и `!==`. Нужно сравнить строку из формы с числом — сначала явно преобразуй: `Number(input) === 5`.

Объекты и массивы сравниваются по ссылке, а не по содержимому: `[1] === [1]` — `false`, потому что это две разные коробки с одинаковым содержимым.

?: Почему явное `Number(input) === 18` лучше, чем `input == 18`, если результат одинаковый? || В явном варианте видно, что ты осознанно превращаешь строку в число. `==` делает то же самое скрыто и по запутанным правилам, и в другом месте эти правила дадут неожиданное `true`, например для пустой строки и нуля.

### Пример
```js
const input = "18";

console.log(input === 18);
console.log(Number(input) === 18);

const a = [1, 2];
const b = a;
console.log([1, 2] === [1, 2]);
console.log(a === b);
```

?! Что выведут четыре строки? || `false` — строка не число. `true` — после преобразования. `false` — два разных массива, хоть и одинаковых на вид. `true` — `a` и `b` указывают на одну и ту же коробку.

### Проверь себя
?? Чем `===` отличается от `==`? || `===` сравнивает без приведения типов: должны совпасть и тип, и значение. `==` сначала приводит к одному типу.
?? Что вернёт `[1] === [1]` и почему? || `false`: это два разных массива, а объекты и массивы сравниваются по ссылке, а не по содержимому.

### Ситуация
Плеер с громкостью: пользователь выкрутил звук в ноль и сохранил настройки. При следующем запуске звук снова на 50%. Код выглядит безобидно: `volume || 50` — «если громкость не задана, поставь 50». Но для JavaScript ноль — это «как будто не задано». Логические операторы хитрее, чем кажутся.

### На пальцах
`&&` (И) — «пойду гулять, если тепло И нет дождя»: нужны оба условия. `||` (ИЛИ) — «возьму такси, если опаздываю ИЛИ идёт дождь»: хватит одного. `!` (НЕ) — переворачивает: «если НЕ выходной — иду на работу».

### Как это работает
>> `&&` — оба истинны → `||` — хотя бы один → `!` — наоборот → `??` — только для null/undefined

- `a && b` — истина, если истинны оба.
- `a || b` — истина, если истинен хотя бы один.
- `!a` — противоположное значение.

Особенность JavaScript: `&&` и `||` возвращают одно из значений, а не обязательно `true`/`false`:

- `a || b` — вернёт `a`, если оно истинное, иначе `b`. Удобно для значения по умолчанию: `name || "Гость"`.
- `a && b` — вернёт `a`, если оно ложное, иначе `b`. Удобно: «выполни, только если есть»: `user && user.name`.

`??` — как `||`, но подставляет значение по умолчанию только для `null` и `undefined`. Для нуля: `0 || 10` даст `10`, а `0 ?? 10` — `0`.

`?.` — безопасный доступ: `user?.address?.city` вернёт `undefined` вместо ошибки, если чего-то нет.

?: Почему `||` теряет ноль, а `??` — нет? || `||` подставляет запасное значение для любого «ложного» — а ноль и пустая строка считаются ложными. `??` срабатывает только когда значения действительно нет: `null` или `undefined`. Ноль для него — нормальное значение.

### Пример
```js
const nickname = "";
const volume = 0;
const user = null;

console.log(nickname || "Гость");
console.log(volume || 50);
console.log(volume ?? 50);
console.log(user?.name);
```

?! Что выведут четыре строки? || `Гость` — пустая строка ложная. `50` — ноль тоже ложный, громкость потеряна. `0` — `??` ноль не трогает. `undefined` — без ошибки, благодаря `?.`.

### Частые ошибки
- **`if (a === 1 || 2)`** в значении «a равно 1 или 2». Правильно: `a === 1 || a === 2`. Иначе условие всегда истинно: `2` само по себе truthy.
- **`||` для чисел** — теряется ноль.
- **Путаница с отрицанием сложных условий.** `!(a && b)` — это `!a || !b`.

### Проверь себя
?? Когда `a && b` истинно? || Когда истинны оба: и `a`, и `b`.
?? Чем `??` отличается от `||`? || `??` подставляет значение по умолчанию только для `null` и `undefined`. `||` — для любого ложного значения, включая `0` и `""`.
?? Объясни своими словами, что делает `user?.address?.city`. || Безопасно достаёт город: если `user` или `address` отсутствуют, вернёт `undefined` вместо ошибки.

### Как это работает

Falsy-значений всего восемь:

- `false`
- `0` и `-0`
- `0n` (ноль типа BigInt)
- `""` — пустая строка
- `null`
- `undefined`
- `NaN`

Это позволяет писать короче: `if (name)` вместо `if (name !== "" && name !== null && name !== undefined)`.

- **Проверка пустого массива через `if (arr)`** — он всегда truthy. Проверяй `arr.length`.

### Ситуация
Нужно написать «1 товар», «3 товара» или вывести статус заказа по коду: «new» → «Ждёт оплаты», «paid» → «Оплачен». Можно нагородить пять `if`, но код раздувается на экран. Для таких мелких решений в JavaScript есть короткие формы — и одна ловушка, на которой спотыкаются все.

### На пальцах
Тернарный оператор — короткий вопрос с двумя ответами: «Тебе есть 18? Если да — кофе, если нет — какао». `switch` — автомат с газировкой: нажал кнопку с номером — получил напиток, который к ней привязан.

### Как это работает
>> `условие ? да : нет` → короткий выбор → `switch` → много вариантов одного значения

Тернарный оператор: `условие ? значение_если_да : значение_если_нет`. Это выражение, его можно положить в переменную или подставить в строку. Хорош для выбора из двух. Вложенные тернарники читаются плохо — тогда лучше `if`.

`switch` сравнивает одно значение со списком вариантов через `===`:

```js
switch (значение) {
  case вариант1:
    ...
    break;
  case вариант2:
  case вариант3:   // несколько вариантов — одно действие
    ...
    break;
  default:
    ... // если ничего не подошло
}
```

`break` обязателен: без него выполнение «проваливается» в следующий `case`.

Часто вместо `switch` удобнее объект-справочник: `const labels = { new: "Новый", done: "Готов" }; labels[status]`.

?: Почему объект-справочник часто удобнее `switch`? || Он короче, в нём нет `break`, которые легко забыть, и его можно хранить отдельно, пополнять или даже получать с сервера. `switch` нужен, когда в ветках не просто значения, а разные действия.

### Пример
```js
const status = "paid";
switch (status) {
  case "new":
    console.log("Ждёт оплаты");
  case "paid":
    console.log("Оплачен, собираем");
  case "shipped":
    console.log("В пути");
    break;
  default:
    console.log("Неизвестный статус");
}
```

?! Что выведет код при `status = "paid"`? || Две строки: «Оплачен, собираем» и «В пути». После `case "paid"` нет `break`, и выполнение провалилось в следующий `case`, пока не встретило `break`.

### Частые ошибки
- **Забыт `break`** — выполняется несколько веток, как в примере.
- **Тернарники в три этажа** — никто не поймёт.
- **Тернарник для действий вместо значений:** `ok ? save() : alert()` — для действий понятнее `if`.

### Проверь себя
?? Как записать тернарный оператор? || `условие ? значение_если_да : значение_если_нет`.
?? Что произойдёт, если в `case` забыть `break`? || Выполнение продолжится в следующих `case` до первого `break` или конца `switch`.
?? Объясни своими словами, когда лучше тернарник, а когда `if`. || Тернарник — когда нужно выбрать одно из двух значений в одной строке. `if` — когда выполняются действия или вариантов больше двух.

Два способа поставить паузу:

1. **Слово `debugger;`** в коде. Если DevTools открыты, выполнение остановится на этой строке.

- Наведи курсор на переменную — увидишь её значение.
- Справа панель Scope показывает все переменные.
- Кнопки: продолжить (F8), шаг через строку (F10), зайти в функцию (F11), выйти из функции (Shift + F11).

```js
    sum += item.price;

]);
```

?! Что будет лежать в `sum`, когда цикл дойдёт до кофе и выполнит сложение? || Строка `"300450"`. Цена кофе пришла строкой, а `+` со строкой склеивает. В отладчике видно: на втором шаге `sum` из числа превращается в строку.

Открой DevTools, запусти код и шагай F10 — увидишь это своими глазами.

### Частые ошибки
- **`debugger` в коде проекта** — у пользователя с открытыми DevTools страница внезапно «зависнет».
- **Точка остановки при закрытых DevTools** — ничего не произойдёт.
- **Двадцать `console.log`** там, где одна точка остановки показала бы всё сразу.

### Проверь себя
?? Как поставить точку остановки без изменения кода? || DevTools → Sources → открыть файл → кликнуть по номеру строки.
?? Какая клавиша делает шаг на следующую строку, не заходя в функции? || F10.
?? Объясни своими словами, чем отладчик лучше `console.log`. || Он останавливает программу в нужный момент и показывает все переменные сразу, а дальше можно идти шаг за шагом и видеть, где именно значение испортилось.
