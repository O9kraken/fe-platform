### На пальцах
`if` — развилка на дороге с указателем: «Если идёт дождь — бери зонт». `else if` — следующий указатель: «Иначе, если солнце — надень очки». `else` — «во всех остальных случаях просто иди». Компьютер проверяет условия сверху вниз и выбирает первую подходящую дорогу.

### Как это работает
```js
if (условие1) {
  // если условие1 истинно
} else if (условие2) {
  // если условие1 ложно, а условие2 истинно
} else {
  // если ничего не подошло
}
```

- Условия проверяются по порядку. Как только одно подошло, остальные не проверяются.
- Поэтому порядок важен: сначала более строгие условия, потом общие.
- `else` необязателен.
- Фигурные скобки ставь всегда, даже для одной строки — так меньше ошибок при правках.

Приём «ранний выход»: в функции сначала обрабатывают плохие случаи и сразу выходят, а основной код пишут без вложенности.

### Пример
```js
const score = 78;
let grade;

if (score >= 90) {
  grade = "отлично";
} else if (score >= 70) {
  grade = "хорошо";
} else if (score >= 50) {
  grade = "удовлетворительно";
} else {
  grade = "нужно повторить";
}
console.log(grade); // хорошо

function deliveryCost(sum) {
  if (sum <= 0) return 0;          // ранний выход
  if (sum >= 5000) return 0;       // бесплатно
  return 300;
}
```

### Частые ошибки
- Неправильный порядок: если первым проверить `score >= 50`, все отличники получат «удовлетворительно».
- Точка с запятой после условия: `if (x > 5); { ... }` — блок выполнится всегда.
- Глубокая вложенность `if` в `if` в `if`. Ранний выход делает код плоским.

### На пальцах
`==` — охранник, который пускает «похожих»: «Этот ноль и эта пустая строка — примерно одно и то же, проходите». `===` — строгий охранник: проверяет и значение, и тип. Строку «5» и число 5 он не перепутает.

### Как это работает
- `===` (строгое равенство) — `true`, только если совпадают и тип, и значение.
- `==` (нестрогое) — сначала пытается привести значения к одному типу, потом сравнивает. Правила приведения запутанные.

| Выражение | `==` | `===` |
|---|---|---|
| `5 == "5"` | true | false |
| `0 == ""` | true | false |
| `0 == false` | true | false |
| `null == undefined` | true | false |
| `"" == false` | true | false |

Правило простое: всегда используй `===` и `!==`. Если нужно сравнить строку из формы с числом — сначала явно преобразуй: `Number(input) === 5`.

Объекты и массивы сравниваются по ссылке, а не по содержимому: `[1] === [1]` — `false`, потому что это две разные коробки, хоть и с одинаковым содержимым.

### Пример
```js
const input = "18";   // из поля формы всегда приходит строка

console.log(input == 18);           // true — но это случайность
console.log(input === 18);          // false — честно: строка не число
console.log(Number(input) === 18);  // true — правильно

console.log([1, 2] === [1, 2]);     // false — разные массивы
const a = [1, 2];
const b = a;
console.log(a === b);               // true — одна и та же коробка
```

### Частые ошибки
- Использовать `==` и ловить странные баги вроде `0 == ""`.
- Сравнивать значение из `input` с числом, не преобразовав.
- Пытаться сравнить два объекта через `===`, чтобы узнать, одинаковые ли у них поля.

### На пальцах
`&&` (И) — «пойду гулять, если тепло И нет дождя»: нужны оба условия. `||` (ИЛИ) — «возьму такси, если опаздываю ИЛИ идёт дождь»: хватит одного. `!` (НЕ) — переворачивает: «если НЕ выходной — иду на работу».

### Как это работает
- `a && b` — истина, если истинны оба.
- `a || b` — истина, если истинен хотя бы один.
- `!a` — противоположное значение.

Особенность JavaScript: `&&` и `||` возвращают не обязательно `true`/`false`, а одно из значений:

- `a || b` — вернёт `a`, если оно истинное, иначе `b`. Удобно для значения по умолчанию: `name || "Гость"`.
- `a && b` — вернёт `a`, если оно ложное, иначе `b`. Удобно: «выполни, только если есть»: `user && user.name`.

Есть ещё `??` — как `||`, но подставляет значение по умолчанию только для `null` и `undefined`. Разница важна для нуля: `0 || 10` даст `10`, а `0 ?? 10` даст `0`.

И `?.` — безопасный доступ: `user?.address?.city` вернёт `undefined` вместо ошибки, если чего-то нет.

### Пример
```js
const age = 20;
const hasTicket = true;

if (age >= 18 && hasTicket) console.log("Проходите");
if (age < 7 || age > 65) console.log("Скидка");
if (!hasTicket) console.log("Купите билет");

const nickname = "";
console.log(nickname || "Гость");   // Гость

const volume = 0;
console.log(volume || 50);          // 50 — ошибка, громкость 0 потеряли!
console.log(volume ?? 50);          // 0 — правильно

const user = null;
console.log(user?.name);            // undefined, без ошибки
```

### Частые ошибки
- Писать `if (a = 1 || 2)`, имея в виду «a равно 1 или 2». Правильно: `a === 1 || a === 2`.
- Использовать `||` для чисел и терять ноль.
- Путаница с отрицанием сложных условий. `!(a && b)` — это `!a || !b`.

### На пальцах
В условиях JavaScript любое значение — как кандидат на собеседовании: его оценивают по принципу «есть что-то или нет». Пустая строка, ноль, «ничего» — проваливают собеседование (falsy). Всё остальное — проходит (truthy), даже строка «0» и пустой массив.

### Как это работает
Falsy-значений всего восемь, их стоит запомнить:

- `false`
- `0` и `-0`
- `0n` (ноль типа BigInt)
- `""` — пустая строка
- `null`
- `undefined`
- `NaN`

Всё остальное — truthy: `"0"`, `"false"`, `" "` (пробел), `[]`, `{}`, `-1`, любая функция.

Это позволяет писать короче: `if (name)` вместо `if (name !== "" && name !== null && name !== undefined)`.

Превратить значение в настоящий `true`/`false`: `Boolean(x)` или `!!x`.

### Пример
```js
const items = [];
if (items) console.log("Это выполнится — пустой массив truthy!");
if (items.length) console.log("А это нет — 0 falsy");

const name = "  ";
if (name.trim()) {
  console.log("Привет,", name);
} else {
  console.log("Введите имя");   // выполнится: после trim — пустая строка
}

console.log(Boolean("0"));      // true
console.log(!!NaN);             // false
```

### Частые ошибки
- Проверять пустой массив через `if (arr)` — он всегда truthy. Проверяй `arr.length`.
- Терять ноль: `if (price)` при цене 0 решит, что цены нет.
- Строка `"false"` из `localStorage` — truthy. Сравнивай явно: `value === "true"`.

### На пальцах
Тернарный оператор — короткий вопрос с двумя ответами: «Ты совершеннолетний? Если да — пиво, если нет — сок». `switch` — автомат с газировкой: нажал кнопку с номером — получил напиток, который к ней привязан.

### Как это работает
Тернарный оператор: `условие ? значение_если_да : значение_если_нет`. Это выражение, его можно сразу положить в переменную или подставить в строку. Хорош для простого выбора из двух. Вложенные тернарники читаются плохо — тогда лучше `if`.

`switch` сравнивает одно значение со списком вариантов через `===`:

```js
switch (значение) {
  case вариант1:
    ...
    break;
  case вариант2:
  case вариант3:   // несколько вариантов — одно действие
    ...
    break;
  default:
    ... // если ничего не подошло
}
```

`break` обязателен: без него выполнение «проваливается» в следующий `case`.

Часто вместо `switch` удобнее объект-справочник: `const labels = { new: "Новый", done: "Готов" }; labels[status]`.

### Пример
```js
const age = 16;
const drink = age >= 18 ? "кофе" : "какао";
console.log(`Вам ${drink}`);

const items = 3;
console.log(`В корзине ${items} ${items === 1 ? "товар" : "товара"}`);

const status = "paid";
switch (status) {
  case "new":
    console.log("Ждёт оплаты");
    break;
  case "paid":
    console.log("Оплачен, собираем");
    break;
  case "shipped":
  case "delivered":
    console.log("В пути или доставлен");
    break;
  default:
    console.log("Неизвестный статус");
}

const LABELS = { new: "Ждёт оплаты", paid: "Оплачен" };
console.log(LABELS[status] ?? "Неизвестный статус");
```

### Частые ошибки
- Забыть `break` и получить выполнение нескольких веток.
- Вложенные тернарники в три этажа — никто не поймёт.
- Использовать тернарник для действий вместо значений: `ok ? save() : alert()` — для действий понятнее `if`.

### На пальцах
`console.log` — расспрашивать свидетелей после происшествия. Отладчик — поставить на паузу видео и посмотреть кадр за кадром: что лежит в каждой переменной в этот самый момент, куда пойдёт программа дальше.

### Как это работает
Два способа поставить паузу:

1. **Слово `debugger;`** в коде. Если DevTools открыты, выполнение остановится на этой строке.
2. **Точка остановки** в DevTools: вкладка Sources → открой свой файл (Ctrl + P) → кликни по номеру строки. Появится синяя метка.

Когда код на паузе:

- Наведи курсор на переменную — увидишь её значение.
- Справа панель Scope показывает все переменные.
- Кнопки управления: продолжить (F8), шаг через строку (F10), зайти внутрь функции (F11), выйти из функции (Shift + F11).
- Вкладка Watch — добавь выражение, и оно будет пересчитываться на каждом шаге.
- Правый клик по точке остановки → «Edit breakpoint» — остановка по условию, например только когда `i === 50`.

### Пример
```js
function total(cart) {
  let sum = 0;
  for (const item of cart) {
    debugger;                    // пауза на каждом товаре
    sum += item.price * item.qty;
  }
  return sum;
}

total([
  { title: "Чай", price: 300, qty: 2 },
  { title: "Кофе", price: "450", qty: 1 },  // цена строкой — найди баг отладчиком
]);
```

Открой DevTools, запусти код и шагай F10. На втором товаре увидишь, что `sum` превратилась в строку `"600450"`.

### Частые ошибки
- Оставить `debugger` в коде проекта.
- Ставить точку остановки при закрытых DevTools и ждать, что что-то произойдёт.
- Добавлять двадцать `console.log` там, где одна точка остановки показала бы всё сразу.
