### Ситуация
Заказчик после ребрендинга: «Наш синий теперь фиолетовый». Ты открываешь CSS, а там `#1f4fd8` встречается 47 раз — в кнопках, ссылках, рамках, тенях, иногда в чуть другом оттенке. Поиск с заменой пропустит половину. Будь цвет записан один раз в переменной, правка заняла бы десять секунд.

### На пальцах
CSS-переменная — банка краски с этикеткой «фирменный синий». Везде, где нужен этот цвет, ты не смешиваешь краску заново, а берёшь из банки. Решили сменить фирменный цвет — перекрасил одну банку, обновились все стены.

### Как это работает
- Объявление: имя начинается с двух дефисов, обычно в `:root` (это `html`), чтобы переменная была видна везде: `--accent: #1f4fd8;`
- Использование: `color: var(--accent);`
- Запасное значение: `var(--accent, blue)` — если переменная не задана.
- Переменные наследуются и переопределяются: внутри `.dark` можно задать `--bg` иначе, и все вложенные элементы возьмут новое значение.
- Их можно менять из JavaScript: `document.documentElement.style.setProperty("--accent", "red")`.

Что выносить в переменные: цвета, шрифты, радиусы скругления, основные отступы. Получается мини-дизайн-система.

?: Почему переменные объявляют именно в `:root`? || `:root` — самый верхний элемент документа. Переменные наследуются вниз по дереву, поэтому объявленная в `:root` видна абсолютно всем элементам страницы.

### Пример
```css
:root {
  --accent: #1f4fd8;
  --radius: 12px;
  --space: 16px;
}

.btn {
  background: var(--accent);
  border-radius: var(--radius);
  padding: calc(var(--space) * 0.75) var(--space);
}

.promo {
  --accent: #e8590c;
}
```

- **Один дефис:** `-accent` — не сработает. Нужно два.
- **Забыт `var()`:** `color: --accent` — не сработает.
- **Переменная на каждый оттенок «на всякий случай».** Начни с 5–8 основных, иначе система превращается в хаос.

### Ситуация
Наводишь мышку на карточку — она резко дёргается вверх, как от испуга. Убираешь — падает обратно рывком. Технически эффект есть, но ощущение дешёвое. А теперь представь то же движение плавным, за пятую долю секунды, — интерфейс сразу кажется дороже. Разница — одна строчка `transition`.

### На пальцах
`transition` — дверь с доводчиком вместо хлопка: из состояния А в состояние Б не мгновенно, а за 0,2 секунды. `transform` — подвинуть, повернуть или увеличить предмет, не двигая мебель вокруг. `@keyframes` — мультфильм по кадрам. `prefers-reduced-motion` — уважение к тем, кого от анимации укачивает.

### Как это работает
- `transition: свойство длительность функция` — анимирует изменение, например при `:hover`.
- `transform: translateY(-4px) scale(1.02) rotate(5deg)` — сдвиг, масштаб, поворот. Соседи не сдвигаются.
- Анимировать дешевле всего `transform` и `opacity`. Анимация `width`, `top`, `margin` заставляет браузер пересчитывать раскладку.
- `@keyframes имя { from {...} to {...} }` + `animation: имя 1s ease infinite` — самостоятельная анимация.
- `@media (prefers-reduced-motion: reduce)` — пользователь просит уменьшить движение. Убери или упрости анимации.

?: Почему анимировать `transform` лучше, чем `margin-top`? || Изменение `margin` двигает соседей, и браузер на каждом кадре пересчитывает раскладку страницы — это тяжело и может дёргаться. `transform` двигает только картинку элемента, соседи стоят на месте, и видеокарта рисует это плавно.

### Пример
```css
.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 12px 24px rgb(0 0 0 / 12%);
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

@keyframes pulse {
  0%, 100% { transform: scale(1); }
  50%      { transform: scale(1.08); }
}
.badge-new {
  animation: pulse 1.5s ease-in-out infinite;
}
```

?! Мышь наводится на карточку и затем уходит. Как будет выглядеть движение «туда» и «обратно»? || Туда — плавно за 0,2 секунды. Обратно — рывком: `transition` записан только в `:hover`, и когда наведение пропадает, правила плавности уже нет. `transition` нужно перенести в обычное правило `.card`.

### Частые ошибки
- **`transition: all`** — анимируется всё подряд, включая то, что не нужно, и иногда это заметно тормозит.
- **Долгие анимации:** 1–2 секунды на наведение раздражают. Ориентир — 150–300 мс.
- **`transition` только в `:hover`** — анимация работает лишь в одну сторону.

### Проверь себя
?? Какие свойства дешевле всего анимировать? || `transform` и `opacity`.
?? Чем `transition` отличается от `@keyframes`-анимации? || `transition` плавно переводит из одного состояния в другое при изменении (например, при наведении). `@keyframes` — самостоятельная анимация по кадрам, может повторяться бесконечно.
?? Объясни своими словами, что такое `prefers-reduced-motion` и зачем его учитывать. || Системная настройка «уменьшить движение». Некоторых людей от анимаций укачивает или отвлекает, и сайт должен в этом случае их упростить или отключить.

### Мини-задание
Сделай карточкам плавный подъём при наведении, кнопке — плавную смену цвета, значку «Новинка» — пульсацию. Включи «уменьшение движения» (или эмулируй в DevTools → Rendering) и проверь, что анимации отключились.

### Ситуация
Заголовок `h1` в 56 пикселей шикарно смотрится на мониторе. На телефоне он ломается по слогам на четыре строки. Ты пишешь медиазапрос, потом ещё один для планшета, потом для маленьких ноутбуков… А можно одной строчкой сказать: «расти вместе с экраном, но в разумных пределах».

### На пальцах
`clamp()` — резинка с ограничителями. Заголовок растягивается вместе с экраном, но не меньше «маленького» размера и не больше «большого». На телефоне не огромный, на мониторе не крошечный, и никаких медиазапросов.

### Как это работает
`clamp(минимум, желаемое, максимум)`:

- **минимум** — меньше не будет, например `28px` на маленьком телефоне;
- **желаемое** — значение, зависящее от ширины экрана, например `5vw` (5% ширины окна);
- **максимум** — больше не будет, например `56px`.

Чтобы шрифт оставался масштабируемым при зуме, к `vw` добавляют `rem`: `clamp(1.75rem, 1rem + 3vw, 3.5rem)`.

`clamp()` работает не только для шрифтов: для отступов секций, ширины колонок, внутренних полей. Похожие функции: `min(a, b)` — меньшее из двух, `max(a, b)` — большее.

?: Почему к `vw` в формуле добавляют `rem`? || Чистые `vw` зависят только от ширины окна и не реагируют на зум и настройку шрифта. Слагаемое в `rem` возвращает эту связь: увеличил человек шрифт — заголовок тоже подрос.

### Пример
```css
h1 {
  font-size: clamp(1.75rem, 1rem + 3vw, 3.5rem);
  line-height: 1.1;
}

.section {
  padding-block: clamp(40px, 8vw, 120px);
}

.container {
  width: min(100% - 32px, 1200px);
  margin-inline: auto;
}
```

?! Какой отступ у `.section` на экране 375px и на 2000px? Посчитай. || На 375px: 8vw = 30px, это меньше минимума, поэтому 40px. На 2000px: 8vw = 160px, это больше максимума, поэтому 120px.

### Частые ошибки
- **Только `vw` без ограничений:** на телефоне заголовок 12px, на 4K-мониторе — 150px.
- **Минимум больше максимума** — результат непредсказуем.
- **Чистые `vw` без `rem`** — шрифт не реагирует на зум и настройки пользователя.

### Проверь себя
?? В каком порядке пишутся аргументы `clamp()`? || Минимум, желаемое значение, максимум.
?? Что вернёт `min(100% - 32px, 1200px)` на экране 800px? || 768px — меньшее из двух значений.
?? Объясни своими словами, чем `clamp()` удобнее медиазапросов для шрифтов. || Размер меняется плавно на любой ширине экрана и сам упирается в границы. Не нужно писать отдельные правила для каждой точки перелома.

### Мини-задание
Сделай резиновые размеры для `h1`, `h2` и отступов секций через `clamp`. Проверь ширины 375 и 1440px — заголовки должны выглядеть пропорционально на обоих.

### Ситуация
Ты пишешь `.title { color: red; }` для заголовка карточки — и вдруг краснеют заголовки в модальном окне, в подвале и в статье блога: везде, где кто-то когда-то тоже назвал класс `title`. Через месяц в проекте никто не рискует трогать стили. БЭМ — договорённость об именах, которая делает такие конфликты невозможными.

### На пальцах
БЭМ — система подписей для коробок при переезде. Блок — «Кухня». Элемент — «Кухня: тарелки». Модификатор — «Кухня: тарелки, хрупкое». По подписи сразу понятно, что это, к чему относится и чем особенное.

### Как это работает
- **Блок** — самостоятельный компонент: `.card`, `.menu`, `.btn`.
- **Элемент** — часть блока, через два подчёркивания: `.card__title`, `.card__photo`, `.menu__link`.
- **Модификатор** — вариант или состояние, через два дефиса: `.btn--primary`, `.card--featured`, `.menu__link--active`.

Правила:

- Элемент принадлежит только своему блоку и вне его не используется.
- Без «внуков»: `.card__body__title` — плохо, `.card__title` — хорошо, даже если заголовок глубоко вложен.
- Модификатор добавляется к основному классу: `class="btn btn--primary"`.
- Стили пишем по одному классу, без вложенных селекторов вроде `.card h3`.

?: Почему в БЭМ избегают вложенных селекторов вроде `.card h3`? || У всех селекторов из одного класса одинаковый вес, поэтому правила не воюют по специфичности и легко переопределяются модификаторами. А ещё стиль не зависит от того, какой тег стоит внутри: заменишь `h3` на `h2` — ничего не сломается.

### Пример
```html
<article class="card card--featured">
  <img class="card__photo" src="img/landing.jpg" alt="Пример лендинга">
  <h3 class="card__title">Лендинг под ключ</h3>
  <p class="card__price">от 30 000 ₽</p>
  <a class="btn--primary" href="#order">Заказать</a>
</article>
```

```css
.card { padding: 20px; border-radius: 12px; background: #fff; }
.card--featured { border: 2px solid #1f4fd8; }
.btn { padding: 12px 20px; border-radius: 10px; }
.btn--primary { background: #1f4fd8; color: #fff; }
```

?! Как будет выглядеть кнопка «Заказать»: со скруглением и отступами или нет? || Будет синей с белым текстом, но без отступов и скругления: у неё только модификатор `btn--primary`, а базовый класс `btn` забыт. Правильно: `class="btn btn--primary"`.

### Частые ошибки
- **Цепочки элементов:** `.card__body__title`. Элемент всегда пишется от имени блока.
- **Модификатор без основного класса:** `class="btn--primary"` — теряются базовые стили.
- **БЭМ вперемешку с селекторами по тегам** внутри блоков — возвращаются войны специфичности.

### Проверь себя
?? Как в БЭМ записывается элемент и модификатор? || Элемент — через два подчёркивания: `card__title`. Модификатор — через два дефиса: `btn--primary`.
?? Как правильно назвать заголовок, лежащий в `.card__body` внутри `.card`? || `.card__title` — без цепочки через `body`.
?? Объясни своими словами, какую проблему решает БЭМ. || Конфликты имён и войну специфичности: у каждого класса понятный хозяин, все селекторы одного веса, и стили одного компонента не задевают другие.

### Мини-задание
Перепиши классы своих карточек и кнопок по БЭМ. Сделай вариант «рекомендуем» через модификатор `card--featured`.

### Ситуация
Вечер, у пользователя в телефоне включена тёмная тема: почта, мессенджеры, настройки — всё тёмное. Он открывает твой сайт — и получает в глаза белой вспышкой, как фарами. Многие сразу закрывают вкладку. Сделать тёмную тему проще, чем кажется, если цвета уже лежат в переменных.

### На пальцах
`prefers-color-scheme` — сайт спрашивает систему: «Хозяин любит тёмное?» — и сам переодевается. Благодаря переменным переодеться — значит поменять пять банок краски, а не перекрашивать каждую стену.

### Как это работает
1. Все цвета — в переменных в `:root`.
2. В медиазапросе `@media (prefers-color-scheme: dark)` переопределяешь только переменные.
3. `color-scheme: light dark` подсказывает браузеру перекрасить полосы прокрутки, поля ввода и прочие системные элементы.

Для ручного переключателя используют атрибут на `html`: `data-theme="dark"`, и JavaScript, который его ставит и запоминает выбор в `localStorage`.

Тёмная тема — не инверсия. Чистый чёрный `#000` и чистый белый текст режут глаза; лучше тёмно-серый фон и светло-серый текст. Акцентные цвета делают чуть светлее и менее насыщенными.

?: Почему синий акцент `#1f4fd8` в тёмной теме обычно заменяют более светлым? || Тёмно-синий на почти чёрном фоне даёт низкий контраст — текст и кнопки плохо читаются. Светлый оттенок того же тона сохраняет фирменный цвет и остаётся различимым.

### Пример
```css
:root {
  color-scheme: light dark;
  --bg: #ffffff;
  --text: #16202a;
  --accent: #1f4fd8;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f151b;
    --text: #e6ecf1;
    --accent: #86a6ff;
  }
}

body { background: var(--bg); color: var(--text); }
.logo { color: #16202a; }
```

?! Пользователь с тёмной темой открыл страницу. Что будет с фоном, текстом и логотипом? || Фон станет тёмным, текст светлым — переменные переопределились. А логотип останется тёмным `#16202a`, потому что цвет вписан напрямую, — на тёмном фоне он почти исчезнет.

Проверить без смены настроек системы: DevTools → Ctrl + Shift + P → «Emulate CSS prefers-color-scheme: dark».

### Частые ошибки
- **Цвета вписаны прямо в правила** — тёмную тему придётся писать заново.
- **Забытые картинки и логотипы:** тёмный логотип исчезает на тёмном фоне.
- **Низкий контраст** серого текста на тёмно-сером фоне.

### Проверь себя
?? Какой медиазапрос определяет, что у пользователя тёмная тема? || `@media (prefers-color-scheme: dark)`.
?? Что делает `color-scheme: light dark`? || Разрешает браузеру перекрашивать системные элементы — полосы прокрутки, поля ввода — под текущую тему.
?? Объясни своими словами, почему тёмная тема — не просто инверсия цветов. || Чистый чёрный и белый режут глаза, а акцентные цвета теряют контраст. Нужны мягкий тёмный фон, светло-серый текст и осветлённые акценты.

### Мини-задание
Добавь своему лендингу тёмную тему через `prefers-color-scheme`. Проверь эмуляцией в DevTools, что все тексты читаются, а логотип и иконки видны.

### Ситуация
Ты сверстал первый лендинг, и он прекрасен — на твоём компьютере. Показать его некому: файл `index.html` у тебя на диске. Друзья, работодатель, будущий заказчик хотят просто ссылку. GitHub Pages даёт её бесплатно, за пять минут и без единой настройки сервера.

### На пальцах
GitHub Pages — бесплатная витрина для проекта. Код уже лежит на GitHub, как товар на складе. Pages выставляет его на витрину по адресу `твой-логин.github.io/проект`, и любой открывает сайт по ссылке. Идеально для портфолио.

### Как это работает
1. Сайт — статические файлы: HTML, CSS, JS, картинки. Главная страница должна называться `index.html`.
2. Отправь проект на GitHub (`git push`).
3. На странице репозитория: Settings → Pages.
4. «Build and deployment» → Source: «Deploy from a branch», ветка `main`, папка `/ (root)`. Save.
5. Через минуту-две сайт доступен по адресу `https://логин.github.io/имя-репозитория/`.
6. Каждый новый `git push` обновляет сайт автоматически.

Можно подключить свой домен: Settings → Pages → Custom domain, плюс запись в DNS у регистратора.

?: Почему на GitHub Pages ломаются пути, начинающиеся с `/`? || Сайт живёт не в корне домена, а в подпапке `/имя-репозитория/`. Путь `/img/logo.png` ищет картинку в корне `логин.github.io`, где её нет. Относительный `img/logo.png` считается от страницы и работает.

### Пример
```text
web-landing/
├── index.html
├── css/style.css
└── img/Hero.jpg
```

### Частые ошибки
- **Главный файл `Index.html` или `home.html`** — Pages покажет 404.
- **Абсолютные пути `/css/style.css`** — стили не загрузятся.
- **Разный регистр** в именах файлов и ссылках: на GitHub Pages `Hero.JPG` и `hero.jpg` — разные файлы.

### Проверь себя
?? Как должен называться главный файл сайта для GitHub Pages? || `index.html`, строчными буквами.
?? Что нужно сделать, чтобы обновить опубликованный сайт? || Закоммитить изменения и выполнить `git push` — Pages обновится сам.
?? Объясни своими словами, почему на Pages лучше использовать относительные пути. || Сайт лежит в подпапке с именем репозитория, поэтому пути от корня домена ведут не туда, а относительные считаются от текущей страницы.
