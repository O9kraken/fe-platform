### Ситуация
До сих пор JavaScript жил в консоли: считал, выводил строчки. А пользователю консоль не показывают. Он хочет, чтобы при нажатии «В корзину» цифра у значка корзины сменилась с 2 на 3, а меню выезжало по клику на бургер. Для этого коду нужно дотянуться до элементов страницы — и тут появляется DOM.

### На пальцах
DOM — живой макет страницы, который браузер собрал из HTML. JavaScript может взять в руки любую деталь макета. `querySelector` — найти деталь по описанию («кнопка с классом buy»). `textContent` — заменить надпись на детали. `classList` — повесить или снять ярлык, от которого зависит внешний вид.

### Как это работает
Поиск:

- `document.querySelector("css-селектор")` — первый подходящий элемент или `null`.
- `document.querySelectorAll("селектор")` — все подходящие (по списку можно идти `for...of` или `forEach`).
- Искать можно и внутри элемента: `card.querySelector(".price")`.

Текст и атрибуты:

- `el.textContent = "текст"` — безопасно заменить текст.
- `el.value` — значение поля ввода.
- `el.getAttribute("href")`, `el.setAttribute("href", "...")`, `el.dataset.id` — данные из `data-id="..."`.

Классы — главный способ менять внешний вид из JS, а сами стили держать в CSS:

- `el.classList.add("open")`, `remove("open")`, `toggle("open")`, `contains("open")`.

?: Почему внешний вид лучше менять через классы, а не через `el.style.color = ...`? || Стили остаются в CSS, где их видно и легко поправить, а JavaScript только говорит, в каком состоянии элемент: «открыт», «выбран». Inline-стили из JS разбросаны по коду, перебивают CSS и их трудно найти.

### Пример
```html
<h1 class="title">Корзина</h1>
<p class="count">Товаров: 0</p>
<button data-price="1500">Купить</button>
```

```js
const title = document.querySelector("title");
const btn = document.querySelector("button");
const items = document.querySelectorAll("p");

console.log(title?.textContent);
console.log(btn.dataset.price, typeof btn.dataset.price);
console.log(items.length);
```

?! Что выведут три строки? || Первая — текст из тега `<title>` во вкладке, а не «Корзина»: в селекторе забыта точка, и ищется тег `title`. Вторая — `1500 string`: из `dataset` всё приходит строкой. Третья — `1`.

### Частые ошибки
- **Забыта точка в селекторе класса:** `querySelector("title")` ищет тег `<title>`.
- **Работа с результатом `querySelector` без проверки на `null`** — «Cannot read properties of null».
- **`el.style.color = ...` повсюду** вместо переключения классов.

### Проверь себя
?? Что вернёт `querySelector`, если ничего не нашёл? || `null`.
?? Как переключить класс у элемента туда-обратно одной командой? || `el.classList.toggle("имя")`.
?? Объясни своими словами, что такое DOM. || Дерево объектов, которое браузер построил из HTML. JavaScript может находить в нём элементы и менять их текст, атрибуты и классы, и страница сразу обновляется.

### Ситуация
Ты делаешь список задач. Пользователь вводит «Купить хлеб» и нажимает «Добавить» — в списке должен появиться новый пункт, которого не было в HTML. А один хитрый пользователь вводит `<img src=x onerror="alert('взлом')">` — и если ты вставил текст неправильно, этот код выполнится на странице. Создавать элементы нужно уметь безопасно.

### На пальцах
`createElement` — сделать новую деталь для макета: пока она лежит у тебя в руках, на странице её нет. `append` — прикрутить деталь в нужное место. `remove` — открутить и выбросить.

### Как это работает
1. `document.createElement("li")` — создать элемент. Он существует, но не на странице.
2. Настроить: `textContent`, `className`, атрибуты, вложенные элементы.
3. Вставить: `parent.append(el)` — в конец родителя, `parent.prepend(el)` — в начало, `el.before(other)` / `el.after(other)` — рядом.
4. Удалить: `el.remove()`.

Очистить контейнер: `list.replaceChildren()` или `list.textContent = ""`.

Быстрый путь — `innerHTML` с готовой HTML-строкой — опасен с пользовательскими данными. Для пользовательского текста всегда используй `textContent`.

Если элементов много, их можно собрать в `DocumentFragment` и вставить разом — браузер перерисует страницу один раз.

?: Почему `textContent` безопасен, а `innerHTML` — нет? || `textContent` всегда трактует строку как обычный текст: угловые скобки просто отображаются. `innerHTML` разбирает строку как HTML, и если в ней спрятан тег с обработчиком, браузер его создаст и выполнит код злоумышленника.

### Пример
```js
const list = document.querySelector("#list");
const text = "<b>жирный</b>";

const li1 = document.createElement("li");
li1.textContent = text;

const li2 = document.createElement("li");
li2.innerHTML = text;

list.append(li1);
```

?! Что увидит пользователь в списке? || Один пункт с буквальным текстом `<b>жирный</b>` вместе со скобками — это `li1`. Второй элемент создан, но так и не вставлен на страницу: для `li2` нет `append`.

### Частые ошибки
- **Создать элемент и забыть вставить** — он «висит в воздухе».
- **`innerHTML += "<li>" + userText + "</li>"`** — дыра для XSS и пересоздание всех элементов списка при каждом добавлении.
- **Вставка по одному в цикле на тысячу штук** — медленно. Используй фрагмент или вставь разом.

### Проверь себя
?? Какие три шага нужны, чтобы добавить новый элемент на страницу? || Создать через `createElement`, настроить (текст, классы, атрибуты) и вставить через `append` или похожий метод.
?? Как удалить элемент со страницы? || `el.remove()`.
?? Объясни своими словами, что такое XSS на примере `innerHTML`. || Злоумышленник вводит текст с HTML-тегом и кодом. Если вставить его через `innerHTML`, браузер выполнит этот код у всех, кто видит страницу.

### Мини-задание
Сделай список покупок: поле, кнопка «Добавить» и список. У каждой покупки — кнопка удаления. Проверь, что ввод `<b>жирный</b>` отображается как текст, а не жирным шрифтом.

### Ситуация
Ты сделал форму подписки, вешаешь обработчик, нажимаешь «Подписаться» — сообщение «Спасибо!» мелькает на долю секунды и исчезает. Страница перезагрузилась, как в 2005 году. А если пользователь нажмёт Enter в поле вместо клика — твой обработчик на кнопке вообще не сработает. Работа с событиями — это умение договориться с браузером.

### На пальцах
Событие — звонок в дверь. `addEventListener` — договориться: «когда позвонят, я открою». `event.target` — посмотреть в глазок, кто именно позвонил. `preventDefault` — «не делай того, что обычно делаешь»: например, не перезагружай страницу при отправке формы, я сам разберусь.

### Как это работает
```js
element.addEventListener("тип", (event) => { ... });
```

| Событие | Когда |
|---|---|
| `click` | клик или Enter на кнопке |
| `input` | каждое изменение текста в поле |
| `change` | значение изменили и ушли с поля (select, checkbox) |
| `submit` | отправка формы (кнопкой или Enter) |
| `keydown` | нажатие клавиши |
| `DOMContentLoaded` | HTML загружен |

Объект `event`:

- `event.target` — элемент, на котором произошло событие.
- `event.currentTarget` — элемент, на котором висит обработчик.
- `event.preventDefault()` — отменить действие браузера: отправку формы, переход по ссылке.
- `event.key` — какая клавиша нажата.

?: Почему для формы слушают `submit` на самой форме, а не `click` на кнопке? || Форму можно отправить не только кликом, но и клавишей Enter в любом поле. `submit` срабатывает в обоих случаях, а `click` на кнопке пропустит Enter.

### Пример
```html
<form id="subscribe">
  <input name="email" type="email" required>
  <button>Подписаться</button>
</form>
<p id="result"></p>
```

```js
const form = document.querySelector("#subscribe");
const result = document.querySelector("#result");

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const email = new FormData(form).get("email");
  result.textContent = `Спасибо! Письмо придёт на ${email}`;
  form.reset();
});
```

?! Пользователь ввёл `anna@mail.ru` и нажал Enter. Что произойдёт? А если убрать строку `preventDefault()`? || Под формой появится «Спасибо! Письмо придёт на anna@mail.ru», поле очистится, страница не перезагрузится. Без `preventDefault` браузер отправит форму обычным способом и перезагрузит страницу — сообщение мелькнёт и исчезнет.

### Частые ошибки
- **Результат вызова вместо функции:** `addEventListener("click", handle())` — `handle` выполнится сразу при загрузке.
- **`click` на кнопке отправки** — Enter в поле не сработает.
- **Нет `preventDefault`** — форма перезагружает страницу, и все изменения исчезают за долю секунды.

### Проверь себя
?? Какое событие срабатывает при каждом изменении текста в поле? || `input`.
?? Чем `event.target` отличается от `event.currentTarget`? || `target` — элемент, где событие произошло (например, иконка внутри кнопки). `currentTarget` — элемент, на котором висит обработчик.
?? Объясни своими словами, что делает `preventDefault()`. || Отменяет стандартное действие браузера для события: отправку формы с перезагрузкой, переход по ссылке и так далее.

### Мини-задание
Сделай форму с полем имени. По отправке без перезагрузки выводи под формой «Привет, Имя!». Добавь счётчик символов под полем, который обновляется при каждом вводе (событие `input`).

### Ситуация
У тебя список из 500 задач, у каждой — кнопка удаления. Ты в цикле вешаешь 500 обработчиков. Потом пользователь добавляет новую задачу — а её кнопка не работает, потому что обработчик ей не повесили. Ты добавляешь навешивание при создании, и после перерисовки клики срабатывают по два раза. Есть приём, который решает всё это сразу.

### На пальцах
Вместо охранника у каждой двери в офисе ставят одного на входе на этаж. Он видит, к какой двери пошёл посетитель, и решает, что делать. Это делегирование: один обработчик на родителе вместо сотни на детях.

### Как это работает
События «всплывают»: клик по кнопке внутри карточки внутри списка срабатывает сначала на кнопке, потом на карточке, потом на списке, потом на `document`. Поэтому обработчик на родителе узнаёт о кликах по всем детям.

Как делегировать:

1. Вешаешь один обработчик на общий контейнер.
2. Внутри находишь нужный элемент: `event.target.closest(".delete")` — ближайший предок (или сам элемент) с этим селектором.
3. Если нашёлся — действуешь. Нужные данные удобно хранить в `data-` атрибутах.

Плюсы:

- Один обработчик вместо сотни.
- Работает для элементов, добавленных позже.

?: Зачем `closest`, если можно проверить `event.target.classList.contains("delete")`? || Клик может прийтись на иконку или `span` внутри кнопки, и тогда `target` — это иконка, а не кнопка. `closest` поднимается вверх и находит саму кнопку, даже если кликнули по её содержимому.

### Пример
```html
<ul id="todos">
  <li data-id="1">Сверстать шапку <button class="delete"><span>✕</span></button></li>
</ul>
```

```js
const list = document.querySelector("#todos");

list.addEventListener("click", (event) => {
  const btn = event.target.closest(".delete");
  if (!btn) return;
  btn.closest("li").remove();
});

list.insertAdjacentHTML("beforeend",
  '<li data-id="2">Задеплоить <button class="delete"><span>✕</span></button></li>');
```

?! Пользователь кликнул точно по крестику во второй задаче, которую добавили уже после навешивания обработчика. Удалится ли она? || Да. Клик по `span` всплывёт до `ul`, `closest(".delete")` найдёт кнопку, а `closest("li")` — задачу. Новый элемент работает без собственного обработчика.

### Частые ошибки
- **`event.target.classList.contains("delete")`** — не сработает, если клик пришёлся на иконку внутри кнопки.
- **Обработчик каждой карточке внутри цикла отрисовки** — после перерисовки клики срабатывают по два раза.
- **Забыт `return`**, когда клик был не по нужному элементу.

### Проверь себя
?? Что такое всплытие события? || Событие сначала срабатывает на элементе, где произошло, а затем по очереди на всех его предках до `document`.
?? Что делает `el.closest(".delete")`? || Ищет ближайший элемент с классом `delete`, начиная с самого `el` и поднимаясь по предкам. Не нашёл — возвращает `null`.
?? Объясни своими словами, что такое делегирование событий и зачем оно. || Один обработчик на общем родителе ловит события всех детей благодаря всплытию. Это экономит обработчики и автоматически работает для элементов, добавленных позже.

Сделай галерею из 6 карточек с кнопками «В избранное». Одним обработчиком на контейнере переключай у карточки класс `is-fav`. Добавь кнопку, которая создаёт новую карточку, и убедись, что избранное работает и для неё.

### Ситуация
Пользователь полчаса составлял список задач в твоём приложении. Случайно обновил страницу — и всё пропало. Одна из худших вещей, которые можно сделать с человеком. Браузер умеет хранить данные между перезагрузками — нужно только знать, что туда влезают одни строки.

### На пальцах
`localStorage` — ящик стола в браузере: положил записку, закрыл вкладку, выключил компьютер — завтра записка на месте. Но в ящик кладут только листы бумаги (строки). Объект сначала нужно «записать на бумагу» — `JSON.stringify`, а достав, «прочитать обратно» — `JSON.parse`.

### Как это работает
- `localStorage.setItem("ключ", "строка")` — сохранить.
- `localStorage.getItem("ключ")` — прочитать. Если ничего нет — `null`.
- `localStorage.removeItem("ключ")`, `localStorage.clear()` — удалить.
- Хранит только строки, примерно 5 МБ на сайт, только в этом браузере на этом устройстве.

JSON — текстовый формат записи данных:

- `JSON.stringify(obj)` → строка `'{"name":"Анна"}'`.
- `JSON.parse(str)` → обратно объект.

Безопасное чтение: если данных нет или они испорчены, `JSON.parse` упадёт — оборачивай в `try/catch` и давай значение по умолчанию.

Что не хранить: пароли, токены и любые секреты — любой скрипт на странице может их прочитать.

?: Почему чтение из `localStorage` оборачивают в `try/catch`? || Данные могли испортиться: другой код записал туда не JSON, человек поправил значение вручную, сохранение оборвалось. `JSON.parse` на кривой строке бросает ошибку и роняет всё приложение. `try/catch` позволяет спокойно вернуть значение по умолчанию.

### Пример
```js
const user = { name: "Анна", visits: 3 };

localStorage.setItem("a", user);
localStorage.setItem("b", JSON.stringify(user));

console.log(localStorage.getItem("a"));
console.log(JSON.parse(localStorage.getItem("b")).visits);
console.log(localStorage.getItem("nothing"));
```

?! Что выведут три строки? || `[object Object]` — объект без `stringify` превратился в бесполезную строку. `3` — правильно сохранённый и прочитанный объект. `null` — такого ключа нет.

Посмотреть содержимое: DevTools → Application → Local Storage.

### Частые ошибки
- **`setItem("user", user)` без `stringify`** — сохранится строка `"[object Object]"`.
- **Чтение без `parse`** и попытка работать со строкой как с массивом.
- **Пароль или токен в `localStorage`** — любой скрипт на странице может его украсть.

### Проверь себя
?? Какие данные умеет хранить `localStorage`? || Только строки. Объекты и массивы нужно превращать в строку через `JSON.stringify`.
?? Что вернёт `getItem` для несуществующего ключа? || `null`.
?? Объясни своими словами, зачем нужны `JSON.stringify` и `JSON.parse`. || `stringify` превращает объект в текст, чтобы его можно было сохранить или отправить. `parse` превращает текст обратно в объект, с которым можно работать.
