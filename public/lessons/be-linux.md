### На пальцах
Сервер — компьютер без монитора и мышки, который стоит где-то в дата-центре. Общаться с ним можно только текстом. Эти команды — твои руки на сервере: посмотреть, что лежит, перейти в папку, скопировать, переложить, удалить, заглянуть в файл.

### Как это работает
| Команда | Что делает | Пример |
|---|---|---|
| `ls -la` | содержимое папки, включая скрытые файлы, с правами и размерами | `ls -la /var/log` |
| `cd` | перейти; `cd ~` — домой, `cd -` — в предыдущую | `cd /srv/app` |
| `cp` | копировать; `-r` для папок | `cp .env.example .env` |
| `mv` | переместить или переименовать | `mv old.js new.js` |
| `rm` | удалить; `-r` для папок | `rm -r dist` |
| `cat` | вывести файл целиком | `cat package.json` |
| `less` | листать большой файл: пробел — дальше, `/слово` — поиск, `q` — выход | `less app.log` |
| `mkdir -p` | создать папку со всеми промежуточными | `mkdir -p src/routes` |
| `touch` | создать пустой файл | `touch index.js` |

Полезное:

- `tail -f app.log` — смотреть, как лог пополняется в реальном времени.
- `grep "error" app.log` — найти строки со словом.
- `|` (пайп) передаёт вывод одной команды в другую: `cat app.log | grep 500 | wc -l`.
- `>` записать вывод в файл, `>>` дописать в конец.

Корзины в терминале нет: `rm` удаляет навсегда. Особенно осторожно с `rm -rf`.

### Пример
```bash
cd ~/projects
mkdir -p api/src
cd api
touch src/index.js
cp ../template/.env.example .env
ls -la
cat .env
grep -n "PORT" .env
tail -n 20 /var/log/syslog
```

### Частые ошибки
- `rm -rf` не в той папке. Перед удалением проверь `pwd`.
- Пробелы в именах без кавычек: `rm my file.txt` удалит два файла — `my` и `file.txt`.
- Открыть огромный лог через `cat` и залить терминал. Для больших файлов — `less` или `tail`.

### Мини-задание
Через терминал создай структуру проекта `api/src/routes`, файлы `index.js` и `README.md`, скопируй `README.md` в `docs/`, переименуй `index.js` в `server.js`. Найди через `grep` все строки со словом `const` в своих JS-файлах.

### На пальцах
На сервере, как в офисном здании, у каждого файла есть хозяин, отдел и правила: кто может читать, кто может править, кто может запускать. `chmod` — поменять правила на двери. `sudo` — попросить ключ администратора на одну операцию: «можно я войду в серверную?»

### Как это работает
`ls -l` показывает права в виде строки `-rwxr-xr--`:

- первый символ: `-` файл, `d` папка;
- дальше три тройки: **владелец**, **группа**, **все остальные**;
- в каждой тройке: `r` — чтение, `w` — запись, `x` — выполнение (для папки — право зайти).

Права часто записывают цифрами: `r = 4`, `w = 2`, `x = 1`, складываем по каждой тройке.

| Цифры | Значение | Где применять |
|---|---|---|
| `644` | владелец читает и пишет, остальные только читают | обычные файлы |
| `755` | владелец всё, остальные читают и запускают | папки, скрипты |
| `600` | только владелец читает и пишет | `.env`, SSH-ключи |

- `chmod 600 .env` — изменить права.
- `chmod +x deploy.sh` — сделать скрипт исполняемым.
- `chown user:group file` — сменить владельца.
- `sudo команда` — выполнить от имени администратора (root). Спросит пароль.
- `whoami` — кто я сейчас.

Принцип наименьших прав: приложение запускают от отдельного обычного пользователя, а не от root. Если его взломают, вред будет ограничен.

### Пример
```bash
ls -l
# -rw-r--r-- 1 anna anna  220 .env
# -rwxr-xr-x 1 anna anna  512 deploy.sh

chmod 600 .env            # секреты видит только владелец
chmod +x deploy.sh        # скрипт можно запускать
./deploy.sh

sudo apt update           # установка пакетов требует прав администратора
sudo systemctl restart nginx
```

### Частые ошибки
- `chmod 777` «чтобы заработало» — теперь любой пользователь может изменить файл.
- Запускать Node.js-приложение через `sudo` — оно получает полную власть над сервером.
- Забыть `chmod +x` и получить «Permission denied» при запуске скрипта.

### Мини-задание
Создай файлы `.env` и `run.sh`. Поставь `.env` права 600, сделай `run.sh` исполняемым (внутри — `echo "Привет"`) и запусти его. Посмотри итоговые права через `ls -l` и расшифруй каждую тройку.

### На пальцах
Процесс — запущенная программа, как работник в офисе. У каждого есть табельный номер — PID. `ps` — список всех, кто сейчас работает. `top` — монитор, кто сколько сил тратит. `kill` — попросить работника закончить смену, а если он не слышит — вывести принудительно.

### Как это работает
- `ps aux` — все процессы: пользователь, PID, загрузка CPU и памяти, команда.
- `ps aux | grep node` — найти процессы Node.js.
- `top` (или более удобный `htop`) — живой список, сортировка по нагрузке, выход — `q`.
- `kill PID` — вежливо попросить завершиться (сигнал SIGTERM). Программа может сохранить данные и закрыться.
- `kill -9 PID` — убить немедленно (SIGKILL). Только если обычный `kill` не помог.
- `Ctrl + C` в терминале — остановить запущенную в нём программу (сигнал SIGINT).
- `lsof -i :3000` или `ss -ltnp` — какой процесс занимает порт.

Хорошее серверное приложение реагирует на SIGTERM: перестаёт принимать новые запросы, дорабатывает текущие и закрывает соединения с базой. Это называется graceful shutdown. Хостинги вроде Render посылают SIGTERM перед перезапуском.

На сервере приложение не держат в открытом терминале — им управляет менеджер процессов: systemd, pm2 или Docker. Он перезапустит программу при падении.

### Пример
```bash
ps aux | grep node
# anna  48211  2.1  1.3  node server.js

lsof -i :3000
# node  48211 anna  TCP *:3000 (LISTEN)

kill 48211          # вежливо
kill -9 48211       # если не помогло
```

```js
// server.js — аккуратное завершение
const server = app.listen(3000);

process.on("SIGTERM", () => {
  console.log("Получен SIGTERM, завершаем работу");
  server.close(() => {
    db.end();
    process.exit(0);
  });
});
```

### Частые ошибки
- Сразу `kill -9` — программа не успевает сохранить данные и закрыть соединения.
- Запускать сервер командой `node server.js &` и забыть про него — потом порт «занят непонятно кем».
- Убить не тот процесс из-за похожего имени. Сверяй PID и команду.

### Мини-задание
Запусти любой Node.js-сервер, найди его PID через `ps` и `lsof -i`, заверши через `kill`. Добавь в код обработчик SIGTERM с выводом в консоль и проверь, что он срабатывает.

### На пальцах
Переменные окружения — записка с настройками, которую программа получает при запуске: «работай на порту 3000», «база вот по этому адресу», «ключ вот такой». Код один и тот же везде, а записки разные: на твоём ноутбуке — тестовая база, на сервере — боевая. И главное — секреты не лежат в коде, который видят все.

### Как это работает
- Переменная окружения — пара «имя = значение», которую операционная система передаёт процессу.
- В терминале: `export PORT=4000` (Linux/macOS) — действует в этом окне.
- Для одного запуска: `PORT=4000 node server.js`.
- В Node.js читаются через `process.env.PORT`. Всё приходит строкой: `Number(process.env.PORT)`.
- Файл `.env` — удобный способ хранить переменные локально: по строке `ИМЯ=значение`.
- Node.js 20+ умеет читать его сам: `node --env-file=.env server.js`. Раньше использовали пакет `dotenv`.
- `.env` всегда в `.gitignore`. В репозиторий кладут `.env.example` с пустыми значениями — как подсказку.
- На хостинге (Render, Railway) переменные задают в настройках сервиса.

Что выносить: адрес базы, ключи API, секрет для подписи сессий, порт, режим работы (`NODE_ENV`), адрес фронтенда для CORS.

### Пример
```bash
# .env — не коммитим
PORT=3000
DATABASE_URL=postgres://postgres:secret@localhost:5432/studio
JWT_SECRET=очень-длинная-случайная-строка
NODE_ENV=development
```

```bash
# .env.example — коммитим
PORT=3000
DATABASE_URL=
JWT_SECRET=
NODE_ENV=development
```

```js
// server.js
const port = Number(process.env.PORT) || 3000;
if (!process.env.DATABASE_URL) {
  console.error("Не задана DATABASE_URL");
  process.exit(1);
}
```

```bash
node --env-file=.env server.js
```

### Частые ошибки
- Закоммитить `.env` с паролями. Если это случилось — смени все секреты, удаление файла не помогает: он остаётся в истории.
- Пробелы вокруг `=` в `.env` или лишние кавычки, которые попадают в значение.
- Считать порт числом без `Number()`.

### Мини-задание
Вынеси в `.env` порт и любое приветствие (`GREETING=Привет`). Выведи их из Node.js при старте. Создай `.env.example`, добавь `.env` в `.gitignore` и проверь `git status`, что файл с секретами не попал в коммит. Потренируйся в задаче «Проверка окружения при запуске» из урока про деплой.

### На пальцах
IP-адрес — адрес дома в интернете. Порт — номер квартиры: в одном доме (на одном сервере) живут разные программы, и каждая принимает гостей на своём номере. `localhost` — «мой собственный дом», адрес `127.0.0.1`. curl — курьер, которого можно отправить из терминала с любым запросом и посмотреть, что ему ответят.

### Как это работает
- IP-адрес: `93.184.216.34` (IPv4) или длинный IPv6. Домен через DNS превращается в IP.
- `localhost` / `127.0.0.1` — этот же компьютер. Сервер на `localhost:3000` доступен только с твоей машины.
- `0.0.0.0` в настройке сервера — «слушать на всех сетевых интерфейсах»: так сервер доступен извне (нужно в Docker и на хостинге).
- Порт — число от 1 до 65535. Стандартные: 80 (HTTP), 443 (HTTPS), 22 (SSH), 5432 (PostgreSQL), 6379 (Redis). Для разработки обычно 3000, 5173, 8080.
- Один порт может занимать только одна программа — иначе ошибка `EADDRINUSE`.

curl:

| Команда | Что делает |
|---|---|
| `curl http://localhost:3000/api/health` | GET-запрос |
| `curl -i URL` | показать заголовки ответа |
| `curl -X POST URL -H "Content-Type: application/json" -d '{"name":"Анна"}'` | POST с JSON |
| `curl -X DELETE URL` | DELETE |
| `curl -H "Authorization: Bearer TOKEN" URL` | с заголовком авторизации |

### Пример
```bash
curl -i http://localhost:3000/api/health
# HTTP/1.1 200 OK
# Content-Type: application/json
#
# {"status":"ok"}

curl -X POST http://localhost:3000/api/projects \
  -H "Content-Type: application/json" \
  -d '{"title":"Лендинг","budget":30000}'

curl -s https://api.github.com/users/octocat | head -n 5
```

### Частые ошибки
- Сервер слушает `127.0.0.1`, а запрос идёт из Docker-контейнера или с другого компьютера — «connection refused». Слушай `0.0.0.0`.
- Одинарные и двойные кавычки в `-d` на Windows (cmd) работают иначе — используй Git Bash или PowerShell с экранированием.
- Забыть `Content-Type: application/json` в POST — сервер не разберёт тело.

### Мини-задание
Запусти любой локальный сервер и сделай к нему через curl GET, POST с JSON-телом и запрос с `-i`, чтобы увидеть заголовки. Затем запроси через curl публичный API (`https://jsonplaceholder.typicode.com/posts/1`).

### На пальцах
SSH — защищённый телефонный провод к серверу: набираешь номер и работаешь в его терминале, как будто сидишь рядом. Вход по ключу вместо пароля — как замок с уникальным ключом вместо кодового: ключ невозможно подсмотреть или подобрать, а потерянный ключ можно просто «перевыпустить».

### Как это работает
Пара ключей:

- **приватный** ключ (`~/.ssh/id_ed25519`) — хранится только у тебя, никому не показывается;
- **публичный** ключ (`id_ed25519.pub`) — кладётся на сервер в файл `~/.ssh/authorized_keys`. Его не страшно показывать.

При входе сервер проверяет, что у тебя есть приватный ключ к этому публичному, при этом сам ключ по сети не передаётся.

Шаги:

1. Создать ключи: `ssh-keygen -t ed25519 -C "anna@laptop"`. Можно задать пароль на ключ.
2. Отправить публичный ключ на сервер: `ssh-copy-id user@1.2.3.4` или вставить его в панели хостинга при создании сервера.
3. Подключиться: `ssh user@1.2.3.4`.
4. Для удобства — запись в `~/.ssh/config`, тогда хватит `ssh studio`.

Тот же ключ используют для GitHub: Settings → SSH and GPG keys — и `git push` без пароля.

Безопасность сервера: после настройки ключей отключи вход по паролю и вход под root (`PasswordAuthentication no`, `PermitRootLogin no` в `/etc/ssh/sshd_config`).

### Пример
```bash
ssh-keygen -t ed25519 -C "anna@laptop"
cat ~/.ssh/id_ed25519.pub           # это можно копировать на сервер и в GitHub

ssh-copy-id deploy@203.0.113.10
ssh deploy@203.0.113.10
```

```text
# ~/.ssh/config
Host studio
  HostName 203.0.113.10
  User deploy
  IdentityFile ~/.ssh/id_ed25519
```

```bash
ssh studio                          # теперь так
scp dump.sql studio:/home/deploy/   # скопировать файл на сервер
```

### Частые ошибки
- Отправить кому-то приватный ключ вместо публичного (`.pub`).
- Права на приватный ключ слишком открыты — SSH откажется его использовать. Нужно `chmod 600`.
- Отключить вход по паролю, не проверив, что вход по ключу работает, — и потерять доступ к серверу.

### Мини-задание
Создай SSH-ключ и добавь публичную часть в GitHub. Проверь командой `ssh -T git@github.com` и переключи один свой репозиторий на SSH-адрес (`git remote set-url origin git@github.com:...`).
